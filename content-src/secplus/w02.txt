title: What a network is: LAN, WAN, topology and devices
domain: Foundations
obj: none
level: Beginner
min: 120
pre: w1-3
out: Define LAN, WAN, internet and intranet.
out: Describe the job of a hub, switch, router, access point and gateway.
out: Recognize star, mesh, bus and ring topologies.
why: Almost every attack travels over a network, and almost every defense is placed somewhere on one. To decide where a firewall belongs, or how far an infection could spread, you first need to know how the pieces connect.
plain: A network is two or more devices connected so they can exchange data. A LAN is like the internal mail system of one building: fast and local. A WAN connects distant buildings, like the postal service between cities. The internet is the worldwide network of networks.
plain: Different devices have different jobs. A switch is the mail room inside one building, delivering each letter only to the right desk. A router is the post office that sends mail on to other cities. A hub is an old mail room that photocopies every letter and hands it to everyone.
tech: A local area network (LAN) covers a limited area such as an office. A wide area network (WAN) spans large distances. The internet is the public global network that uses the Internet Protocol. An intranet is a private network service available only inside an organization.
tech: A hub repeats incoming signals out of every port. A switch learns which device is on each port and forwards traffic only where it needs to go. A router moves traffic between different networks. A wireless access point (AP) connects Wi-Fi devices to a wired network. A gateway is the device that traffic passes through to leave the local network; on most home and office networks, the router is the default gateway.
tech: Topology describes how a network is arranged. In a star, devices connect to a central switch. In a mesh, devices have multiple links to each other, giving redundancy. In the older bus and ring designs, devices shared a single line or passed data around a loop.
diagram: network-map
table: Network devices | Device | What it does | Security note
| Hub | Repeats traffic to every port | Anyone connected can see all traffic, so hubs are obsolete
| Switch | Forwards traffic to the right port on a LAN | Limits who sees traffic and can separate networks
| Router | Moves traffic between networks | A natural place to control what crosses a boundary
| Access point | Connects wireless devices to the network | Extends the network beyond the walls of the building
| Gateway | The exit point from a local network | All outbound traffic can be observed here
term: Network == Devices connected so that they can exchange data.
term: LAN == Local area network: a network in one limited area.
term: WAN == Wide area network: a network across long distances.
term: Internet == The global public network of networks.
term: Intranet == A private network service used only within an organization.
term: Topology == The layout of how a network's devices connect.
term: Hub == A device that repeats traffic to all of its ports.
term: Switch == A device that forwards traffic within a LAN to the correct port.
term: Router == A device that moves traffic between different networks.
term: Access point == A device that connects wireless clients to a network.
term: Default gateway == The address a device sends traffic to when the destination is on another network.
eg: A home has one box that combines a router, a switch, an access point and a firewall, which is why these separate jobs are easy to confuse.
eg: Bank branches connect to the head office over a WAN. If a branch is compromised, that WAN link is a path that attackers may try to follow.
walk: Trace a message across the network
- A laptop wants to print to a printer in the same office. The switch sends the data straight to the printer's port.
- The same laptop now opens a website. The destination is not local, so the laptop sends the data to its default gateway.
- The router forwards it out toward the internet, from router to router.
- The reply follows the reverse journey and reaches the laptop through the switch or access point.

title: Addresses: IP, IPv4, IPv6, public, private and MAC
domain: Foundations
obj: none
level: Beginner
min: 120
pre: w2-1
out: Read an IPv4 and IPv6 address and explain the parts.
out: Identify private and public IPv4 ranges.
out: Compare IP addresses and MAC addresses.
why: IP addresses are the first thing analysts search for in logs and firewall rules. Knowing that 10.0.0.5 is private and 8.8.8.8 is public tells you straight away whether a connection stayed inside the organization or left it.
plain: Devices need addresses, just as houses do. An IP address is like a street address: it says where a device is on a network and can change when the device moves. A MAC address is like a serial number stamped on the network hardware: it identifies the interface locally.
plain: Private addresses are like internal office extensions. Thousands of companies can all have extension 101 because those numbers only work inside each company. Public addresses are like full phone numbers that must be unique worldwide.
tech: An IPv4 address is 32 bits, written as four numbers from 0 to 255 separated by dots, such as 192.168.1.20. Each number represents one byte, also called an octet. IPv4 offers about 4.3 billion addresses, which is not enough for the world. IPv6 uses 128 bits written in hexadecimal, such as 2001:db8::1. Runs of zero groups can be shortened once with a double colon.
tech: RFC 1918 reserves three IPv4 ranges for private use: 10.0.0.0 to 10.255.255.255, 172.16.0.0 to 172.31.255.255 and 192.168.0.0 to 192.168.255.255. These are not routed on the public internet. The range 127.0.0.0/8 is loopback, meaning the device itself, and 127.0.0.1 is the usual example. A device with an address starting 169.254 usually failed to reach a DHCP server and assigned itself a link-local address.
tech: A MAC address, or media access control address, is a 48-bit identifier for a network interface, written as six pairs of hexadecimal digits such as 3c:22:fb:12:ab:9e. MAC addresses are used to deliver data on the local network segment and do not cross routers. Software can change a MAC address, so it is not proof of identity.
table: Special IPv4 ranges | Range | Meaning | Reachable from the internet?
| 10.0.0.0/8 | Private | No
| 172.16.0.0/12 | Private (172.16 to 172.31) | No
| 192.168.0.0/16 | Private | No
| 127.0.0.0/8 | Loopback, this device | No
| 169.254.0.0/16 | Link-local, often a DHCP failure | No
table: IP versus MAC | Feature | IP address | MAC address
| Identifies | A location on a network | A network interface
| Length | 32 bits (IPv4) or 128 bits (IPv6) | 48 bits
| Scope | Routed between networks | Local network segment only
| Can it change? | Yes, often assigned automatically | Set at the factory, but can be changed in software
term: IP address == A numeric address that identifies a device's location on a network.
term: IPv4 == The 32-bit version of IP, written as four decimal numbers.
term: IPv6 == The 128-bit version of IP, written in hexadecimal.
term: Octet == A group of eight bits, one of the four numbers in an IPv4 address.
term: Private IP address == An address from a reserved range that is not routed on the internet.
term: Public IP address == A globally routable address.
term: Loopback == An address that refers to the device itself, usually 127.0.0.1.
term: MAC address == A 48-bit hardware identifier for a network interface.
term: Hexadecimal == A base-16 number system that uses 0 to 9 and A to F.
eg: A firewall log shows 10.4.2.8 connecting to 203.0.113.50. The first is internal and the second is external, so this is traffic leaving the organization.
eg: Sign-in logs commonly record a public IP address, which is how unusual locations are spotted.
walk: Classify an address in four questions
- Is it 127.x.x.x? Then it is this device.
- Does it start with 10, or 192.168, or 172 followed by 16 through 31? Then it is private.
- Does it start with 169.254? Then it is link-local, and DHCP may have failed.
- Otherwise, treat it as public. Now you know whether the traffic may have crossed the internet.

explain: The difference exists because your router translates private addresses to a public one using NAT, which you will study soon.
pass: You recorded your IPv4 address, gateway and MAC address.

scenario: A help desk analyst finds that a user's laptop has the address 169.254.17.8 and cannot reach anything. What is the most likely issue?
answer: The laptop assigned itself a link-local address because it probably could not get an address from a DHCP server. The analyst should check the network connection and the DHCP service, not the websites the user is trying to reach.

- MAC addresses can only be used on Wi-Fi :: Wired and wireless interfaces both have MAC addresses.
- MAC addresses are encrypted by default :: MAC addresses are not encrypted, and encryption is not the reason.

- It has failed to get a DHCP address :: A 169.254 address suggests that, not loopback.

title: Subnet masks and basic subnetting
domain: Foundations
obj: none
level: Beginner
min: 120
pre: w2-2
out: Explain what a subnet mask and CIDR notation mean.
out: Work out the network address, broadcast address and usable hosts for simple subnets.
out: Decide whether two addresses are on the same subnet.
why: Subnets are the basic building block of network segmentation, and segmentation limits how far an attacker can move. Firewall rules and logs are written with subnet notation, so you need to be able to read a range like 10.20.30.0/24 at a glance.
plain: A subnet is a neighbourhood within a town. Part of an address says which neighbourhood, and the rest says which house. The subnet mask tells you where the neighbourhood part ends.
plain: If two devices are in the same neighbourhood, they can talk directly. If they are in different neighbourhoods, they must go through a router, and that router is a place where the conversation can be checked or blocked.
tech: A subnet mask marks which bits of an IP address are the network part. The mask 255.255.255.0 means the first 24 bits are the network and the last 8 bits identify the host. Classless Inter-Domain Routing (CIDR) notation writes the same thing as /24, which is the count of network bits.
tech: Host bits equal 32 minus the prefix. The total number of addresses is 2 raised to the host bits. In a normal IPv4 subnet, two addresses are reserved: the first is the network address and the last is the broadcast address. Usable hosts therefore equal 2 raised to the host bits, minus 2.
tech: To find a subnet with a mask that ends on an octet boundary, keep the network octets and set the rest. For 192.168.5.77/24, the network is 192.168.5.0, the broadcast is 192.168.5.255 and hosts run from .1 to .254. For prefixes in the middle of an octet, find the block size by subtracting the mask's last value from 256. For /26, the mask ends in 192, so the block size is 64 and networks start at 0, 64, 128 and 192.

term: CIDR == Classless Inter-Domain Routing: writing a network with a prefix length, such as /24.
term: Prefix length == The number of network bits, shown after the slash.
term: Network address == The first address in a subnet, which identifies the subnet itself.
term: Broadcast address == The last address in a subnet, used to reach all hosts in it.
term: Host == Any device with an address on a network.
eg: A company gives accounting 10.1.10.0/24 and guests 10.1.50.0/24. A router between them can block guests from reaching accounting.
eg: A firewall rule that allows 203.0.113.0/28 is allowing exactly 16 addresses, so a single typo in the prefix can open access to far more.
walk: Are 192.168.1.70 and 192.168.1.130 on the same /26?
- A /26 has a block size of 64, so subnets in the last octet start at 0, 64, 128 and 192.
- The address 192.168.1.70 falls in the block 64 to 127.
- The address 192.168.1.130 falls in the block 128 to 191.
- They are in different subnets, so traffic between them must go through a router.
- Under a /24 mask, they would have been on the same subnet.

title: DHCP, DNS, NAT and how a packet finds its way
domain: Foundations
obj: none
level: Beginner
min: 120
pre: w2-3
out: Explain what DHCP, DNS and NAT each do.
out: Describe the steps from joining a network to loading a website.
out: Use nslookup and traceroute to observe these services.
why: Attackers abuse all three. Rogue DHCP can redirect traffic, DNS can be poisoned or used to hide data, and NAT shapes what logs can tell you. Before you can recognize those attacks, you need to know what normal looks like.
plain: When you join a network, DHCP acts like a hotel front desk: it assigns you a room number, and tells you where the exit is and who to ask for directions. DNS is the phone book that turns a name such as example.com into a number. NAT is the company switchboard: many people inside share one outside number.
plain: A packet is a small labelled parcel of data. Each router along the way reads the destination and passes the parcel closer to it, the way postal centres do.
tech: The Dynamic Host Configuration Protocol (DHCP) gives a device its IP address, subnet mask, default gateway and DNS server. The exchange has four messages: Discover, Offer, Request and Acknowledge, often remembered as DORA. The address is leased for a limited time.
tech: The Domain Name System (DNS) translates domain names into addresses. A resolver asks on your behalf and caches answers for a time set by the record's time to live (TTL). The resolver works from the root servers to the top-level domain servers to the domain's authoritative server. Common record types are A (IPv4), AAAA (IPv6), CNAME (an alias), MX (mail server), TXT (text, used for email security) and NS (name server).
tech: Network Address Translation (NAT) rewrites addresses as traffic crosses a router. In the common form, many private addresses share one public address, with port numbers keeping conversations apart. Before a device can send to another on the local segment, it uses the Address Resolution Protocol (ARP) to find the matching MAC address.
diagram: dns-lookup
diagram: nat
term: DHCP == Dynamic Host Configuration Protocol: automatically assigns network settings.
term: DORA == Discover, Offer, Request, Acknowledge: the four steps of a DHCP exchange.
term: DNS == Domain Name System: translates names into IP addresses.
term: Resolver == The DNS server that looks up answers on a client's behalf.
term: Authoritative server == The DNS server holding the official records for a domain.
term: TTL == Time to live: how long a DNS answer may be cached.
term: A record == A DNS record mapping a name to an IPv4 address.
term: MX record == A DNS record that names a domain's mail servers.
term: NAT == Network Address Translation: rewrites addresses as traffic crosses a router.
term: ARP == Address Resolution Protocol: finds the MAC address for an IP address on the local network.
term: Packet == A unit of data with addressing information.
eg: A log shows many devices connecting from one public IP address. That is often NAT, so one address does not necessarily mean one computer.
eg: Security teams watch DNS logs because malware has to look up where to connect, which can reveal infected hosts.
walk: From joining Wi-Fi to loading a page
- Your laptop joins Wi-Fi and uses DHCP to get an address, a gateway and a DNS server.
- You type www.example.com. The laptop asks its DNS resolver for the address.
- The destination is on another network, so the laptop uses ARP to find the gateway's MAC address.
- The laptop sends the packet to the gateway. NAT replaces the private source address with a public one.
- Routers across the internet forward the packet toward its destination, and the reply returns the same way.
