out: Name the major vulnerability types and attack surfaces.
out: Explain race conditions and unsafe code practices.
out: Recognize shadow IT, rogue devices and stale credentials.
why: You cannot fix a weakness you cannot name. This list is effectively a checklist of the places where real organizations get hurt, and many have nothing to do with sophisticated hacking.
plain: A vulnerability is any weak spot. Some are like a door with an old lock nobody makes keys for: unsupported products. Some are like a door the landlord does not know exists: shadow IT. Some are a key taped next to the lock: hardcoded secrets.
tech: System weaknesses: unsupported products no longer receive vendor fixes. Unpatched systems have fixes available that were not applied. Obsolete systems are outdated and may be past useful life. Unmanaged systems are not tracked by IT, so they miss updates and monitoring. Open ports and services expose functionality that may not be needed. Operating system (OS) based vulnerabilities are flaws in the OS itself. Virtualization vulnerabilities include VM escape, where code breaks out of a guest into the host, and resource reuse between VMs.
tech: Application weaknesses: a race condition happens when the result depends on the timing of events. In a time-of-check (TOC) to time-of-use (TOU) flaw, a system checks something, and the thing changes before it is used. A malicious update delivers harmful code through a normal update channel. Code weaknesses include hardcoded secrets, such as a password written into source code, and unsafe exception handling, which can expose internal details or leave a system in an insecure state when errors happen.
tech: A zero-day is a vulnerability unknown to the vendor or with no fix available. Cryptographic vulnerabilities include weak algorithms, short keys and poor key handling. Unmanaged or stale credentials are accounts and passwords left active after they are no longer needed. Rogue devices are unauthorized devices attached to a network. Shadow IT is technology used without IT's knowledge or approval.
tech: Other surfaces: wireless and low-powered communications, which often have weak security; large language models (LLMs), which accept natural language input and can be manipulated; identity providers, where one compromise can open access to many applications; mobile devices, which face loss, sideloading (installing apps from outside the official store) and jailbreaking or rooting; misconfiguration, among the most common causes of breaches; public repositories where code and secrets are accidentally published; and public object storage, such as cloud buckets left open.

out: Distinguish commonly confused attacks such as spraying and brute force.
why: This is where the networking foundation pays off. Attacks such as on-path, DNS poisoning and credential stuffing only make sense once you understand how normal traffic works. Indicators are how you know something has already happened.
plain: Network attacks intercept or flood the road. Application attacks trick the program into doing something it should not, like handing a waiter a note that reads and also bring me everyone's wallet. Credential attacks try to obtain the keys. Indicators of compromise are fingerprints left at the scene.
tech: Network attacks: distributed denial of service (DDoS) overwhelms a target from many sources. A protocol downgrade forces a weaker protocol version. Rogue devices or access points attract traffic. Sniffing captures traffic. Spoofing fakes a source identity such as an IP or MAC address. An on-path attack places the attacker between two parties. Domain Name System (DNS) attacks include cache poisoning, which inserts false records into a resolver, so users are directed to the wrong address.
tech: Application attacks: injection places untrusted input into a command or query. In SQL injection, input changes a database query. A buffer overflow writes past the end of a memory area. A replay attack resends captured valid data. Privilege escalation gains higher rights than granted. Forgery tricks a system into making or accepting a request, such as cross-site request forgery. Directory traversal uses paths like ../ to reach files outside the intended folder.
tech: Credential attacks: password spraying tries a few common passwords against many accounts, avoiding lockouts. Brute force tries many passwords against an account. User enumeration works out which usernames exist, for example from different error messages. Replay reuses captured credentials or tokens. Multifactor authentication (MFA) bypass includes push fatigue, SIM swapping and token theft.
tech: Indicators of compromise (IOCs) include a known malicious file hash, Internet Protocol (IP) address or domain; malicious processes; file system artifacts; a suspicious timestamp, which may have been altered; log manipulation or missing logs; excessive resource consumption; plaintext strings found in malware or memory; account lockout; impossible travel, such as sign-ins from two distant countries within minutes; and concurrent sessions from different places.

title: Threats and weaknesses in AI systems
domain: Domain 2: Threats, Vulnerabilities, and Attacks
obj: 2.6

out: Explain each AI threat named by the objective.
out: Distinguish prompt injection from jailbreaking and poisoning from evasion.
out: Recommend controls for using AI safely.
why: AI tools now have access to company data and can take actions. That creates new ways for information to leak and for systems to be manipulated, and it is a dedicated objective on this exam.
plain: An AI model is like a very well-read assistant who is eager to please, sometimes confidently wrong, and cannot reliably tell the difference between your instructions and instructions written on a note someone has passed it. Most AI risks follow from these characteristics.
tech: Model manipulation means altering a model's behaviour, through its training data, its weights or how it is deployed. Poisoning corrupts training data so that a model learns wrong or hidden behaviour. Evasion crafts inputs that cause a trained model to misclassify, such as altering malware to slip past a detector. These attack different stages: poisoning happens during training, and evasion happens when the model is in use.
tech: Prompt injection supplies input that overrides a model's intended instructions. It can be direct, typed by a user, or indirect, hidden in a document or web page that the model later reads. Jailbreaking is a form of manipulation aimed at bypassing a model's safety restrictions to obtain prohibited output. Injection usually targets the application's instructions, and jailbreaking usually targets its safety rules.
tech: Data loss happens when people paste sensitive information into AI tools, or when a model reveals data from its context. Privacy concerns include training on personal data and the difficulty of deleting it. Hallucinations are confident but false outputs. Bias is systematically unfair output that often reflects training data. Explainability is the ability to understand why a model produced a result, and its absence makes decisions hard to audit. Ethical considerations cover fairness, accountability and appropriate human oversight.
tech: Session hijacking in an AI context means taking over a user's or agent's session, for example through a stolen token, gaining access to its conversation history and permissions. Code execution risk arises when an application runs code that a model generated or that an attacker induced it to produce, so outputs must be treated as untrusted, and run only in a sandbox.
tech: Controls include limiting data the model can reach, giving AI agents least privilege, validating outputs, requiring human approval for sensitive actions, using data loss prevention, logging interactions and having an approved list of AI tools.
table: AI threats compared | Threat | When it occurs | What it does
| Poisoning | Training | Corrupts what the model learns
| Evasion | Use | Fools a trained model with crafted input
| Prompt injection | Use | Overrides intended instructions
| Jailbreaking | Use | Bypasses safety restrictions
| Model manipulation | Training or deployment | Alters how a model behaves
| Hallucinations | Use | Produces false output without any attacker
term: Model manipulation == Altering a model's behaviour through its data, weights or deployment.
term: Poisoning == Corrupting training data.
term: Prompt injection == Input that overrides a model's intended instructions.
term: Data loss == Sensitive information leaving through AI use.
term: Bias == Systematically unfair output.
term: Explainability == The ability to understand why a model produced a result.
term: Hallucinations == Confident but false output.
term: Jailbreaking == Bypassing a model's safety restrictions.
term: Evasion == Crafting inputs to make a model misclassify.
term: Privacy == Protecting personal information, including in AI training and use.
term: Ethical considerations == Fairness, accountability and human oversight in AI use.
term: Session hijacking == Taking over an authenticated session.
term: Code execution == Running code generated or induced through an AI system.
eg: A support bot summarizes a customer's email. Hidden text in the email tells it to include other customers' data. That is indirect prompt injection.
eg: An employee pastes confidential source code into a public chatbot to debug it. That is data loss, even though no attacker was involved.

- What data can it read? Limit it to what is necessary.
- What actions can it take? Require approval for sensitive actions.
- What happens to prompts? Check data retention and training terms.
- Is its output used without review? Validate it before use.
- Who is accountable for its decisions? Name an owner and log its activity.

scenario: An AI agent reads incoming supplier invoices and can issue payments. An attacker sends an invoice with hidden text saying to pay a new account immediately. What is the attack, and which two controls matter most?
answer: Indirect prompt injection. The most important controls are least privilege for the agent and mandatory human approval for payments. Treating document content as untrusted also helps.
q 2.6 mcq e | Hallucinations | A model states a made-up legal case confidently. What is this?
+ A hallucination :: It is false output presented confidently.
- Poisoning :: Nothing suggests the training data was attacked.
- Evasion :: This describes misleading a classifier.
- Session hijacking :: No session was taken over.
q 2.6 mcq m | Poisoning versus evasion | An attacker changes samples in a spam filter's training set so future spam is marked as safe. What is this?
+ Poisoning :: The training data was corrupted.
- Evasion :: Evasion crafts an input at inference time.
- Jailbreaking :: This targets safety restrictions.
- Explainability :: This is a property of models, and not an attack.
q 2.6 mcq m | Prompt injection | A chatbot reads a web page containing hidden text telling it to reveal its system instructions. What is this?
+ Indirect prompt injection :: The malicious instruction arrived through content the model processed.
- Hallucination :: The problem is outside instructions, not a false output.
- Bias :: This is unfair output.
- Data poisoning of a training set :: The content was read during use, not training.
q 2.6 multi m | AI controls | Which controls reduce risk from an AI agent that can send email? Choose two.
+ Require human approval for external messages :: A person checks actions with real impact.
+ Give the agent only the permissions it needs :: Least privilege limits the damage.
- Remove all logging :: Logs are needed for investigation.
- Let it read every mailbox for better accuracy :: This greatly increases exposure.
q 2.6 mcq h | Code execution | An application automatically runs scripts produced by an LLM on its server. What is the primary risk?
+ An attacker can steer the model into producing code that runs with the application's privileges :: Model output must be treated as untrusted.
- The model will become biased :: This does not address the execution issue.
- The server will lose its IP address :: There is no such connection.
- The model will be unable to explain itself :: Explainability is a separate matter.
q 2.6 match h | AI terminology | Match each scenario to its AI threat.
= Tiny image changes cause misclassification => Evasion
= User persuades a model to ignore its safety rules => Jailbreaking
= A hiring model favours one group unfairly => Bias
= Staff paste client data into a public AI tool => Data loss
why: Note whether an attacker is involved and at what stage the problem appears.
mistake: Treating prompt injection and jailbreaking as identical. They overlap, but they target different things.
mistake: Assuming that a confident answer is an accurate one.
sum: AI risks affect training, use and the systems connected to a model.
sum: Treat model input and output as untrusted.
sum: Least privilege and human approval limit damage from AI agents.
