out: Name the major vulnerability types and attack surfaces.
out: Explain race conditions and unsafe code practices.
out: Recognize shadow IT, rogue devices and stale credentials.
why: You cannot fix a weakness you cannot name. This list is effectively a checklist of the places where real organizations get hurt, and many have nothing to do with sophisticated hacking.
plain: A vulnerability is any weak spot. Some are like a door with an old lock nobody makes keys for: unsupported products. Some are like a door the landlord does not know exists: shadow IT. Some are a key taped next to the lock: hardcoded secrets.
tech: System weaknesses: unsupported products no longer receive vendor fixes. Unpatched systems have fixes available that were not applied. Obsolete systems are outdated and may be past useful life. Unmanaged systems are not tracked by IT, so they miss updates and monitoring. Open ports and services expose functionality that may not be needed. Operating system (OS) based vulnerabilities are flaws in the OS itself. Virtualization vulnerabilities include VM escape, where code breaks out of a guest into the host, and resource reuse between VMs.
tech: Application weaknesses: a race condition happens when the result depends on the timing of events. In a time-of-check (TOC) to time-of-use (TOU) flaw, a system checks something, and the thing changes before it is used. A malicious update delivers harmful code through a normal update channel. Code weaknesses include hardcoded secrets, such as a password written into source code, and unsafe exception handling, which can expose internal details or leave a system in an insecure state when errors happen.
tech: A zero-day is a vulnerability unknown to the vendor or with no fix available. Cryptographic vulnerabilities include weak algorithms, short keys and poor key handling. Unmanaged or stale credentials are accounts and passwords left active after they are no longer needed. Rogue devices are unauthorized devices attached to a network. Shadow IT is technology used without IT's knowledge or approval.
tech: Other surfaces: wireless and low-powered communications, which often have weak security; large language models (LLMs), which accept natural language input and can be manipulated; identity providers, where one compromise can open access to many applications; mobile devices, which face loss, sideloading (installing apps from outside the official store) and jailbreaking or rooting; misconfiguration, among the most common causes of breaches; public repositories where code and secrets are accidentally published; and public object storage, such as cloud buckets left open.

out: Distinguish commonly confused attacks such as spraying and brute force.
why: This is where the networking foundation pays off. Attacks such as on-path, DNS poisoning and credential stuffing only make sense once you understand how normal traffic works. Indicators are how you know something has already happened.
plain: Network attacks intercept or flood the road. Application attacks trick the program into doing something it should not, like handing a waiter a note that reads and also bring me everyone's wallet. Credential attacks try to obtain the keys. Indicators of compromise are fingerprints left at the scene.
tech: Network attacks: distributed denial of service (DDoS) overwhelms a target from many sources. A protocol downgrade forces a weaker protocol version. Rogue devices or access points attract traffic. Sniffing captures traffic. Spoofing fakes a source identity such as an IP or MAC address. An on-path attack places the attacker between two parties. Domain Name System (DNS) attacks include cache poisoning, which inserts false records into a resolver, so users are directed to the wrong address.
tech: Application attacks: injection places untrusted input into a command or query. In SQL injection, input changes a database query. A buffer overflow writes past the end of a memory area. A replay attack resends captured valid data. Privilege escalation gains higher rights than granted. Forgery tricks a system into making or accepting a request, such as cross-site request forgery. Directory traversal uses paths like ../ to reach files outside the intended folder.
tech: Credential attacks: password spraying tries a few common passwords against many accounts, avoiding lockouts. Brute force tries many passwords against an account. User enumeration works out which usernames exist, for example from different error messages. Replay reuses captured credentials or tokens. Multifactor authentication (MFA) bypass includes push fatigue, SIM swapping and token theft.
tech: Indicators of compromise (IOCs) include a known malicious file hash, Internet Protocol (IP) address or domain; malicious processes; file system artifacts; a suspicious timestamp, which may have been altered; log manipulation or missing logs; excessive resource consumption; plaintext strings found in malware or memory; account lockout; impossible travel, such as sign-ins from two distant countries within minutes; and concurrent sessions from different places.

title: Threats and weaknesses in AI systems
domain: Domain 2: Threats, Vulnerabilities, and Attacks
obj: 2.6

out: Explain each AI threat named by the objective.
out: Distinguish prompt injection from jailbreaking and poisoning from evasion.
out: Recommend controls for using AI safely.
why: AI tools now have access to company data and can take actions. That creates new ways for information to leak and for systems to be manipulated, and it is a dedicated objective on this exam.
plain: An AI model is like a very well-read assistant who is eager to please, sometimes confidently wrong, and cannot reliably tell the difference between your instructions and instructions written on a note someone has passed it. Most AI risks follow from these characteristics.
tech: Model manipulation means altering a model's behaviour, through its training data, its weights or how it is deployed. Poisoning corrupts training data so that a model learns wrong or hidden behaviour. Evasion crafts inputs that cause a trained model to misclassify, such as altering malware to slip past a detector. These attack different stages: poisoning happens during training, and evasion happens when the model is in use.
tech: Prompt injection supplies input that overrides a model's intended instructions. It can be direct, typed by a user, or indirect, hidden in a document or web page that the model later reads. Jailbreaking is a form of manipulation aimed at bypassing a model's safety restrictions to obtain prohibited output. Injection usually targets the application's instructions, and jailbreaking usually targets its safety rules.
tech: Data loss happens when people paste sensitive information into AI tools, or when a model reveals data from its context. Privacy concerns include training on personal data and the difficulty of deleting it. Hallucinations are confident but false outputs. Bias is systematically unfair output that often reflects training data. Explainability is the ability to understand why a model produced a result, and its absence makes decisions hard to audit. Ethical considerations cover fairness, accountability and appropriate human oversight.
tech: Session hijacking in an AI context means taking over a user's or agent's session, for example through a stolen token, gaining access to its conversation history and permissions. Code execution risk arises when an application runs code that a model generated or that an attacker induced it to produce, so outputs must be treated as untrusted, and run only in a sandbox.
tech: Controls include limiting data the model can reach, giving AI agents least privilege, validating outputs, requiring human approval for sensitive actions, using data loss prevention, logging interactions and having an approved list of AI tools.
table: AI threats compared | Threat | When it occurs | What it does
| Poisoning | Training | Corrupts what the model learns
| Evasion | Use | Fools a trained model with crafted input
| Prompt injection | Use | Overrides intended instructions
| Jailbreaking | Use | Bypasses safety restrictions
| Model manipulation | Training or deployment | Alters how a model behaves
| Hallucinations | Use | Produces false output without any attacker
term: Model manipulation == Altering a model's behaviour through its data, weights or deployment.
term: Poisoning == Corrupting training data.
term: Prompt injection == Input that overrides a model's intended instructions.
term: Data loss == Sensitive information leaving through AI use.
term: Bias == Systematically unfair output.
term: Explainability == The ability to understand why a model produced a result.
term: Hallucinations == Confident but false output.
term: Jailbreaking == Bypassing a model's safety restrictions.
term: Evasion == Crafting inputs to make a model misclassify.
term: Privacy == Protecting personal information, including in AI training and use.
term: Ethical considerations == Fairness, accountability and human oversight in AI use.
term: Session hijacking == Taking over an authenticated session.
term: Code execution == Running code generated or induced through an AI system.
eg: A support bot summarizes a customer's email. Hidden text in the email tells it to include other customers' data. That is indirect prompt injection.
eg: An employee pastes confidential source code into a public chatbot to debug it. That is data loss, even though no attacker was involved.

- What data can it read? Limit it to what is necessary.
- What actions can it take? Require approval for sensitive actions.
- What happens to prompts? Check data retention and training terms.
- Is its output used without review? Validate it before use.
- Who is accountable for its decisions? Name an owner and log its activity.

why: The last lesson covered attacks that guess or trick their way to a password. This one covers what happens after an attacker gets onto one machine: they look for credentials already sitting in memory or on disk, and reuse them to move to the next machine without ever learning a password. It explains why breaches spread so quickly through some networks, and why advice such as unique local administrator passwords matters.
plain: A password hash should be like a fingerprint of a key: useful for checking, useless for opening the door. Pass-the-hash works where a door accepts the fingerprint itself. Credential dumping is a thief photographing every fingerprint left on the counter. Shared local administrator passwords are one master key cut for every office: steal it once, open them all. A memory leak is a tap left running: nothing is stolen, but eventually the room floods.
tech: Local authentication checks credentials stored on the device itself. Windows keeps local account password hashes in the Security Account Manager (SAM) database. Linux keeps them in /etc/shadow, salted and computed with slow algorithms such as yescrypt or SHA-512 crypt, marked by prefixes such as $y$ and $6$. A central directory, such as Active Directory or another LDAP directory, holds one account that works across many systems and can be disabled in one place. Local accounts are useful when the network is down, but they are often forgotten, rarely reviewed and sometimes share one password across many machines.
tech: Credential dumping is extracting stored credentials from an operating system: from the memory of the process that handles sign-ins (on Windows, the Local Security Authority Subsystem Service, LSASS), from the SAM database, or from a domain controller's directory database. It usually needs administrator rights, so it typically follows privilege escalation. MITRE ATT&CK lists it as OS Credential Dumping (T1003).
tech: Pass-the-hash reuses a stolen password hash to authenticate, without cracking it. It works against NTLM, an older Windows authentication protocol in which the client proves it knows the hash, not the password itself. Windows NT hashes are not salted, so the same password produces the same hash on every machine: if many computers share one local administrator password, one dumped hash unlocks all of them. Moving from machine to machine this way is called lateral movement. A similar attack against Kerberos reuses stolen tickets and is called pass-the-ticket. ATT&CK lists pass-the-hash as T1550.002.
tech: Controls: give every machine a unique, regularly rotated local administrator password (Windows LAPS automates this); never sign in to ordinary workstations with domain administrator accounts; use dedicated privileged access workstations; isolate stored secrets with features such as Credential Guard, which uses virtualization-based security; restrict or disable NTLM where it is not needed; and alert on access to LSASS memory and on unusual network logons. In Windows logs, an event 4624 with logon type 3 using NTLM from an unexpected machine is a common lead.
tech: A memory leak is a software flaw in which a program keeps memory it no longer needs, so its memory use grows until the system slows down or the program crashes. It is an availability problem: an attacker who can trigger the leak repeatedly can cause a denial of service. Memory disclosure is different: a flaw lets someone read memory they should not, which can expose secrets such as keys or session tokens. A buffer overflow writes past the end of a memory area and can corrupt data or run code.
table: Memory flaws compared | Flaw | What goes wrong | Main impact
| Memory leak | Memory is never released | Availability: slowdown, crash, denial of service
| Memory disclosure | Memory is read that should not be | Confidentiality: leaked keys, tokens or data
| Buffer overflow | Data is written past a buffer's end | Integrity and possibly code execution

| Credential stuffing | Usernames and passwords from other breaches | Sites where people reuse passwords
| Pass-the-hash | A password hash | NTLM authentication

| Session token theft | A signed-in session cookie or token | Web applications

title: Wireless and switching attacks: deauthentication, WPS, evil twins and VLAN hopping
domain: Domain 2: Threats, Vulnerabilities, and Attacks

out: Explain deauthentication, WPS PIN and evil twin attacks, and the settings that prevent them.
out: Compare WPA2 and WPA3, and EAP-TLS and PEAP, for personal and enterprise Wi-Fi.
out: Explain switch spoofing and double tagging, and how switch configuration stops VLAN hopping.
why: Wi-Fi and switches are the parts of a network people physically touch: anyone in range of an access point, or with a cable in a meeting-room socket, can reach them. Week 3 explained how these networks work. This lesson shows how they are attacked, and why a few configuration choices, such as switching off WPS or turning off automatic trunking, close whole classes of attack.
plain: A deauthentication attack is someone shouting "everyone out!" in the hotel lobby in the manager's voice: guests leave, then come back in, and the attacker watches how they do it. WPS is a spare key under the mat with a four-digit lock. An evil twin is a fake hotel front desk set up across the street. VLAN hopping is slipping from the visitors' corridor into the staff corridor by finding an unlocked connecting door.
tech: Wi-Fi management frames, such as deauthentication and disassociation, were not authenticated in older networks. In a deauthentication attack, an attacker sends forged frames that appear to come from the access point, disconnecting clients. This is a denial of service on its own, and it is also used to force clients to reconnect: the attacker captures the WPA2 four-way handshake and tries passwords against it offline, or pushes clients toward an evil twin. Protected Management Frames (PMF), defined in IEEE 802.11w, authenticate these frames, and WPA3 requires them. Wireless intrusion detection and prevention systems can detect floods of these frames.
tech: Wi-Fi Protected Setup (WPS) lets a device join with a button press or an eight-digit PIN instead of the password. The PIN method has a design flaw: the access point checks the PIN in two halves, and the last digit is a checksum, so only about eleven thousand guesses cover every possibility. Once the PIN is found, the attacker obtains the network password. Disable WPS, especially the PIN method, and keep access point firmware updated.
tech: A rogue access point is any unauthorized access point connected to the network, such as one an employee plugs in for convenience. An evil twin is an attacker's access point that imitates a real network's name to lure clients. WEP and the original WPA are broken. WPA2-Personal uses a pre-shared key and is open to offline guessing from a captured handshake. WPA3-Personal uses Simultaneous Authentication of Equals (SAE), which resists offline guessing, and requires PMF.
tech: Enterprise Wi-Fi and wired network access control use IEEE 802.1X. The supplicant is the user's device, the authenticator is the access point or switch, and the authentication server is usually RADIUS. The Extensible Authentication Protocol (EAP) is a framework with several methods. EAP-TLS uses certificates on both the server and the client, so there is no password to steal; it is the strongest common method. Protected EAP (PEAP) builds a TLS tunnel using only the server's certificate, then sends a password-based method inside, often MSCHAPv2. PEAP is easier to roll out, but if devices do not check the server's certificate, an evil twin running its own RADIUS server can capture credentials.
tech: VLAN hopping is reaching a VLAN you should not be able to reach. In switch spoofing, the attacker's device negotiates a trunk link with a switch port that is set to form trunks automatically, and then receives traffic for every VLAN. In double tagging, an attacker on the native VLAN sends a frame with two 802.1Q tags: the first switch removes the outer tag and forwards the frame, and the next switch delivers it according to the inner tag into the target VLAN. Double tagging only works in one direction, so replies do not come back. Defences: set user ports to access mode, disable automatic trunk negotiation, use an unused VLAN as the native VLAN on trunks and never assign users to it, and tag the native VLAN where the switch supports it.
table: Wi-Fi security compared | Setting | Strength | Main weakness or note
| WEP | Broken | Never use
| WPA2-Personal | Acceptable with a long passphrase | Offline guessing from a captured handshake
| WPA3-Personal | Strong | Uses SAE and requires PMF; older devices may need transition mode
| PEAP | Good if certificates are checked | Credential capture by an evil twin if devices skip server certificate checks
| EAP-TLS | Strongest common choice | Needs certificates issued to every device or user
| WPS PIN | Weak | Brute force in hours; disable it

term: PMF == Protected Management Frames (IEEE 802.11w): authentication for Wi-Fi management frames.
term: Four-way handshake == The WPA2 exchange that confirms both sides know the key; capturing it allows offline guessing.
term: WPS == Wi-Fi Protected Setup: joining with a button or PIN; the PIN method can be brute forced.
term: SAE == Simultaneous Authentication of Equals: the WPA3-Personal handshake that resists offline guessing.
term: Rogue access point == An unauthorized access point connected to the network.
term: 802.1X == Port-based network access control with a supplicant, an authenticator and an authentication server.
term: EAP == Extensible Authentication Protocol: a framework for authentication methods used with 802.1X.
term: EAP-TLS == An EAP method using certificates on both server and client.
term: PEAP == Protected EAP: a TLS tunnel using the server's certificate, with a password method inside.
term: VLAN hopping == Reaching traffic on a VLAN that should be out of reach.

eg: Guests on an office's visitor Wi-Fi keep being disconnected every few minutes, and the wireless controller logs a flood of deauthentication frames from one location. Turning on PMF stops forged frames from disconnecting clients that support it.
