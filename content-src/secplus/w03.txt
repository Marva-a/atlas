@lesson w3-1
title: The OSI and TCP/IP models, packets and encapsulation
domain: Foundations
obj: none
level: Beginner
min: 120
pre: w2-4
out: Name the seven OSI layers and map them to the TCP/IP model.
out: Explain encapsulation using segments, packets and frames.
out: Place common devices and protocols at the right layer.
why: Security tools are described by layer. A Layer 4 firewall and a Layer 7 web application firewall see very different things. Exam questions and vendor documentation both assume you know the difference.
plain: Sending a letter involves layers. You write the letter, put it in an envelope, address it, the post office puts it in a sack, and a truck carries the sack. Each step only deals with its own wrapping. At the far end, each wrapping is removed in reverse order.
plain: The OSI model is a teaching map with seven layers. TCP/IP is the practical model that the internet actually uses, with four layers. Both describe the same idea: each layer does one job and relies on the layer below.
tech: From top to bottom, the OSI layers are 7 Application, 6 Presentation, 5 Session, 4 Transport, 3 Network, 2 Data Link and 1 Physical. The TCP/IP model groups them into Application, Transport, Internet and Link.
tech: As data moves down the layers, each adds a header. This is encapsulation. At Layer 4 the unit is a segment (TCP) or datagram (UDP). At Layer 3 it is a packet. At Layer 2 it is a frame, and at Layer 1 it is bits on the medium. A router works mainly at Layer 3 using IP addresses. A switch works mainly at Layer 2 using MAC addresses.
tech: Each router removes the frame and builds a new one for the next link. The IP packet inside keeps its source and destination, unless NAT changes them. That is why MAC addresses matter only locally.
diagram: osi-tcpip
diagram: encapsulation
term: OSI model == A seven-layer model that describes network communication.
term: TCP/IP model == The four-layer model used by the internet.
term: Encapsulation == Wrapping data with a new header at each layer.
term: Header == Control information added in front of data.
term: Segment == The unit of data at the transport layer in TCP.
term: Packet == The unit of data at the network layer.
term: Frame == The unit of data at the data link layer.
term: Layer 4 == The transport layer, where TCP, UDP and port numbers operate.
term: Layer 7 == The application layer, where protocols such as HTTP operate.
eg: A Layer 4 firewall can allow traffic to port 443 but cannot see the web request inside it.
eg: A Layer 7 device can tell the difference between a normal search and a request that contains an attack string.
walk: Follow an email down and up the layers
- Your mail application creates the message at the application layer.
- TCP adds a header with source and destination ports, forming a segment.
- IP adds source and destination addresses, forming a packet.
- The data link layer adds MAC addresses for the next hop, forming a frame, and sends it as signals.
- The receiver removes each wrapping in reverse until the mail server reads the message.

do: Click any TCP packet. In the middle pane, expand Frame, Ethernet, Internet Protocol and Transmission Control Protocol.
do: Find a MAC address, an IP address and a port number, and match each to its layer.
do: Do not capture on networks you do not own or lack permission to monitor.
expect: The details pane shows the layers stacked, in the same order as encapsulation.
explain: Wireshark displays each header separately because each layer added its own. Seeing this makes the abstract model concrete.
pass: You found a MAC address, IP address and port number in one packet.
pass: You named the layer for each.
scenario: A firewall allows all traffic to TCP port 443, yet an attack is arriving inside normal-looking web requests to that port. Why did the firewall not stop it, and what kind of device could?
answer: A firewall inspecting only Layer 3 and 4 information sees addresses and ports, not the content of the web request. A Layer 7 device, such as a web application firewall, can inspect the application data and block malicious requests.

q none mcq h | Layer visibility | Which information can a device examining only Layer 3 see?

- The URL requested by a browser :: A URL is application-layer data.
- The contents of an encrypted web page :: That is application data, and encrypted as well.
- The username typed into a form :: A form field is application-layer data.
mistake: Believing the OSI model describes exactly how the internet is built. It is a reference model, while TCP/IP is what is implemented.
mistake: Thinking a switch reads IP addresses in all cases. Standard switching uses MAC addresses, while multilayer switches can also route.
sum: OSI has seven layers, and TCP/IP groups them into four.
sum: Each layer wraps the one above it, and the receiver unwraps in reverse.
sum: A device's layer decides what it can see and control.

@lesson w3-2
title: TCP, UDP, ports and how traffic moves
domain: Foundations
obj: none
level: Beginner
min: 120
pre: w3-1
out: Compare TCP and UDP and choose the right one for a use.
out: Explain what a port is and describe the TCP three-way handshake.
out: Recall the common ports and their services.
why: Ports are where services listen, and each open port is a possible way in. Firewall rules and scan results are written in ports, and a port outside the expected list can be the first clue of trouble.
plain: An IP address gets a delivery to the right building, and the port is the apartment number. A web server waits behind one door, and an email server behind another.
plain: TCP is like a phone call: you confirm the other person is there and each part is acknowledged. UDP is like dropping postcards in a mailbox: quick, with no confirmation they arrived.
tech: The Transmission Control Protocol (TCP) is connection-oriented. It sets up a connection using a three-way handshake of SYN, SYN-ACK and ACK, numbers data, retransmits lost segments and closes the connection deliberately. The User Datagram Protocol (UDP) is connectionless and sends datagrams without those guarantees, so it has less overhead. Streaming, voice and DNS queries commonly use UDP.
tech: Ports are 16-bit numbers, from 0 to 65535. Ports 0 to 1023 are well-known, 1024 to 49151 are registered, and 49152 to 65535 are dynamic or ephemeral. A client typically uses a temporary high port to reach a server's well-known port. A switch forwards frames by MAC address, and a router forwards packets by consulting its routing table for the best next hop.

term: TCP == Transmission Control Protocol: connection-oriented and reliable delivery.
term: UDP == User Datagram Protocol: connectionless delivery without guarantees.
term: Three-way handshake == SYN, SYN-ACK, ACK: how TCP opens a connection.
term: Port == A number identifying a service or conversation on a device.
term: Ephemeral port == A temporary high port used by a client.
term: Socket == The combination of an IP address, protocol and port.
term: Routing table == A list a router uses to choose the next hop for a destination.
term: Next hop == The next router along the path to a destination.
eg: A server scan finds port 3389 open to the internet. Remote desktop exposed like this is a common way attackers get in.
eg: A firewall rule allows outbound 443, because users need websites, and blocks most other outbound ports.
walk: Open a TCP connection to a website
- Your computer picks a temporary source port such as 51234.
- It sends a SYN to the server's port 443.
- The server replies with SYN-ACK.
- Your computer sends ACK, and the connection is established.
- TLS and the web request now travel over that connection.

scenario: A team wants to send live voice between offices. Occasional lost packets are acceptable, but delay is not. Should the application favour TCP or UDP?
answer: UDP. Retransmitting a lost piece of a live conversation arrives too late to be useful, and TCP's waiting adds delay. UDP gives low overhead and leaves occasional loss for the application to tolerate.

title: Application protocols: HTTP, TLS, SSH, FTP and VPN
domain: Foundations
obj: none
level: Beginner
min: 120
pre: w3-2
out: Describe what happens when a browser loads an HTTPS page.
out: Choose secure protocols over their insecure equivalents.
out: Explain what a VPN does and what it does not do.
why: Many breaches trace back to a protocol sending secrets in clear text, or to a false sense of safety from a padlock or a VPN. Knowing what each protocol really protects helps you choose correctly.
plain: HTTP is like sending a postcard: anyone handling it can read it. HTTPS is the same conversation in a locked box that only you and the website can open. A VPN is a private tunnel through a public road, between you and the VPN's far end. Beyond that exit, the traffic is on open road again.
plain: The padlock in a browser means the connection to that site is encrypted and the certificate checks out. It does not mean the website is honest. Criminals can get certificates too.
tech: The Hypertext Transfer Protocol (HTTP) defines requests and responses using methods such as GET and POST, and status codes such as 200, 404 and 500. HTTPS is HTTP inside Transport Layer Security (TLS). TLS provides encryption, integrity checking and server authentication using certificates. In a TLS handshake, the client and server agree on parameters, the server presents a certificate, and they derive shared session keys.
tech: Secure Shell (SSH) provides an encrypted remote shell, usually on port 22. File Transfer Protocol (FTP) sends data and credentials unencrypted. SFTP runs over SSH and is different from FTPS, which is FTP with TLS. DNS and DHCP, seen earlier, normally operate without encryption, although encrypted DNS options exist.
tech: A virtual private network (VPN) creates an encrypted tunnel between two points. A remote-access VPN connects a user to an organization, and a site-to-site VPN joins two networks. Common technologies are TLS-based VPNs and IPsec. A full-tunnel VPN sends all traffic through the tunnel, while a split-tunnel VPN sends only some traffic through it.

term: HTTP == Hypertext Transfer Protocol: the request and response protocol of the web.
term: HTTPS == HTTP protected by TLS.
term: TLS == Transport Layer Security: encrypts and authenticates a connection.
term: Certificate == A signed file that binds a public key to a name.
term: SSH == Secure Shell: encrypted remote administration.
term: FTP == File Transfer Protocol: unencrypted file transfer.
term: SFTP == SSH File Transfer Protocol: file transfer over SSH.
term: VPN == Virtual private network: an encrypted tunnel across another network.
term: Split tunnel == A VPN setup that sends only some traffic through the tunnel.
term: IPsec == A protocol suite that secures IP traffic, often used for VPNs.
eg: A login page served over HTTP sends the password as readable text across every network on its path.
eg: A staff member on a split-tunnel VPN has corporate traffic protected, but personal browsing goes directly out and bypasses corporate filtering.
walk: What happens when you open https://example.com
- DNS resolves the name to an address.
- Your browser opens a TCP connection to port 443.
- The TLS handshake runs. The server presents its certificate, and the browser checks it.
- Both sides derive session keys, and encryption begins.
- The browser sends an HTTP GET request inside TLS, and the server responds.

scenario: An administrator proposes using Telnet for router management, because the management network is internal. What is the risk, and what should be used instead?
answer: Telnet sends credentials and commands in clear text, so anyone able to capture traffic on that network could read them. Internal does not mean safe. Use SSH, which encrypts the session.

+ The connection is encrypted and the server holds a certificate valid for that name :: TLS gives encryption and verifies the server's identity by name.
- The website is honest and safe to give your data to :: Scam sites can obtain valid certificates.
- The website has no vulnerabilities :: TLS protects the connection, not the site's code.

+ File transfer runs over SSH :: SFTP is the SSH File Transfer Protocol.
- FTP runs over TLS :: That describes FTPS.
- FTP runs without encryption :: That is plain FTP.
- HTTP runs on port 21 :: This describes neither.

- True :: A VPN encrypts the path. It does not judge what the user does.

mistake: Treating the padlock as proof that a site is legitimate.
mistake: Confusing SFTP with FTPS. SFTP runs over SSH on port 22, while FTPS adds TLS to FTP.
sum: HTTPS is HTTP inside TLS.
sum: Replace clear-text protocols with their secure versions.
sum: A VPN protects the path it covers and nothing beyond it.

title: Wireless networking and basic troubleshooting
domain: Foundations
obj: none
level: Beginner
min: 120
pre: w3-3
out: Describe Wi-Fi basics, including SSIDs and WPA2 and WPA3.
out: Use a layered approach to troubleshoot a connection.
out: Use ping, DNS lookups and traceroute to narrow down a problem.
why: Wi-Fi extends a network beyond its walls, so anyone within range can attempt to connect. Troubleshooting matters too: when an alert fires, you need to know quickly whether it is an attack or simply something broken.
plain: Wi-Fi replaces cables with radio. An access point broadcasts a network name, and anyone nearby can hear it, so encryption is what keeps the conversation private. Troubleshooting is like checking why a lamp will not turn on. You check the plug first, then the switch, then the bulb, in a logical order.
tech: Wireless LANs follow the IEEE 802.11 standards, using frequency bands such as 2.4 GHz, 5 GHz and 6 GHz. A service set identifier (SSID) is the network's name. WPA2 and WPA3 are security standards. WEP and the original WPA are obsolete and should not be used. WPA3 improves on WPA2 with Simultaneous Authentication of Equals, which resists offline password guessing. Enterprise modes authenticate each user through 802.1X.
tech: For troubleshooting, work up or down the layers. Check the physical link and whether the interface has an address. Use ping to test reachability to the gateway, then to an external IP address, then to a name. If an IP address works but a name does not, suspect DNS. Note that many systems block ping, so a failed ping does not prove a host is down.
diagram: evil-twin
table: Troubleshooting ladder | Test | If it fails, suspect
| Is the interface connected, with a valid address? | Cable, Wi-Fi association or DHCP
| Ping the default gateway | Local network problem
| Ping a known external IP address | Router, ISP or firewall
| Resolve a name with nslookup | DNS
| Open the service port or website | The service itself or a firewall
term: Wi-Fi == Wireless networking based on the IEEE 802.11 standards.
term: SSID == Service set identifier: the name of a wireless network.
term: WPA2 == Wi-Fi Protected Access 2: a security standard for Wi-Fi.
term: WPA3 == The newer Wi-Fi security standard, with stronger password protection.
term: WEP == Wired Equivalent Privacy: an obsolete and broken Wi-Fi standard.
term: Evil twin == A fake access point that imitates a legitimate network.
term: ping == A tool that tests whether a host replies, using ICMP.
term: ICMP == Internet Control Message Protocol: used for error and status messages.
eg: A coffee shop's open Wi-Fi lets others nearby observe unencrypted traffic, and a nearby attacker can set up a similar network name.
eg: An analyst finds that a server is unreachable by name but reachable by IP, and so saves hours by checking DNS rather than the application.
walk: Users cannot reach a website
- Check the device has a valid address. An address starting 169.254 points to DHCP.
- Ping the default gateway. Success shows the local network is working.
- Ping a known public address such as a public DNS server.
- Run nslookup on the site's name. If it fails while the IP ping works, the problem is DNS.
- If DNS works, try the site from elsewhere to see whether the service itself is down.

scenario: Staff report an open network called CorpGuest appearing in the lobby alongside the real, password-protected corporate network. Nobody at the company set it up. What could this be, and why does it matter?
answer: It could be a rogue access point or an evil twin. Users who join could have their traffic observed or be sent to fake sign-in pages. It should be located and removed, and staff told to use only the approved network. Network and wireless monitoring help to detect this.
