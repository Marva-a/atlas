out: Choose the right firewall type and write basic rules.
out: Distinguish IDS from IPS, and network from host-based sensors.
out: Explain content filtering and network access control.
why: These are the everyday tools of a security team. Knowing which one fits a scenario is a major part of this domain, and PBQs often ask you to configure them.
plain: A firewall is a guard checking addresses and door numbers. A web application firewall reads the content of what is being carried. An intrusion detection system is a security camera with an alarm, and an intrusion prevention system is a guard who can actually step in.
tech: Segmentation limits movement between areas of a network. Access controls decide who may reach what. Firewalls include rule-based filtering, which permits or denies according to a list; Layer 4 firewalls, which decide on addresses, ports and connection state; and Layer 7 firewalls, which understand applications. A web application firewall (WAF) protects web applications from attacks such as injection. Unified threat management (UTM) combines several functions in one device. Rate-limiting requests restricts how many requests are allowed in a period, which slows brute force and some denial-of-service attempts.
tech: An intrusion detection system (IDS) monitors and alerts. An intrusion prevention system (IPS) sits inline and can block. Network-based intrusion detection system (NIDS) and network-based intrusion prevention system (NIPS) sensors watch network traffic. Host-based intrusion detection system (HIDS) and host-based intrusion prevention system (HIPS) agents watch a single host. A wireless intrusion prevention system (WIPS) detects and responds to wireless threats such as rogue access points. Detection may use signatures, which match known patterns, or anomalies, which flag departures from normal.
tech: A content filter controls what users can reach or send. Data loss prevention (DLP) detects and blocks sensitive data leaving. Agent-based filters run on the device and work anywhere. A centralized proxy routes traffic through a central inspection point.
tech: Network access control (NAC) decides whether a device may join a network. It uses 802.1X for port-based authentication, usually with a RADIUS server, endpoint posture and compliance checks such as patch level, and captive portals, the web pages that appear before guest Wi-Fi access. Monitoring and alerting tell you when these controls see something important.

table: Commonly confused | Tool | What it does | Where
| Firewall | Allows or denies traffic by rule | Boundary or host
| WAF | Inspects and filters web requests | In front of a web app
| IDS | Detects and alerts, does not block | Out of band
| IPS | Detects and blocks | Inline

term: Layer 7 firewall == A firewall that understands application content.

term: UTM == Unified threat management: several security functions in one device.

term: NIDS == Network-based intrusion detection system.
term: NIPS == Network-based intrusion prevention system.

term: WIPS == Wireless intrusion prevention system.
term: Content filter == A control that limits access to or movement of content.
term: DLP == Data loss prevention: stops sensitive data from leaving.
term: Agent-based == Using software installed on the device.
term: Centralized proxy == A central point through which traffic is inspected.
term: NAC == Network access control: decides which devices may connect.
term: 802.1X == A standard for port-based network authentication.
term: Endpoint posture/compliance == Whether a device meets security requirements.
term: Captive portals == Web pages shown before network access is granted.

eg: A login page is rate-limited to five attempts a minute for each IP address, which slows guessing.
eg: A laptop missing critical patches is placed by NAC into a remediation network until it is updated.
walk: Read a firewall rule list
- Rules are evaluated from top to bottom, and the first match wins.
- Rule 1: allow TCP 443 from any source to the web server.
- Rule 2: allow TCP 22 from the admin subnet to the web server.
- Rule 3: deny everything else, and log it.
- A broad allow rule placed above a specific deny rule will defeat it, so order matters.

q 4.1 mcq e | IDS versus IPS | What is the key difference between an IDS and an IPS?
+ An IPS can block traffic, and an IDS only alerts :: The IPS sits inline and can act.
- An IDS encrypts traffic :: Neither system's purpose is encryption.
- An IPS can only be used on Wi-Fi :: IPS is used widely.
- An IDS replaces a firewall :: These have different roles.
q 4.1 mcq m | WAF | Which control best stops cross-site scripting aimed at a web application?
+ WAF :: It inspects application-layer web content.
- Layer 4 firewall :: It sees only ports, addresses and connection state.
- UPS :: This is a power device.
- Captive portal :: This controls guest network access.
q 4.1 mcq m | NAC | A device is checked for patches and antivirus before it may join the network. What is this?
+ Network access control using endpoint posture :: NAC can check compliance before granting access.
- Rate limiting :: This limits request volume.
- A DLP proxy :: This focuses on data leaving.
- A honeypot :: This is a decoy system.
q 4.1 mcq h | Firewall rule order | An ordered list reads: 1) allow any to any on TCP 443; 2) deny 203.0.113.9 to any on TCP 443. What happens to 203.0.113.9?
+ It is allowed, because rule 1 matches first :: First match wins, so rule 2 is never reached.
- It is denied, because deny rules always take priority :: Most firewalls process rules in order.
- It is logged and dropped automatically :: Nothing in this list would do that.
- The firewall will report a syntax error :: These rules are valid.

= Detect a rogue wireless access point => WIPS

title: Securing endpoints, mobile devices and operating systems
domain: Domain 4: Security Operations

out: Compare antivirus, EDR and XDR.
out: Explain sandboxing, application control and MDM.
out: Describe Group Policy and SELinux.
why: Most attacks end up on an endpoint. Stronger endpoint visibility and tighter control over what can run are often the difference between a blocked attack and a breach.
plain: Antivirus is a list of known criminals' photos. Endpoint detection and response is a detective watching for suspicious behaviour and able to intervene. Allow listing is a guest list: if your name is not on it, you do not get in. A sandbox is a quarantine room for testing a suspicious package.
tech: Hardening removes unnecessary services, accounts and settings. Sandboxing runs code in an isolated environment. Application control restricts what software runs, through allow lists, which permit only approved items, or block lists, which forbid known bad items. Allow lists are stronger but need more upkeep.
tech: Antivirus detects known malicious code and some suspicious behaviour. Endpoint detection and response (EDR) records endpoint activity, detects suspicious behaviour and enables a response such as isolating a host. Extended detection and response (XDR) correlates data across endpoints, networks, identity and email.
tech: Mobile device management (MDM) enforces policies such as passcodes and encryption, can remotely wipe a lost device and controls apps. In Windows domains, Group Policy centrally applies settings to users and computers. Security-Enhanced Linux (SELinux) is a mandatory access control system that confines what each process can do, even if it runs as a privileged account.
term: Hardening == Reducing attack surface through secure settings.
term: Sandboxing == Running code in an isolated environment.
term: Application control == Restricting which software can run.
term: Allow lists == Lists of items that are explicitly permitted.
term: Block lists == Lists of items that are explicitly forbidden.
term: Antivirus == Software that detects known malicious code and behaviours.
term: EDR == Endpoint detection and response: detects and responds on endpoints.
term: XDR == Extended detection and response: correlates data across many sources.
term: MDM == Mobile device management: central control of mobile devices.
term: Group Policy == Windows feature that centrally applies settings.
term: SELinux == Security-Enhanced Linux: mandatory access control for Linux.
eg: EDR notices Word launching PowerShell and isolates that laptop from the network, automatically.
eg: A lost phone is remotely wiped using MDM.
walk: Choose between allow list and block list
- If the environment is stable, like a kiosk or a server, consider an allow list.
- If users constantly need new software, a block list is easier but is weaker.
- Plan how updates are handled, since a new version can break a hash-based allow list.
- Apply the change using change management, and monitor what gets blocked.

scenario: A company's kiosks should run one application and nothing else. Which control provides the strongest enforcement?
answer: Application allow listing, as nothing outside the approved list can run. Block lists would miss anything unknown.
q 4.1 mcq e | Allow lists | Which approach permits only approved software?
+ Allow list :: Everything not listed is blocked.
- Block list :: This forbids only named items.
- Captive portal :: This handles network access for guests.
- Load balancing :: This distributes requests.
q 4.1 mcq m | EDR versus antivirus | What does EDR add beyond traditional antivirus?
+ Continuous behaviour monitoring and response actions such as host isolation :: EDR is designed for detection and response.
- Only a larger signature list :: EDR is not limited to signatures.
- Battery power for laptops :: This is unrelated.
- Replacement of user authentication :: This is unrelated.
q 4.1 mcq m | MDM | An employee loses a company phone containing email. Which capability is most useful?
+ Remote wipe through MDM :: MDM can erase the device remotely.
- SELinux enforcing mode :: This is for Linux access control.
- A WAF rule :: This is for web applications.
- A DMARC record :: This is for email domains.
q 4.1 mcq h | SELinux | A web server running as a service is compromised, but it cannot read other system files. What is the most likely reason?
+ SELinux confines the process by policy :: Mandatory access control limits it.
- The server has a UPS :: A UPS protects power.
- The server has a CRL :: A CRL relates to certificates.

@lesson w10-3
title: Application, email and deception controls
domain: Domain 4: Security Operations
obj: 4.1
level: Intermediate
min: 120
pre: w10-2
out: Apply application security controls.
out: Explain how SPF, DKIM, DMARC and BIMI work together.
out: Choose deception technologies.
why: Web applications and email are the two most common ways into an organization. Deception gives defenders a rare advantage, since nobody legitimate should touch a decoy.
plain: Input validation is like checking that a phone number field has only digits before accepting it. SPF is a list of who may send mail for your domain, DKIM is a wax seal on the letter, and DMARC tells recipients what to do if either one fails. A honeypot is a decoy safe left out to catch thieves.
tech: Application security covers input validation, which checks data against what is expected; secure cookies, using the Secure, HttpOnly and SameSite attributes; static code analysis, which reviews source code without running it; and code signing, which proves who published code and that it has not been altered. Repositories should use secrets scanning to find leaked credentials.
tech: Email security uses DNS records. Sender Policy Framework (SPF) lists the servers allowed to send for a domain. DomainKeys Identified Mail (DKIM) adds a digital signature to messages. Domain-based Message Authentication, Reporting, and Conformance (DMARC) tells recipients how to handle messages failing checks, such as none, quarantine or reject, and asks for reports. Brand Indicators for Message Identification (BIMI) displays a verified brand logo, and depends on DMARC enforcement.
tech: Deception and disruption technology includes a honeypot (a decoy system), a honeynet (a network of decoys), a honeyfile (a decoy document), a honeytoken (fake data or a credential that raises an alert when used) and a canary account (a decoy account that should never be used). Any use of these indicates something is wrong, so false positives are low.
diagram: email-auth
table: Email authentication | Control | Answers | Stored in
| SPF | Is this server allowed to send for this domain? | DNS TXT record
| DKIM | Was the message signed and left unchanged? | Signature in message, key in DNS
| DMARC | What should happen if checks fail? | DNS TXT record
| BIMI | Can a brand logo be shown? | DNS TXT record
term: Input validation == Checking data against what is expected.
term: Secure cookies == Cookies protected using attributes such as Secure and HttpOnly.
term: Static code analysis == Reviewing code for flaws without running it.
term: Code signing == Digitally signing code to prove its origin and integrity.
term: Repositories == Stores of source code and related files.
term: Secrets scanning == Searching code and repositories for exposed credentials.
term: SPF == Sender Policy Framework: lists authorized mail servers.
term: DKIM == DomainKeys Identified Mail: signs outgoing mail.
term: DMARC == A policy for handling mail failing SPF or DKIM checks.
term: BIMI == Brand Indicators for Message Identification: shows a verified logo.
term: Honeypot == A decoy system.
term: Honeynet == A network of decoy systems.
term: Honeyfile == A decoy file.
term: Honeytoken == Fake data that raises an alert when used.
term: Canary account == A decoy account that should never be used.
term: Deception and disruption == Techniques that mislead attackers and reveal them.
eg: A domain publishes a DMARC policy of reject, so forged mail claiming to be from the domain is refused by receiving servers.
eg: A fake credentials file on a file share triggers an alert the moment anyone opens it.
walk: Read a domain's email security
- Look up the SPF TXT record, starting v=spf1.
- Look up the DMARC record at _dmarc.domain.
- Check the DMARC policy: p=none only monitors, while p=reject is enforcing.
- Check whether messages carry a DKIM-Signature header.

title: Managing hardware, software and data assets
domain: Domain 4: Security Operations
obj: 4.2

out: Follow an asset through its life cycle.
out: Explain why an accurate inventory matters.
out: Choose the proper disposal method.
why: You cannot protect what you do not know you have. Assets that nobody tracks do not get patched, and discarded drives have exposed a surprising amount of sensitive data.
plain: Think of a company car. It is planned, bought, assigned to a driver, tracked and serviced, then sold or scrapped. You would clear out the glove compartment before selling it. Hardware, software and data need the same care.
tech: The asset management life cycle has these stages. Planning/scoping decides what is needed. The acquisition/procurement process covers buying through approved suppliers, with security requirements. Assignment/accounting records who owns or uses an asset and adds it to inventory. Monitoring/asset tracking keeps records current, for example through discovery scans. Disposal/decommissioning retires an asset securely.
tech: NIST SP 800-88 describes three main sanitization outcomes: clear, using logical methods to protect against simple recovery; purge, using stronger techniques that defeat laboratory recovery, such as cryptographic erase; and destroy, making the media unusable. Keep a certificate of destruction when third parties do this work. Data assets need the same tracking and also have owners, classifications and retention periods. Software assets need license and version tracking.
table: Media sanitization | Method | Protects against | Example
| Clear | Simple recovery | Overwriting with standard tools
| Purge | Laboratory recovery | Cryptographic erase
| Destroy | Any recovery, media unusable | Shredding or incineration
term: Asset management life cycle == The stages an asset goes through, from planning to disposal.
term: Planning/scoping == Deciding what is needed and what is included.
term: Acquisition/procurement process == Buying assets through approved channels.
term: Assignment/accounting == Recording ownership and adding to inventory.
term: Monitoring/asset tracking == Keeping track of where assets are and their state.
term: Disposal/decommissioning == Securely retiring an asset.
term: Sanitization == Making data on media unrecoverable.
term: Cryptographic erase == Destroying the key so that encrypted data cannot be recovered.
term: Certificate of destruction == Proof that media were destroyed.
eg: A forgotten test server, not on any inventory, runs out-of-date software and becomes the entry point for a breach.
eg: An organization resells old laptops without wiping them, and customer data ends up on the second-hand market.
walk: Decommission a server
- Confirm its owner approves retirement, and check dependencies.
- Migrate or archive data according to retention rules.
- Revoke its credentials and certificates and remove its DNS and firewall entries.
- Sanitize or destroy the disks in accordance with data sensitivity.
- Update the inventory and keep the record.
