Containers and Kubernetes in plain words

Day 29 · Week 5 · Intermediate · about 120 min

A container packs an app with everything it needs so it runs the same anywhere, and Kubernetes is the system that runs many containers across many machines and keeps them healthy.

By the end, you can: Explain the relationship between containers, Pods, nodes, namespaces and Services in Kubernetes.

Why it matters to a designer

Tigera, and many security companies, sell to platform engineers who run Kubernetes. You cannot design for them without their basic vocabulary: pods, nodes, namespaces and services. Today you learn it with everyday pictures, plus the cloud basics around it.

Key ideas

  • You already ran a container on Day 3: Keycloak in Docker. A container is like a lunchbox: the app and everything it needs, packed so it works the same on any table.
  • Kubernetes is like a restaurant kitchen manager: it decides which cook (machine) prepares which dish (container), replaces a cook who goes home sick, and adds cooks when it gets busy.
  • A node is one machine. A pod is the smallest unit Kubernetes runs, usually one container. A cluster is all the nodes together. A namespace is a separate area of the cluster, for example one per team.
  • Most clusters run in a cloud (AWS, Google Cloud, Azure). In the shared responsibility model, the cloud secures the buildings and hardware; you secure your accounts, settings, data and who can reach what.
  • In AWS, a VPC is your private network in the cloud, a subnet is a section of it (public if it has a route to the internet), and a security group is a firewall around a server.
  • Many small services talking to each other inside a cluster is called east-west traffic. Traffic coming in from users outside is north-south. Most attacks spread east-west after getting in.

Key terms

containerAn app packaged with everything it needs, so it runs the same anywhere.
imageThe saved template a container is started from.
KubernetesA system that runs and manages many containers across many machines.
nodeOne machine in a Kubernetes cluster.
podThe smallest unit Kubernetes runs, usually one container.
clusterA group of nodes managed together by Kubernetes.
namespaceA separate area inside a cluster, often one per team or app.
shared responsibilityThe cloud provider secures the infrastructure; you secure what you put on it and how you configure it.
VPCVirtual private cloud: your own private network in a cloud provider.
east-west trafficTraffic between services inside a network or cluster.

What a good answer looks like

  • A container packs an app with everything it needs, like a lunchbox that works on any table. Kubernetes is the kitchen manager that decides where each dish is cooked, replaces cooks who leave and adds cooks when busy.
  • A pod is the smallest unit that runs (usually one container), a node is a machine that runs pods, and a cluster is all the nodes managed together.
  • For example: who has access to your cloud accounts, how your network and security groups are configured, and protecting your data. The provider secures the data centres and hardware.
