Exercise 16: an access policy managed in git

Day 45 · Week 7 · Advanced · about 120 min

You will move your Exercise 6 policy into a git repository, change it through a pull request with tests, and roll it back, as a platform team would.

By the end, you can: Propose an access-policy change as a pull request and explain what review and automated tests it should pass before merging.

Why it matters to a designer

This is how many technical customers of Tailscale and Tigera really work. Doing it yourself shows you where the console and git experiences meet, and gives you a design insight for case study 1: policy changes need review, preview and safe rollback.

Key ideas

  • Your policy file becomes a file in a GitHub repository. A GitHub Action tests and applies it to the tailnet when a change is merged.
  • The workflow: create a branch, edit the policy, open a pull request, tests run, someone reviews, merge, the change goes live.
  • Your ACL tests from Exercise 6 now run in the pull request: a failing test blocks the merge.
  • Rollback is just reverting the commit. Notice how much safer this feels than editing live in a console.
  • As a designer, notice what the pull request does not show: who will gain or lose access in human terms. That gap is a design idea.

Key terms

repositoryA project folder tracked by git, often on GitHub.
branchA separate line of changes in git.
GitHub ActionsGitHub’s system for running automatic steps, such as tests, on changes.
mergeAccepting a pull request into the main version.
revertUndoing a change by adding a commit that reverses it.

Check yourself

  • What does a test in the pull request protect against?
  • What does a reviewer of a policy pull request need to see that a text diff does not show?

What a good answer looks like

  • It stops a change that breaks an expected access promise from being merged, so mistakes are caught before they reach real people and systems.
  • The effect in human terms: who will gain or lose access to what, how risky the change is, and which tests cover it. A text diff shows only changed lines.
