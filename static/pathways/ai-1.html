How AI products work, and where security fits

Pathway: AI Security · Lesson 1 · Intermediate · about 85 min

An AI product is a model surrounded by prompts, retrieved documents, tools, memory and people, and most of its security risks sit in those connections, not inside the model.

By the end, you can: Draw the parts of an AI assistant or agent (user, app, model, system prompt, retrieval, tools, memory) with their trust boundaries, and explain the difference between AI security and AI safety.

Why it matters to a designer

The practical question is not 'what is prompt injection?' but 'how do I design an AI product that can read enterprise data and take actions without exceeding the authority the user granted?' That starts with a clear picture of the system, which is the same skill as Day 8, applied to AI.

Key ideas

  • A large language model (LLM) predicts text. On its own it has no memory between requests and no access to your systems. Everything else is added by the application around it.
  • The usual parts: the user's message; a system prompt with the app's instructions; retrieved content (RAG: documents fetched from a search index or vector store to answer a question); tools the model can call (send an email, query a database, open a ticket); memory saved across sessions; and the model's output, shown to a person or passed to another system.
  • An agent is an AI system that plans and takes several steps with tools to reach a goal, with less human checking at each step. More autonomy means more need for limits.
  • The key weakness: the model receives instructions and data as one stream of text and cannot reliably tell them apart. Anything that reaches the model can influence what it does next.
  • Trust boundaries in AI systems: the user's text, every retrieved document, every tool result, every web page and every piece of memory is untrusted input to the model. The model's output is untrusted input to whatever comes next.
  • AI security protects the system, its data and its users from misuse and attack (leaks, unauthorised actions, poisoning). AI safety is broader: avoiding harmful behaviour and outputs even without an attacker. They overlap but use different methods.
  • Identity still matters most: whose permissions does the model use when it retrieves a file or calls a tool? Day 51's answer, its own scoped, short-lived, delegated access, is the foundation for the rest of this pathway.

Key terms

LLMLarge language model: a model that generates text by predicting what comes next.
system promptInstructions from the application that the model sees before the user's message.
RAGRetrieval-augmented generation: fetching relevant documents and giving them to the model to answer a question.
tool callWhen a model asks the application to run a function, such as searching, sending or updating something.
agentAn AI system that plans and takes several steps with tools to reach a goal.
context windowAll the text the model can see at once: instructions, conversation, retrieved content and tool results.
AI securityProtecting AI systems, their data and their users from misuse and attack.
AI safetyMaking AI systems behave in beneficial, non-harmful ways, with or without an attacker.

Check yourself

  • Why is every retrieved document and tool result treated as untrusted input to the model?
  • What is the difference between AI security and AI safety? Give an example of each.
  • In an AI assistant that reads company documents, whose permissions should decide which documents it can retrieve for a question?

What a good answer looks like

  • Because the model cannot reliably separate instructions from data. Text inside a document, email or tool result can contain instructions, and the model may follow them. So content from anywhere other than the application's own fixed instructions must be treated as potentially hostile.
  • AI security: stopping an attacker from using a hidden instruction in a shared document to make an assistant leak files. AI safety: stopping a model from giving dangerous medical advice even when nobody is attacking it.
  • The asking user's, at the moment of asking: it should only retrieve what that person is already allowed to see. Using a broad service account would let anyone see anything the service can reach.
