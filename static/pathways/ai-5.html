Supply chain, output handling, monitoring and incident response

Pathway: AI Security · Lesson 5 · Advanced · about 90 min

AI products depend on models, datasets, plugins and tool servers from others, pass model output into other systems, and need logs, testing and an incident plan built for agents that act on their own.

By the end, you can: Name the parts of an AI supply chain and one risk for each, explain why model output must be treated as untrusted input, and describe what an audit trail and incident response plan for an agent must include.

Why it matters to a designer

When an agent does something wrong, admins need to answer quickly: what did it read, what did it decide, what did it do, on whose authority, and how do we stop and undo it? Those answers depend on audit trails, kill switches and review screens that someone has to design.

Key ideas

  • AI supply chain: base models, fine-tuned models, training and evaluation datasets, prompt templates, plugins, MCP servers and other agents. Any of them can be compromised, malicious or simply changed without notice. Keep an inventory and know which versions are in use.
  • Treat tool servers like software dependencies: verify who publishes them, pin versions, review changes to tool descriptions (a changed description can carry an injected instruction) and remove ones you do not use.
  • Improper output handling: model output is untrusted input to whatever comes next. Output shown in a web page can carry script; output used in a database query, shell command or API call can carry injection. The receiving system must validate it, exactly as for user input on Day 11.
  • Audit trails for agents should record: the user and the agent identity, the goal, what was retrieved, each tool call with its inputs and results, approvals and who gave them, and the final outcome. Without this, an incident cannot be investigated (Week 6).
  • Testing: red teaming tries to make the system misbehave on purpose, and automated scanners such as garak probe models for known weaknesses. Test the whole application, including tools and retrieval, not only the model.
  • Incident response for agents follows the usual phases (Week 6) with additions: a way to pause or disable an agent instantly, revoke its tokens, see every action it took in a time window and reverse what can be reversed.
  • Monitor for unusual agent behaviour, such as a sudden burst of tool calls, new destinations for data or access to sources it rarely uses, much as you would for a human account.

Key terms

AI supply chainThe models, data, prompts, plugins and tool servers an AI product depends on.
improper output handlingPassing model output to other systems without validating it.
audit trailA complete record of who or what did what, when, and on whose authority.
red teamingDeliberately trying to make a system fail or misbehave, to find weaknesses first.
kill switchA control that stops an agent or feature immediately.
model cardA document describing a model's purpose, data, limits and known risks.
tool poisoningHiding malicious instructions in a tool's description or results so an agent follows them.

Check yourself

  • Name three parts of an AI product's supply chain and one risk for each.
  • Why must a system that receives model output validate it?
  • What should an admin be able to do in the first five minutes after discovering an agent is misbehaving?

What a good answer looks like

  • For example: a base model (it may behave differently after an update), an MCP tool server (its publisher could add a malicious instruction to a tool description), and a dataset used for fine-tuning (it could be poisoned).
  • Because the model's output may contain anything an attacker managed to inject, such as script, a database command or an unexpected address. Treating it as trusted lets an injection in the model become an attack on the next system.
  • Pause or disable the agent, revoke its tokens and connections, see every action it took in the relevant time window with inputs and results, and know who granted its access, so they can contain the problem before investigating fully.
