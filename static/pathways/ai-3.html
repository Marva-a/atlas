Data exposure, retrieval boundaries and memory

Pathway: AI Security · Lesson 3 · Advanced · about 90 min

AI systems leak data when retrieval ignores who is asking, when sensitive information flows into answers, logs or memory, or when poisoned content enters the knowledge base, so access control must follow the data into every AI step.

By the end, you can: Explain permission-aware retrieval, name three ways an AI product can disclose sensitive data, describe memory and knowledge-base poisoning, and design a retrieval experience that respects existing permissions.

Why it matters to a designer

Enterprise AI search and assistants are among the fastest-growing security products, and their biggest failure is showing someone a document they should never have seen. Designers decide what sources are connected, what answers cite, what is remembered and what admins can see and control.

Key ideas

  • Permission-aware retrieval: when an assistant searches company documents, it must only retrieve what the asking user may already open, checked at query time. Copying documents into a shared index without their permissions is the classic failure.
  • Over-shared data becomes over-exposed. AI search makes every existing permission mistake visible: a salary sheet shared with 'everyone' was hard to find before; now anyone can ask for it. Cleaning up permissions often has to come before an AI launch.
  • Sensitive information disclosure can come from: retrieved documents, other users' conversations or memory leaking across sessions, the system prompt itself, or data the model learned during training or fine-tuning.
  • Vector stores and embeddings hold a numeric form of your documents. They need the same access control, tenant separation and deletion as the original data; deleting a file must also remove it from the index.
  • Poisoning: if anyone can add content to the knowledge base (a wiki, a shared drive, a support ticket), an attacker can plant false or malicious content that the assistant later retrieves and repeats or acts on.
  • Memory makes this persistent: an injected instruction or false fact saved to an agent's long-term memory can affect future sessions. Users should be able to see, edit and delete what an assistant remembers.
  • Design levers: citations that show which source an answer used and who can see it; admin controls over connected sources; clear retention for chats and memory; and redaction of sensitive fields before they reach the model or logs.

Key terms

permission-aware retrievalRetrieval that only returns content the asking user is already allowed to access.
vector storeA database of embeddings used to find documents similar to a question.
embeddingA list of numbers that represents the meaning of a piece of text, used for search.
sensitive information disclosureWhen an AI system reveals data it should not, such as personal, confidential or secret information.
data poisoningPlanting false or malicious content in data that a model or retrieval system will use.
memory poisoningGetting false facts or instructions saved into an agent's long-term memory.
tenant isolationKeeping one customer's data completely separate from another's.
redactionRemoving or masking sensitive parts of data before it is shown, stored or sent.

Check yourself

  • Why can launching an AI search tool expose data that was already technically shared but rarely found?
  • What does permission-aware retrieval check, and when?
  • How could an attacker poison an assistant that answers questions from a company wiki?

What a good answer looks like

  • Because AI search removes the obscurity that hid permission mistakes. A file shared with everyone by accident used to stay buried; now anyone can ask a question that surfaces it. Fixing over-sharing has to be part of the launch.
  • It checks that the user asking the question is allowed to open each document before the document is retrieved or used in the answer, at the time of the query, using the source system's current permissions rather than a copy made earlier.
  • By editing or adding a wiki page with false information or hidden instructions. When someone later asks a related question, the assistant retrieves the page and repeats the false answer or follows the instruction. Controls include limiting which sources are trusted, showing citations and reviewing changes to key pages.
