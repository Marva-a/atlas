Addresses: IP, IPv4, IPv6, public, private and MAC

Lesson 6 · Week 2 · Foundations · Foundation (not an exam objective) · Beginner · about 120 min

Open this lesson in Atlas →

Professional relevance for cross-functional work

1. Learn the concept

By the end, you can

  • Read an IPv4 and IPv6 address and explain the parts.
  • Identify private and public IPv4 ranges.
  • Compare IP addresses and MAC addresses.

Why it exists and what problem it solves

IP addresses are the first thing analysts search for in logs and firewall rules. Knowing that 10.0.0.5 is private and 8.8.8.8 is public tells you straight away whether a connection stayed inside the organization or left it.

In plain language

Devices need addresses, just as houses do. An IP address is like a street address: it says where a device is on a network and can change when the device moves. A MAC address is like a serial number stamped on the network hardware: it identifies the interface locally.

Private addresses are like internal office extensions. Thousands of companies can all have extension 101 because those numbers only work inside each company. Public addresses are like full phone numbers that must be unique worldwide.

2. Technical deep dive

An IPv4 address is 32 bits, written as four numbers from 0 to 255 separated by dots, such as 192.168.1.20. Each number represents one byte, also called an octet. IPv4 offers about 4.3 billion addresses, which is not enough for the world. IPv6 uses 128 bits written in hexadecimal, such as 2001:db8::1. Runs of zero groups can be shortened once with a double colon.

RFC 1918 reserves three IPv4 ranges for private use: 10.0.0.0 to 10.255.255.255, 172.16.0.0 to 172.31.255.255 and 192.168.0.0 to 192.168.255.255. These are not routed on the public internet. The range 127.0.0.0/8 is loopback, meaning the device itself, and 127.0.0.1 is the usual example. A device with an address starting 169.254 usually failed to reach a DHCP server and assigned itself a link-local address.

A MAC address, or media access control address, is a 48-bit identifier for a network interface, written as six pairs of hexadecimal digits such as 3c:22:fb:12:ab:9e. MAC addresses are used to deliver data on the local network segment and do not cross routers. Software can change a MAC address, so it is not proof of identity.

Key terms

IP addressA numeric address that identifies a device's location on a network.
IPv4The 32-bit version of IP, written as four decimal numbers.
IPv6The 128-bit version of IP, written in hexadecimal.
OctetA group of eight bits, one of the four numbers in an IPv4 address.
Private IP addressAn address from a reserved range that is not routed on the internet.
Public IP addressA globally routable address.
LoopbackAn address that refers to the device itself, usually 127.0.0.1.
MAC addressA 48-bit hardware identifier for a network interface.
HexadecimalA base-16 number system that uses 0 to 9 and A to F.

Walkthrough: Classify an address in four questions

  1. Is it 127.x.x.x? Then it is this device.
  2. Does it start with 10, or 192.168, or 172 followed by 16 through 31? Then it is private.
  3. Does it start with 169.254? Then it is link-local, and DHCP may have failed.
  4. Otherwise, treat it as public. Now you know whether the traffic may have crossed the internet.

Hands-on lab

Read your own addresses

About 30 min. ipconfig on Windows, ip or ifconfig on Linux and macOS

  1. Windows: open Command Prompt and run ipconfig /all. Linux: run ip addr. macOS: run ifconfig.
  2. Find your IPv4 address, IPv6 address if any, your MAC or physical address, and your default gateway.
  3. Classify your IPv4 address using the walkthrough.
  4. In a browser, search for what is my IP and compare the public address it shows with your private one.

Expected: Your computer's own address is probably private, and the address the website reports is public and different.

The difference exists because your router translates private addresses to a public one using NAT, which you will study soon.

Done when:

  • You recorded your IPv4 address, gateway and MAC address.
  • You correctly classified your address as private or public.

3. See it in real products

IP addresses appear in products as login-history entries, new-location alerts and IP allow lists for administrators. An address is only an approximate signal: VPNs, mobile carriers and shared office connections all change what it appears to say.

In security operations

  • A firewall log shows 10.4.2.8 connecting to 203.0.113.50. The first is internal and the second is external, so this is traffic leaving the organization.
  • Sign-in logs commonly record a public IP address, which is how unusual locations are spotted.

4. Apply it as a Product Designer

No design exercise here, on purpose. This becomes design work in the login and monitoring exercises later, where location signals are used in context.

Engineering:

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A help desk analyst finds that a user's laptop has the address 169.254.17.8 and cannot reach anything. What is the most likely issue?

Compare your reasoning

The laptop assigned itself a link-local address because it probably could not get an address from a DHCP server. The analyst should check the network connection and the DHCP service, not the websites the user is trying to reach.

1. Which address is private?

  • 192.168.40.7
  • 8.8.8.8
  • 172.32.1.1
  • 203.0.113.5
Answer and explanation
  • Correct: 192.168.40.7. 192.168.0.0/16 is reserved for private use.
  • Incorrect: 8.8.8.8. This is a public address.
  • Incorrect: 172.32.1.1. The private 172 range stops at 172.31, so this one is public.
  • Incorrect: 203.0.113.5. This is not within any of the three RFC 1918 private ranges.

2. Why does a MAC address not identify a device across the internet?

  • MAC addresses are only used on the local network segment and do not cross routers
  • MAC addresses are longer than IPv6 addresses
  • MAC addresses can only be used on Wi-Fi
  • MAC addresses are encrypted by default
Answer and explanation
  • Correct: MAC addresses are only used on the local network segment and do not cross routers. A router replaces the local delivery information at each hop.
  • Incorrect: MAC addresses are longer than IPv6 addresses. At 48 bits, MAC addresses are shorter than 128-bit IPv6 addresses.
  • Incorrect: MAC addresses can only be used on Wi-Fi. Wired and wireless interfaces both have MAC addresses.
  • Incorrect: MAC addresses are encrypted by default. MAC addresses are not encrypted, and encryption is not the reason.

3. A service is listening on 127.0.0.1 only. Which statement is true?

  • Only programs on the same device can reach it
  • Anyone on the internet can reach it
  • Only devices on the same LAN can reach it
  • It has failed to get a DHCP address
Answer and explanation
  • Correct: Only programs on the same device can reach it. Loopback traffic stays on the device itself.
  • Incorrect: Anyone on the internet can reach it. Loopback addresses are not reachable from other devices.
  • Incorrect: Only devices on the same LAN can reach it. A LAN address would be needed for that.
  • Incorrect: It has failed to get a DHCP address. A 169.254 address suggests that, not loopback.

4. True or false: a MAC address is reliable proof of a device's identity.

  • True
  • False
Answer and explanation
  • Incorrect: True. Software can change or spoof a MAC address.
  • Correct: False. MAC addresses can be spoofed, so they should not be used as strong proof of identity.

6. Review and references

Common mistakes

  • Assuming every address starting with 172 is private. Only 172.16 through 172.31 are.
  • Trusting a MAC address as proof of a device's identity.

Summary

  • IPv4 uses 32 bits and IPv6 uses 128 bits.
  • Three IPv4 ranges are private and not routed on the internet.
  • MAC addresses work locally and IP addresses get data between networks.

References

  • RFC 791: Internet Protocol (IETF, required)
