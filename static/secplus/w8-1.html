Architecture models: cloud, on-premises, serverless and more

Lesson 30 · Week 8 · Domain 3: Security Architecture · Objective 3.1 · Intermediate · about 120 min

Open this lesson in Atlas →

Professional relevance for cross-functional work

1. Learn the concept

By the end, you can

  • Compare cloud deployment models.
  • Explain serverless, microservices and Infrastructure as Code.
  • Identify when on-premises, OT or air-gapped designs apply.

Why it exists and what problem it solves

Each architecture moves the attack surface and changes who is responsible. A control that made sense in one design can be meaningless in another.

In plain language

Choosing an architecture is like choosing where to live. Owning a house gives control but you fix the roof yourself. Renting an apartment means someone else handles the building, but you share walls. A hotel handles nearly everything, and you only bring your luggage.

2. Technical deep dive

On-premises infrastructure is owned and run by the organization, giving maximum control and full responsibility. Cloud deployment models include public (shared provider infrastructure), private (dedicated to one organization), community (shared by organizations with common needs) and hybrid (a mix connected together). Multicloud means using more than one cloud provider, which reduces dependence on one vendor but increases complexity.

In serverless computing, the provider runs the servers and the customer supplies functions that run on demand, so the customer has no OS to patch but must still secure code, permissions and data. Microservices split an application into small independent services communicating through APIs, which limits the damage from one failure but adds many more connections to protect. Infrastructure as Code (IaC) defines infrastructure in version-controlled files, giving repeatable builds, but a single flawed template can replicate an error everywhere.

Operational technology (OT) controls physical equipment. An air-gapped network has no connection to outside networks, which is a strong control but can be defeated through removable media. Logical segmentation separates traffic using software such as VLANs and firewall rules. Physical segmentation uses separate hardware and cabling, which is stronger but costlier.

Moving right, the provider takes on more. Data and access stay with you in every model.

Walkthrough: Pick an architecture

  1. Requirement: a seasonal application with unpredictable demand. Consider public cloud or serverless.
  2. Requirement: strict control of industrial machinery. Keep it on OT networks, separated.
  3. Requirement: legacy database that must remain on site, but with a cloud web front end. That suggests hybrid.
  4. For each option, ask what the organization must still secure.

Hands-on lab

Compare two architectures

About 35 min. Drawing tool

  1. Draw a simple shop website as on-premises. Mark what you must secure.
  2. Redraw it as serverless on a public cloud. Mark what you still must secure.
  3. Write down two risks that went away and two new ones.
  4. Write three lines of pseudo-template for a storage bucket and spot the insecure setting you could accidentally repeat.

Expected: Two diagrams showing that responsibilities moved, not that they disappeared.

The exercise shows the core idea: changing architecture changes the shape of risk.

Done when:

  • Both diagrams mark responsibilities.
  • You named two removed risks and two new risks.

3. See it in real products

Architecture choices limit what a product can promise. Serverless and managed services change who patches what. On-premises deployments mean customers run old versions for years, so a design must survive features being missing or out of date.

In security operations

  • A retailer uses Infrastructure as Code and scans templates before deployment, so that a public storage setting is caught before it exists.
  • A power plant keeps its control network separate from office IT, and carefully controls USB devices.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A government contractor must share a system with three other agencies under the same compliance rules, and wants to split the cost. Which deployment model fits best?

Compare your reasoning

A community cloud, which serves organizations with shared requirements and shares the costs among them.

1. A company connects its data centre to a public cloud and runs one application across both. What is this?

  • Hybrid
  • Community
  • Multicloud only
  • Air-gapped
Answer and explanation
  • Correct: Hybrid. It combines on-premises and cloud.
  • Incorrect: Community. That is shared among organizations with common needs.
  • Incorrect: Multicloud only. Multicloud refers to several cloud providers.
  • Incorrect: Air-gapped. An air-gapped network has no external connection.

2. What remains the customer's job with serverless functions?

  • Securing the code, its permissions and its data
  • Patching the host OS
  • Replacing failed disks
  • Managing data centre cooling
Answer and explanation
  • Correct: Securing the code, its permissions and its data. The provider manages servers, but not your logic or access.
  • Incorrect: Patching the host OS. This is handled by the provider.
  • Incorrect: Replacing failed disks. This is the provider's job.
  • Incorrect: Managing data centre cooling. This is the provider's job.

3. What is a key security benefit of Infrastructure as Code?

  • Configurations can be reviewed, versioned and reproduced consistently
  • It removes the need to control access
  • It makes templates impossible to misconfigure
  • It eliminates the shared responsibility model
Answer and explanation
  • Correct: Configurations can be reviewed, versioned and reproduced consistently. Infrastructure becomes auditable like source code.
  • Incorrect: It removes the need to control access. Access still needs managing.
  • Incorrect: It makes templates impossible to misconfigure. A flawed template can spread an error widely.
  • Incorrect: It eliminates the shared responsibility model. The model still applies.

4. An air-gapped network was infected. What is the most likely route?

  • Removable media
  • DDoS from the internet
  • DNS cache poisoning from an internet resolver
  • A public website's JavaScript
Answer and explanation
  • Correct: Removable media. Data must cross the gap somehow, often through USB drives.
  • Incorrect: DDoS from the internet. An air gap has no internet connection.
  • Incorrect: DNS cache poisoning from an internet resolver. There is no internet connection to reach one.
  • Incorrect: A public website's JavaScript. Hosts have no route to public websites.

6. Review and references

Common mistakes

  • Assuming the cloud provider handles everything in serverless.
  • Thinking that VLANs are equal to physical separation. They are logical controls and can be misconfigured.

Summary

  • On-premises gives control, and cloud shifts duties to the provider.
  • Serverless and microservices change, but do not remove, risk.
  • Air gaps and segmentation limit reach.
