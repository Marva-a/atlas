Virtual machines and an introduction to cloud computing

Lesson 4 · Week 1 · Foundations · Foundation (not an exam objective) · Beginner · about 120 min

Open this lesson in Atlas →

Professional relevance for cross-functional work

1. Learn the concept

By the end, you can

  • Explain what a virtual machine and a hypervisor are.
  • Describe the cloud service models IaaS, PaaS and SaaS and who manages what in each.
  • Build a safe, isolated virtual machine for later labs.

Why it exists and what problem it solves

Security labs run in virtual machines because a mistake stays contained. Businesses run their systems the same way. Knowing who is responsible for what in the cloud prevents one of the most common causes of breaches: each side assuming the other handled a setting.

In plain language

A virtual machine (VM) is a computer simulated in software. One physical computer can pretend to be several separate computers, like one building divided into apartments with separate doors and locks. The hypervisor is the building manager that divides up the space.

Cloud computing means renting computing from someone else over a network and paying for what you use. Instead of buying a server, you ask a provider for one and it is ready in minutes.

2. Technical deep dive

A hypervisor creates and runs VMs. A Type 1 hypervisor runs directly on the hardware and is typical in data centres. A Type 2 hypervisor runs as an application on an existing OS, such as Oracle VirtualBox on a laptop. Each VM believes it has its own CPU, memory, disk and network card. A snapshot records a VM's state so that you can return to it later.

A container is lighter than a VM. Containers share the host's kernel and package just an application and its dependencies. They start quickly but are less isolated than VMs.

NIST defines the main cloud service models. In Infrastructure as a Service (IaaS) the provider supplies virtual servers, storage and networks, and you manage the OS and everything above it. In Platform as a Service (PaaS) you deploy your code and the provider runs the platform. In Software as a Service (SaaS) you simply use a finished application, such as web email. Under every model the customer remains responsible for its own data and for who has access.

Moving right, the provider takes on more. Data and access stay with you in every model.

A VM carries its own operating system. Containers share the host's kernel, so they are lighter but less isolated.

Key terms

Virtual machineA software-based computer that runs on a physical host.
HypervisorSoftware that creates and runs virtual machines.
Type 1 hypervisorA hypervisor that runs directly on the hardware.
Type 2 hypervisorA hypervisor that runs as an application on an existing OS.
SnapshotA saved state of a VM that can be restored later.
ContainerA lightweight package for an application that shares the host's kernel.
IaaSInfrastructure as a Service: rented virtual servers, storage and networking.
PaaSPlatform as a Service: a managed platform for running your code.
SaaSSoftware as a Service: a complete application delivered over the internet.
Shared responsibilityThe split of security duties between a cloud provider and its customer.

Walkthrough: Decide who fixes it

  1. A vulnerability is found in the operating system of a server you rent as IaaS. You patch it, because you manage the OS in IaaS.
  2. The same flaw affects the platform under a PaaS application. The provider patches it.
  3. An employee shares a SaaS document with the public. You fix that, because data and access are always yours.
  4. Physical disks fail in the provider's data centre. The provider replaces them in every cloud model.

Hands-on lab

Build your isolated lab machine

About 60 min. Oracle VirtualBox and an Ubuntu Desktop image (both free)

  1. Install VirtualBox from its official site. Apple-silicon Macs need the Arm build and an Arm version of Ubuntu.
  2. Download the Ubuntu Desktop installer from ubuntu.com. Check that the page is the official one.
  3. Create a VM with at least 2 CPUs, 4 GB of RAM and 25 GB of disk, then install Ubuntu in it.
  4. Shut the VM down, and in Settings, then Network, select Host-only Adapter or disable the adapter. Later labs tell you when you need internet access.
  5. Take a snapshot named clean-install.

Expected: A working Ubuntu VM that you can reset to a clean state at any time.

The snapshot gives you a safe way to undo any mistake. Limiting the network keeps experiments inside the VM. Use this lab only on your own computer.

Done when:

  • The VM starts and you can sign in.
  • A snapshot named clean-install exists.
  • You can state what network mode your VM uses and why.

3. See it in real products

Cloud hosting is why a product can scale overnight and why a customer's security questionnaire asks where data lives. Shared infrastructure also underlies the multi-tenant designs you will meet later, where many customers use one running system.

In security operations

  • A company stores customer files in a cloud storage service and leaves the bucket open to everyone. The provider ran its part correctly. The configuration and the data were the customer's responsibility.
  • Malware analysts open suspicious files in a VM with networking off, then restore a snapshot, so that the host stays clean.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A team moves an application to PaaS and assumes that everything is now the provider's job. An attacker later signs in with a former employee's account, which was still active. Who was responsible?

Compare your reasoning

The customer was. In every cloud model, the customer remains responsible for its data and for managing who has access. Removing the former employee's account was the customer's task, regardless of PaaS.

1. What software creates and runs virtual machines?

  • A hypervisor
  • A router
  • A database
  • A web browser
Answer and explanation
  • Correct: A hypervisor. The hypervisor divides the host's resources between VMs.
  • Incorrect: A router. A router forwards network traffic.
  • Incorrect: A database. A database stores and retrieves data.
  • Incorrect: A web browser. A browser is a client application.

2. A company uses an online email service and manages only its users and settings. Which cloud model is this?

  • SaaS
  • IaaS
  • PaaS
  • On-premises
Answer and explanation
  • Correct: SaaS. The company uses a finished application and manages only its data and users.
  • Incorrect: IaaS. IaaS would require the company to manage servers and operating systems.
  • Incorrect: PaaS. PaaS would require the company to deploy its own code.
  • Incorrect: On-premises. On-premises would mean running the email system itself.

3. Which items does the customer remain responsible for in SaaS? Choose two.

  • Who has access to the application
  • The data the customer puts into it
  • Patching the application's code
  • Replacing failed disks
Answer and explanation
  • Correct: Who has access to the application. Identity and access stay with the customer in every model.
  • Correct: The data the customer puts into it. Data ownership and protection stay with the customer.
  • Incorrect: Patching the application's code. In SaaS, the provider maintains the application.
  • Incorrect: Replacing failed disks. Physical infrastructure is the provider's job.

4. Why take a snapshot of a clean lab VM before testing?

  • To return quickly to a known-good state
  • To make the VM's disk encrypted
  • To give the VM more memory
  • To connect the VM to the internet
Answer and explanation
  • Correct: To return quickly to a known-good state. A snapshot lets you undo changes, even harmful ones.
  • Incorrect: To make the VM's disk encrypted. A snapshot does not encrypt anything.
  • Incorrect: To give the VM more memory. Snapshots do not change the resources allocated.
  • Incorrect: To connect the VM to the internet. Network access is a separate setting.

6. Review and references

Common mistakes

  • Assuming the cloud provider handles all security. Customers always keep responsibility for data and access.
  • Treating a VM as perfectly isolated. Isolation is strong but not absolute, so keep labs away from anything important.

Summary

  • A hypervisor runs VMs, and snapshots let you return to a known state.
  • IaaS, PaaS and SaaS move more management to the provider at each step.
  • Customers are always responsible for their own data and access.
