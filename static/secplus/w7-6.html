Wireless and switching attacks: deauthentication, WPS, evil twins and VLAN hopping

By the end, you can

  • Explain deauthentication, WPS PIN and evil twin attacks, and the settings that prevent them.
  • Compare WPA2 and WPA3, and EAP-TLS and PEAP, for personal and enterprise Wi-Fi.

Why it exists and what problem it solves

Wi-Fi and switches are the parts of a network people physically touch: anyone in range of an access point, or with a cable in a meeting-room socket, can reach them. Week 3 explained how these networks work. This lesson shows how they are attacked, and why a few configuration choices, such as switching off WPS or turning off automatic trunking, close whole classes of attack.

In plain language

A deauthentication attack is someone shouting "everyone out!" in the hotel lobby in the manager's voice: guests leave, then come back in, and the attacker watches how they do it. WPS is a spare key under the mat with a four-digit lock. An evil twin is a fake hotel front desk set up across the street. VLAN hopping is slipping from the visitors' corridor into the staff corridor by finding an unlocked connecting door.

2. Technical deep dive

Wi-Fi management frames, such as deauthentication and disassociation, were not authenticated in older networks. In a deauthentication attack, an attacker sends forged frames that appear to come from the access point, disconnecting clients. This is a denial of service on its own, and it is also used to force clients to reconnect: the attacker captures the WPA2 four-way handshake and tries passwords against it offline, or pushes clients toward an evil twin. Protected Management Frames (PMF), defined in IEEE 802.11w, authenticate these frames, and WPA3 requires them. Wireless intrusion detection and prevention systems can detect floods of these frames.

Wi-Fi Protected Setup (WPS) lets a device join with a button press or an eight-digit PIN instead of the password. The PIN method has a design flaw: the access point checks the PIN in two halves, and the last digit is a checksum, so only about eleven thousand guesses cover every possibility. Once the PIN is found, the attacker obtains the network password. Disable WPS, especially the PIN method, and keep access point firmware updated.

A rogue access point is any unauthorized access point connected to the network, such as one an employee plugs in for convenience. An evil twin is an attacker's access point that imitates a real network's name to lure clients. WEP and the original WPA are broken. WPA2-Personal uses a pre-shared key and is open to offline guessing from a captured handshake. WPA3-Personal uses Simultaneous Authentication of Equals (SAE), which resists offline guessing, and requires PMF.

Enterprise Wi-Fi and wired network access control use IEEE 802.1X. The supplicant is the user's device, the authenticator is the access point or switch, and the authentication server is usually RADIUS. The Extensible Authentication Protocol (EAP) is a framework with several methods. EAP-TLS uses certificates on both the server and the client, so there is no password to steal; it is the strongest common method. Protected EAP (PEAP) builds a TLS tunnel using only the server's certificate, then sends a password-based method inside, often MSCHAPv2. PEAP is easier to roll out, but if devices do not check the server's certificate, an evil twin running its own RADIUS server can capture credentials.

VLAN hopping is reaching a VLAN you should not be able to reach. In switch spoofing, the attacker's device negotiates a trunk link with a switch port that is set to form trunks automatically, and then receives traffic for every VLAN. In double tagging, an attacker on the native VLAN sends a frame with two 802.1Q tags: the first switch removes the outer tag and forwards the frame, and the next switch delivers it according to the inner tag into the target VLAN. Double tagging only works in one direction, so replies do not come back. Defences: set user ports to access mode, disable automatic trunk negotiation, use an unused VLAN as the native VLAN on trunks and never assign users to it, and tag the native VLAN where the switch supports it.

Walkthrough: Harden a small office's wireless and switches

  1. Choose WPA3, or WPA2/WPA3 transition mode if older devices must connect, with a long passphrase.
  2. Turn on PMF, and turn off WPS entirely.
  3. For staff, use 802.1X with EAP-TLS, or PEAP with server certificate checking enforced on every device.
  4. Separate guest Wi-Fi onto its own VLAN with internet access only.
  5. Set every user-facing switch port to access mode and disable automatic trunk negotiation.
  6. Move trunks to an unused native VLAN and enable wireless intrusion detection for rogue and evil twin access points.

Hands-on lab

Audit your own Wi-Fi and router settings

About 30 min. Your own laptop and home router

  1. List nearby networks with their security type. Linux: nmcli -f SSID,SECURITY device wifi list. Windows: netsh wlan show networks mode=bssid. macOS: hold Option and click the Wi-Fi icon. Do not connect to networks you do not own.
  2. On your own connection, check the security mode in use. On Windows: netsh wlan show interfaces, and read Authentication and Cipher.
  3. Sign in to your own home router's admin page. Record the security mode, whether WPS is on, and whether PMF or 802.11w is offered.
  4. If WPS is on, turn it off. If WPA3 or transition mode is available and your devices support it, switch to it, and note any device that can no longer connect.

Expected: You know whether your network uses WPA2 or WPA3, whether WPS was enabled and whether PMF is available, and you have reduced the attack surface of your own network.

These three settings decide whether the attacks in this lesson work at all: WPA3 resists offline guessing, PMF stops forged deauthentication, and disabling WPS removes a brute-force route to the password.

Done when:

  • You recorded the security mode, WPS status and PMF availability of your own network.
  • You explained which attack each setting prevents.

3. See it in real products

Wireless and switch security is mostly configuration, so it reaches products through management consoles and onboarding: how a Wi-Fi network is set up, whether weak defaults such as WPS are on, and how devices are told to trust a network's certificate. Prompts that ask people to accept an unknown certificate are where evil twin attacks succeed.

In security operations

  • Guests on an office's visitor Wi-Fi keep being disconnected every few minutes, and the wireless controller logs a flood of deauthentication frames from one location. Turning on PMF stops forged frames from disconnecting clients that support it.
  • A penetration tester plugs a laptop into a meeting-room socket and the switch port forms a trunk, giving access to the finance VLAN. The fix is to set that port to access mode and switch off automatic trunking on all user ports.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A company's staff Wi-Fi uses PEAP. Several laptops are set to trust any certificate. Staff report short disconnections in the lobby, then a network with the same name and a strong signal. The next week, two staff accounts show sign-ins from abroad. What happened, and what should change?

Compare your reasoning

A deauthentication attack pushed devices off the real network, and an evil twin with the same name offered its own RADIUS server. Because the laptops did not check the server's certificate, they sent their PEAP credentials to it, and the attacker used them to sign in. Reset those passwords, enforce server certificate checking for PEAP on every device, turn on PMF, deploy wireless intrusion detection, and plan a move to EAP-TLS so there is no password to capture.

1. Clients on a Wi-Fi network are repeatedly disconnected by forged frames that appear to come from the access point. Which setting most directly prevents this?

  • Protected Management Frames
  • Hiding the network name
  • MAC address filtering
  • A shorter DHCP lease
Answer and explanation
  • Correct: Protected Management Frames. PMF authenticates management frames, so forged deauthentication frames are ignored.
  • Incorrect: Hiding the network name. Hidden networks can still be found and attacked.
  • Incorrect: MAC address filtering. Addresses are easy to spoof and this does not protect management frames.
  • Incorrect: A shorter DHCP lease. This does not affect Wi-Fi management frames.

2. Why should WPS be disabled on a wireless router?

  • The PIN method can be brute forced in a few thousand guesses, revealing the network password
  • It makes the network invisible
  • It turns off encryption
  • It prevents WPA3 from working
Answer and explanation
  • Correct: The PIN method can be brute forced in a few thousand guesses, revealing the network password. The PIN is checked in two halves.
  • Incorrect: It makes the network invisible. WPS does not hide networks.
  • Incorrect: It turns off encryption. WPS does not disable encryption, but it gives a way to obtain the password.
  • Incorrect: It prevents WPA3 from working. That is not the reason; the PIN design is the weakness.

3. Which 802.1X method removes passwords from Wi-Fi sign-in entirely?

  • EAP-TLS
  • PEAP with MSCHAPv2
  • WPA2-Personal
  • WPS
Answer and explanation
  • Correct: EAP-TLS. Both sides use certificates, so there is no password to capture.
  • Incorrect: PEAP with MSCHAPv2. This still sends a password-based method inside the tunnel.
  • Incorrect: WPA2-Personal. This uses a shared passphrase, not 802.1X.
  • Incorrect: WPS. This is a setup shortcut, not an authentication method.

4. Staff laptops using PEAP accept any server certificate. What attack does this enable?

  • An evil twin with its own RADIUS server can collect staff credentials
  • Double tagging into another VLAN
  • Pass-the-ticket
  • DNS cache poisoning
Answer and explanation
  • Correct: An evil twin with its own RADIUS server can collect staff credentials. Without certificate checks, devices cannot tell the real server from a fake one.
  • Incorrect: Double tagging into another VLAN. That is a switching attack.
  • Incorrect: Pass-the-ticket. That reuses Kerberos tickets.
  • Incorrect: DNS cache poisoning. That targets resolvers, not Wi-Fi sign-in.

5. Match each attack to the configuration that prevents it.

Correct matches
  • Switch spoofing: Disable automatic trunk negotiation on user ports
  • Double tagging: Use an unused native VLAN on trunks
  • WPS PIN brute force: Turn off WPS
  • Forged deauthentication: Turn on Protected Management Frames

Each attack depends on one setting being left at a weak default.

6. Which statements about double tagging are true? Choose two.

  • The attacker must be on the native VLAN
  • Traffic only flows one way
  • It requires the attacker to know the Wi-Fi password
  • It works by negotiating a trunk
Answer and explanation
  • Correct: The attacker must be on the native VLAN. The first switch strips only the native VLAN's outer tag.
  • Correct: Traffic only flows one way. Replies cannot return the same way.
  • Incorrect: It requires the attacker to know the Wi-Fi password. It is a wired switching attack.
  • Incorrect: It works by negotiating a trunk. That describes switch spoofing.

6. Review and references

Common mistakes

  • Thinking a hidden network name or MAC filtering secures Wi-Fi. Both are easy to defeat; WPA3, PMF and 802.1X are real controls.
  • Rolling out PEAP without enforcing server certificate checks, which hands credentials to any evil twin.
  • Leaving switch ports to negotiate trunks automatically, which makes switch spoofing possible.

Summary

  • Forged deauthentication disconnects clients; PMF, required by WPA3, stops it.
  • Turn off WPS; prefer WPA3, and EAP-TLS or PEAP with certificate checks for staff.
  • VLAN hopping relies on automatic trunking or users on the native VLAN; configuration prevents both.

Flashcards

Which Wi-Fi feature stops forged deauthentication frames?

Protected Management Frames (IEEE 802.11w), required by WPA3.

PEAP or EAP-TLS: which needs no user password?

EAP-TLS, which uses certificates on both sides.

Two kinds of VLAN hopping?

Switch spoofing (negotiating a trunk) and double tagging (two VLAN tags from the native VLAN).
