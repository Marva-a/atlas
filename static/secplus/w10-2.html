Securing endpoints, mobile devices and operating systems

Lesson 39 · Week 10 · Domain 4: Security Operations · Objective 4.1 · Intermediate · about 120 min

Open this lesson in Atlas →

Professional relevance for cross-functional work

1. Learn the concept

By the end, you can

  • Compare antivirus, EDR and XDR.
  • Explain sandboxing, application control and MDM.
  • Describe Group Policy and SELinux.

Why it exists and what problem it solves

Most attacks end up on an endpoint. Stronger endpoint visibility and tighter control over what can run are often the difference between a blocked attack and a breach.

In plain language

Antivirus is a list of known criminals' photos. Endpoint detection and response is a detective watching for suspicious behaviour and able to intervene. Allow listing is a guest list: if your name is not on it, you do not get in. A sandbox is a quarantine room for testing a suspicious package.

2. Technical deep dive

Hardening removes unnecessary services, accounts and settings. Sandboxing runs code in an isolated environment. Application control restricts what software runs, through allow lists, which permit only approved items, or block lists, which forbid known bad items. Allow lists are stronger but need more upkeep.

Antivirus detects known malicious code and some suspicious behaviour. Endpoint detection and response (EDR) records endpoint activity, detects suspicious behaviour and enables a response such as isolating a host. Extended detection and response (XDR) correlates data across endpoints, networks, identity and email.

Mobile device management (MDM) enforces policies such as passcodes and encryption, can remotely wipe a lost device and controls apps. In Windows domains, Group Policy centrally applies settings to users and computers. Security-Enhanced Linux (SELinux) is a mandatory access control system that confines what each process can do, even if it runs as a privileged account.

Key terms

HardeningReducing attack surface through secure settings.
SandboxingRunning code in an isolated environment.
Application controlRestricting which software can run.
Allow listsLists of items that are explicitly permitted.
Block listsLists of items that are explicitly forbidden.
AntivirusSoftware that detects known malicious code and behaviours.
EDREndpoint detection and response: detects and responds on endpoints.
XDRExtended detection and response: correlates data across many sources.
MDMMobile device management: central control of mobile devices.
Group PolicyWindows feature that centrally applies settings.
SELinuxSecurity-Enhanced Linux: mandatory access control for Linux.

Walkthrough: Choose between allow list and block list

  1. If the environment is stable, like a kiosk or a server, consider an allow list.
  2. If users constantly need new software, a block list is easier but is weaker.
  3. Plan how updates are handled, since a new version can break a hash-based allow list.
  4. Apply the change using change management, and monitor what gets blocked.

Hands-on lab

Check SELinux or AppArmor and build a sandbox habit

About 35 min. Your lab VM

  1. In Ubuntu, run sudo aa-status to see AppArmor, Ubuntu's mandatory access control.
  2. If you have a Fedora or RHEL VM, run sestatus to view SELinux, and ls -Z to see file labels.
  3. Identify one confined program, and what it is confining.
  4. Write down how you would use a snapshot-based VM as a sandbox for an unknown file.

Expected: A list of confined profiles, and a safe written procedure.

Mandatory access control limits even privileged processes, which is why compromises of confined services can stay contained.

Done when:

  • You viewed profile or SELinux status.
  • Your sandbox procedure includes isolation and snapshot restore.

3. See it in real products

Device management reaches product design through conditional access: "this device is not compliant" is a confusing message for a user who cannot fix it. Mobile policies can also block copy and paste or screenshots inside a managed app.

In security operations

  • EDR notices Word launching PowerShell and isolates that laptop from the network, automatically.
  • A lost phone is remotely wiped using MDM.

4. Apply it as a Product Designer

No design exercise here, on purpose. Endpoint controls are mostly operated by IT. The useful design contribution is clear messaging, which the next exercises practice.

Engineering:

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A company's kiosks should run one application and nothing else. Which control provides the strongest enforcement?

Compare your reasoning

Application allow listing, as nothing outside the approved list can run. Block lists would miss anything unknown.

1. Which approach permits only approved software?

  • Allow list
  • Block list
  • Captive portal
  • Load balancing
Answer and explanation
  • Correct: Allow list. Everything not listed is blocked.
  • Incorrect: Block list. This forbids only named items.
  • Incorrect: Captive portal. This handles network access for guests.
  • Incorrect: Load balancing. This distributes requests.

2. What does EDR add beyond traditional antivirus?

  • Continuous behaviour monitoring and response actions such as host isolation
  • Only a larger signature list
  • Battery power for laptops
  • Replacement of user authentication
Answer and explanation
  • Correct: Continuous behaviour monitoring and response actions such as host isolation. EDR is designed for detection and response.
  • Incorrect: Only a larger signature list. EDR is not limited to signatures.
  • Incorrect: Battery power for laptops. This is unrelated.
  • Incorrect: Replacement of user authentication. This is unrelated.

3. An employee loses a company phone containing email. Which capability is most useful?

  • Remote wipe through MDM
  • SELinux enforcing mode
  • A WAF rule
  • A DMARC record
Answer and explanation
  • Correct: Remote wipe through MDM. MDM can erase the device remotely.
  • Incorrect: SELinux enforcing mode. This is for Linux access control.
  • Incorrect: A WAF rule. This is for web applications.
  • Incorrect: A DMARC record. This is for email domains.

4. A web server running as a service is compromised, but it cannot read other system files. What is the most likely reason?

  • SELinux confines the process by policy
  • The server has a UPS
  • The server has a CRL
  • XDR removed its IP address
Answer and explanation
  • Correct: SELinux confines the process by policy. Mandatory access control limits it.
  • Incorrect: The server has a UPS. A UPS protects power.
  • Incorrect: The server has a CRL. A CRL relates to certificates.
  • Incorrect: XDR removed its IP address. XDR does not do this.

6. Review and references

Common mistakes

  • Treating EDR and XDR as identical. XDR spans more data sources.
  • Assuming a block list stops new malware.

Summary

  • EDR adds behaviour-based detection and response.
  • Allow lists are stronger, and block lists are easier.
  • MDM, Group Policy and SELinux centralize or enforce control.
