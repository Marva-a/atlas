Data sources for investigations

Lesson 49 · Week 12 · Domain 4: Security Operations · Objective 4.8 · Intermediate · about 120 min

Open this lesson in Atlas →

Direct product design relevance

1. Learn the concept

By the end, you can

  • Identify which log types answer which questions.
  • Choose suitable data sources for an investigation.
  • Interpret key fields in logs.

Why it exists and what problem it solves

In an investigation, the right data answers the question quickly. Knowing where to look is frequently what separates a two-hour triage from a two-week one.

In plain language

Investigating an incident is like reconstructing a day using receipts, door badge records and security footage. Each source shows part of the picture. Combined, they tell the story.

2. Technical deep dive

Log and trace data types include access and accounting logs, which are either logical (sign-ins to systems) or physical (door badges); device logs from network equipment; server logs; application logs; authentication logs; communication logs such as email or chat records; audit logs of administrative action; endpoint logs; network logs; and metadata, data about data, such as file timestamps or email headers.

Data sources include vulnerability scans, which show what was exploitable; automated reports; NetFlow and Internet Protocol Flow Information Export (IPFIX), which summarize flows; surveillance footage; security tools such as EDR; dashboards; and packet captures, which contain full traffic content.

Walkthrough: Choose the data to investigate data theft

  1. Authentication logs show which account was used.
  2. Endpoint logs show which files were opened or compressed.
  3. Flow data shows how much went to which external host.
  4. Packet captures, if available, show content.
  5. Correlate timestamps to form the sequence.

Hands-on lab

Read packets and flows

About 40 min. Wireshark and a sample capture from the Wireshark wiki

  1. Download a small HTTP sample capture from the Wireshark SampleCaptures page. Open it only in your lab VM.
  2. Use Statistics, then Conversations, to view who talked to whom and how much.
  3. Filter using http.request and write down the requested paths.
  4. Use Follow, then TCP Stream, on one conversation.

Expected: A list of hosts, volumes and the requested URLs.

The conversations view resembles flow data, while following a stream shows the content that only a packet capture can provide.

Done when:

  • You recorded top conversations and two requested paths.
  • You can state what flow data would not have shown.

3. See it in real products

Audit logs are a product feature that customers buy. An investigator asks who did what, to which object, when, from where and with what result. If those fields are missing, inconsistent or easy to alter, the log is decoration. Export and retention settings then decide whether it survives until someone needs it.

In security operations

  • A badge record shows someone entered the office after hours, and a matching logical login confirms which workstation was used.
  • Email header metadata shows the true sending server, despite the displayed sender name.

4. Apply it as a Product Designer

Design brief: Design an administrator audit log

About 45 min

Scenario: An enterprise customer is investigating whether a former administrator exported customer data before leaving. The product's activity page lists vague entries such as "User updated settings".

Problem statement: The log is missing actors, objects, old and new values and IP addresses, so it can't answer an investigator's questions.

Your design task:

  • Define the event schema: actor, action, target, time, source and result.
  • Design search and filtering, timeline view and detail with old and new values.
  • Design export and streaming to a customer's SIEM.
  • Design retention settings with their consequences.

Technical security constraints:

  • Administrators must not be able to edit or delete audit entries.
  • Logs must not contain passwords, tokens or unnecessary personal data.
  • Time must be precise and shown with a clear time zone.

User needs:

  • Investigators need to reconstruct a sequence of events.
  • Compliance staff need evidence for a stated period.
  • Admins need to troubleshoot day-to-day changes.

Expected deliverable: An event schema with examples, plus search, detail and export designs.

Evaluation criteria:

  • Entries are complete, immutable to admins and free of secrets.
  • Insider misuse, including an admin covering their tracks, is considered.
  • A person can filter to one user and read a clear timeline.
  • Retention weighs investigation needs against privacy and cost.

Senior-level considerations:

  • Logging decisions are product decisions, because a missing event can't be recovered later.
  • Audit data can itself be sensitive, so decide who can read it.

A design review is not a security sign-off. Have security engineers confirm technical decisions.

Questions a Senior Product Designer should ask

Engineering:

  • Which events are recorded today, and which are missing?
  • Can a log entry be modified or deleted by an administrator?

Security:

  • What must be excluded from logs, such as secrets or personal data?

Product:

  • What retention period do customers require by contract?

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: An investigator needs to prove which employee physically accessed a server room overnight. Which data sources are most directly relevant?

Compare your reasoning

Physical access logs from badge readers, along with surveillance footage. Logical logs could show activity on systems but not who was in the room.

1. Which source shows actual packet contents?

  • Packet capture
  • NetFlow
  • A dashboard
  • A vulnerability scan
Answer and explanation
  • Correct: Packet capture. It records actual traffic.
  • Incorrect: NetFlow. It records metadata only.
  • Incorrect: A dashboard. It displays summaries.
  • Incorrect: A vulnerability scan. It reports weaknesses.

2. Which is an example of metadata?

  • An email header's sending server and timestamps
  • The paragraph text of the email
  • A person's memory of the email
  • The company's firewall vendor
Answer and explanation
  • Correct: An email header's sending server and timestamps. It describes the message.
  • Incorrect: The paragraph text of the email. That is the content.
  • Incorrect: A person's memory of the email. That is testimony.
  • Incorrect: The company's firewall vendor. That is unrelated.

3. Match each question to the best source.

Correct matches
  • Who approved a firewall change?: Audit logs
  • Who used a door badge at midnight?: Physical access logs
  • How much data went to an external address?: NetFlow
  • What did a running process do?: Endpoint logs

Each type records a different part of the story.

4. What is the most likely concern in this entry?

2026-10-02 03:14:22 SUCCESS login user=svc_backup src=198.51.100.23
2026-10-02 03:14:25 file_read user=svc_backup path=/hr/payroll.xlsx
  • A service account signed in from outside and accessed a payroll file
  • A normal backup, because the name contains backup
  • A hardware failure
  • An expired certificate
Answer and explanation
  • Correct: A service account signed in from outside and accessed a payroll file. The behaviour does not fit a backup account.
  • Incorrect: A normal backup, because the name contains backup. Names can be misleading.
  • Incorrect: A hardware failure. Nothing indicates a fault.
  • Incorrect: An expired certificate. Nothing indicates this.

B. Product design assessment

Rate your work in the interactive app, where it counts toward design competency only.

1. Which entry is most useful to an investigator?

  • J. Lee exported 4,120 contacts, 14:02 UTC, from 203.0.113.7, succeeded
  • A user performed an export action on the system today
  • Export complete! Your file is ready in the downloads folder
  • System event 4471 occurred in a production service cluster
Answer and explanation
  • Correct: J. Lee exported 4,120 contacts, 14:02 UTC, from 203.0.113.7, succeeded. It states the actor, action, object, time, source and result.
  • Incorrect: A user performed an export action on the system today. It has no identifiable actor, object or precise time.
  • Incorrect: Export complete! Your file is ready in the downloads folder. This is a user message and not a record of activity.
  • Incorrect: System event 4471 occurred in a production service cluster. An unexplained code doesn't answer an investigator's questions.

6. Review and references

Common mistakes

  • Relying on a single source.
  • Forgetting physical logs in technical investigations.

Summary

  • Each log type answers particular questions.
  • Flow data shows volume, and packets show content.
  • Correlate sources by time.
