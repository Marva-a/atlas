Network, application and credential attacks, and indicators of compromise

Lesson 28 · Week 7 · Domain 2: Threats, Vulnerabilities, and Attacks · Objective 2.5 · Intermediate · about 120 min

Open this lesson in Atlas →

Direct product design relevance

1. Learn the concept

By the end, you can

  • Explain network, application and credential attacks.
  • Recognize indicators of compromise in logs.
  • Distinguish commonly confused attacks such as spraying and brute force.

Why it exists and what problem it solves

This is where the networking foundation pays off. Attacks such as on-path, DNS poisoning and credential stuffing only make sense once you understand how normal traffic works. Indicators are how you know something has already happened.

In plain language

Network attacks intercept or flood the road. Application attacks trick the program into doing something it should not, like handing a waiter a note that reads and also bring me everyone's wallet. Credential attacks try to obtain the keys. Indicators of compromise are fingerprints left at the scene.

2. Technical deep dive

Network attacks: distributed denial of service (DDoS) overwhelms a target from many sources. A protocol downgrade forces a weaker protocol version. Rogue devices or access points attract traffic. Sniffing captures traffic. Spoofing fakes a source identity such as an IP or MAC address. An on-path attack places the attacker between two parties. Domain Name System (DNS) attacks include cache poisoning, which inserts false records into a resolver, so users are directed to the wrong address.

Application attacks: injection places untrusted input into a command or query. In SQL injection, input changes a database query. A buffer overflow writes past the end of a memory area. A replay attack resends captured valid data. Privilege escalation gains higher rights than granted. Forgery tricks a system into making or accepting a request, such as cross-site request forgery. Directory traversal uses paths like ../ to reach files outside the intended folder.

Credential attacks: password spraying tries a few common passwords against many accounts, avoiding lockouts. Brute force tries many passwords against an account. User enumeration works out which usernames exist, for example from different error messages. Replay reuses captured credentials or tokens. Multifactor authentication (MFA) bypass includes push fatigue, SIM swapping and token theft.

Indicators of compromise (IOCs) include a known malicious file hash, Internet Protocol (IP) address or domain; malicious processes; file system artifacts; a suspicious timestamp, which may have been altered; log manipulation or missing logs; excessive resource consumption; plaintext strings found in malware or memory; account lockout; impossible travel, such as sign-ins from two distant countries within minutes; and concurrent sessions from different places.

An on-path attacker relays traffic between two sides who each think they are talking directly. Checking the certificate is what breaks it.

Injection works when input is pasted into a command. The attacker's text stops being data and becomes part of the instruction.

A DDoS attacks availability: so many sources flood the target that real users are crowded out.

Walkthrough: Analyze a suspicious login log

  1. Note the account, the source IP and the time for each entry.
  2. Many accounts with few failures each suggests spraying.
  3. One account with many failures suggests brute force.
  4. A success after failures needs immediate attention.
  5. Sign-ins from two countries minutes apart are impossible travel.

Hands-on lab

Find the attack in a log

About 40 min. Text editor and grep in your lab VM

  1. In your VM, save lines of a sample log: five lines with the same password failure on different usernames, plus a line containing ' OR 1=1-- in a URL, plus a line with ../../etc/passwd.
  2. Use grep to find each of the two web attack patterns.
  3. Use cut and sort -u to count the usernames in the failure lines.
  4. Label each line with the attack name and the IOC it represents.

Expected: You locate each pattern and name it: spraying, SQL injection and directory traversal.

Real investigations use the same simple text tools. Patterns are recognizable once you know what they mean.

Done when:

  • You used grep to isolate each pattern.
  • You correctly named each attack.

3. See it in real products

Credential stuffing, password spraying and brute force all arrive at the same login page. How that page responds decides what attackers learn and what real users suffer. A lockout that stops an attacker can also lock out a whole company if it is triggered on purpose.

In security operations

  • Hundreds of accounts each have one failed login at 03:00 with the same password. That is password spraying rather than brute force.
  • A web log shows the path /download?file=../../etc/passwd. That is a directory traversal attempt.

4. Apply it as a Product Designer

Design brief: Design sign-in under attack

About 60 min

Scenario: A B2B SaaS product sees waves of automated sign-in attempts using credentials from other companies' breaches. Some accounts are taken over, and customers complain about lockouts.

Problem statement: The current login reveals which emails are registered and locks an account after five failures, which means attackers can lock out anyone they choose.

Your design task:

  • Write the response for each outcome: wrong password, unknown email, locked, throttled and suspicious device.
  • Design progressive friction in place of a hard lockout.
  • Design the new-device alert and the "this wasn't me" path.
  • Design password reset so that it doesn't confirm whether an account exists.

Technical security constraints:

  • Responses must not reveal whether an email is registered.
  • Friction must be applied per account and per source, and not to everyone.
  • Assistive technology must be able to complete any challenge shown.

User needs:

  • Real users who mistype should recover quickly.
  • Administrators need to see an attack happening across their tenant.
  • Users with disabilities must not be locked out by a challenge.

Expected deliverable: A login state table, a flow for progressive friction, and alert and recovery screens.

Evaluation criteria:

  • Responses are consistent, so account existence is not disclosed.
  • The design recognizes that lockout can be used to deny service.
  • A legitimate user who fails twice has a clear route forward.
  • Accessibility and the trade-off against conversion are addressed explicitly.

Senior-level considerations:

  • Ask for attack data before you choose friction levels, because good thresholds depend on real traffic.
  • Passkeys and multi-factor authentication shrink this whole problem, so raise the larger investment as well as the fix.

A design review is not a security sign-off. Have security engineers confirm technical decisions.

Questions a Senior Product Designer should ask

Engineering:

  • What rate limits apply per account, per IP address and overall?

Security:

  • Do we compare passwords against known-breached lists?

Product:

  • Do our login errors currently reveal whether an account exists?

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A sign-in log shows one user's successful login from Vancouver at 09:00 and another from Frankfurt at 09:12, with an MFA prompt approved at 09:11 following dozens of denied prompts. What is likely happening?

Compare your reasoning

Impossible travel suggests that someone else is using the account. The many denied prompts followed by an approval suggest MFA fatigue, a type of MFA bypass. The account should be contained and its sessions revoked.

1. An attacker tries one common password against thousands of accounts. What is this?

  • Password spraying
  • Brute force
  • Replay
  • Buffer overflow
Answer and explanation
  • Correct: Password spraying. It spreads attempts widely, so it avoids lockouts.
  • Incorrect: Brute force. Brute force targets one account with many passwords.
  • Incorrect: Replay. Replay reuses captured data.
  • Incorrect: Buffer overflow. This is a memory attack.

2. A URL contains ../../etc/passwd. What is being attempted?

  • Directory traversal
  • SQL injection
  • DDoS
  • Vishing
Answer and explanation
  • Correct: Directory traversal. The path sequences attempt to leave the intended folder.
  • Incorrect: SQL injection. There is no database query syntax here.
  • Incorrect: DDoS. There is only one request.
  • Incorrect: Vishing. This is a voice attack.

3. Which log entry most suggests SQL injection?

GET /search?q=shoes HTTP/1.1
GET /item?id=7' OR '1'='1 HTTP/1.1
GET /logo.png HTTP/1.1
  • The second request
  • The first request
  • The third request
  • None of them
Answer and explanation
  • Correct: The second request. The quoted condition is trying to alter a database query.
  • Incorrect: The first request. This is an ordinary search.
  • Incorrect: The third request. This is an image request.
  • Incorrect: None of them. The second line shows a classic pattern.

4. Which of these is the strongest evidence of an attempt to hide activity?

  • Security log entries are missing for a two-hour period
  • A patch was installed on schedule
  • A user changed a password as required
  • CPU use was normal
Answer and explanation
  • Correct: Security log entries are missing for a two-hour period. Log manipulation is an indicator of concealment.
  • Incorrect: A patch was installed on schedule. This is normal maintenance.
  • Incorrect: A user changed a password as required. This is expected.
  • Incorrect: CPU use was normal. This provides no indication of concealment.

5. Match each description to its attack.

Correct matches
  • False DNS answers in a resolver: Cache poisoning
  • Traffic captured for later reading: Sniffing
  • Forged source address: Spoofing
  • Flood from many machines: DDoS

Focus on what the attacker does to the traffic.

6. A user gets dozens of push requests overnight and eventually approves one to stop the noise. What is this?

  • MFA fatigue, a form of MFA bypass
  • Password spraying
  • Skimming
  • A race condition
Answer and explanation
  • Correct: MFA fatigue, a form of MFA bypass. Repeated prompts wear down the user.
  • Incorrect: Password spraying. That is an attempt at the password step.
  • Incorrect: Skimming. That is a card-reader attack.
  • Incorrect: A race condition. That is a timing flaw in software.

B. Product design assessment

Rate your work in the interactive app, where it counts toward design competency only.

1. Which sign-in message best avoids revealing whether an account exists?

  • That email or password didn't work
  • We can't find an account with that email
  • Your password is incorrect for this account
  • This account is locked until an administrator acts
Answer and explanation
  • Correct: That email or password didn't work. The same message covers both cases, so nothing is disclosed.
  • Incorrect: We can't find an account with that email. This tells an attacker which emails are not registered.
  • Incorrect: Your password is incorrect for this account. This confirms that the email is registered.
  • Incorrect: This account is locked until an administrator acts. This confirms the account exists, and it can be used to deny service.

6. Review and references

Common mistakes

  • Swapping spraying and brute force. Remember: spraying goes wide, brute force goes deep.
  • Treating one IOC as proof. Corroborate with other evidence.

Summary

  • Learn what each attack does to traffic, software or credentials.
  • Look for patterns such as many accounts versus many attempts.
  • IOCs are clues that need context and corroboration.
