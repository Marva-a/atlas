Operating systems, programs, processes and services

Lesson 2 · Week 1 · Foundations · Foundation (not an exam objective) · Beginner · about 120 min

Open this lesson in Atlas →

Foundational technical knowledge

1. Learn the concept

By the end, you can

  • Explain what an operating system does and compare Windows, Linux and macOS at a basic level.
  • Tell the difference between an application, a process and a service.
  • Describe how files, users and permissions decide who can do what on a system.

Why it exists and what problem it solves

Attackers run malicious processes, hide inside legitimate services and abuse accounts with too many permissions. Defenders look for exactly those things. Almost every log entry you will ever read names a user, a process or a file.

In plain language

The operating system (OS) is the manager of the computer. Programs do not touch the hardware directly. They ask the OS for memory, for files and for the network, and the OS decides whether to allow it.

An application is like a recipe book on the shelf. A process is the recipe actually being cooked right now. You can open the same application twice and get two separate processes. A service is a process that works in the background without anyone looking at it, like the building's heating.

2. Technical deep dive

The kernel is the core of the OS. It controls memory, the CPU and devices, and it separates programs from one another. Programs run in user space with limited rights and ask the kernel to do privileged work through system calls. A process has its own ID, called a PID, and runs on behalf of a user account, which decides what it may touch.

A service on Windows, or a daemon on Linux, starts in the background, often at boot. Files are organized in a hierarchy of folders. Each file has an owner and permissions. A user account represents a person or a program, and a group collects accounts so that permissions can be granted once rather than person by person.

Windows dominates business desktops and is common on servers, usually centrally managed. Linux is open source, comes in many distributions and runs most internet servers and cloud workloads. macOS is Apple's Unix-based system for its own hardware. The administrator account is called Administrator on Windows and root on Linux and macOS.

Key terms

Operating systemSoftware that manages hardware and gives programs a safe way to use it.
KernelThe core of the operating system, which controls hardware and separates programs.
ApplicationA program installed on the system, waiting to be run.
ProcessA running instance of a program.
Service or daemonA background process that usually starts automatically.
PIDProcess identifier: the number the OS gives each running process.
User accountAn identity that the OS uses to decide what is allowed.
GroupA named collection of accounts that share permissions.
PermissionA rule stating what an account may do with a file or other resource.
root and AdministratorThe most powerful accounts on Linux and macOS, and on Windows.

Walkthrough: Watch a program become a process

  1. You double-click a browser icon. The file on disk is the application.
  2. The OS copies what it needs into RAM and starts a process with a new PID.
  3. The process runs as your user account, so it can read your files but not another user's.
  4. Modern browsers start many processes, one for each group of tabs, to separate them.
  5. When you close the browser, the OS ends the processes and reclaims the memory.

Hands-on lab

Observe processes and services

About 30 min. Task Manager, Activity Monitor or a Linux terminal

  1. Open Task Manager on Windows and choose Processes, then Services. On macOS open Activity Monitor. On Linux run ps aux in a terminal.
  2. Find your browser in the list. Note how many processes it has.
  3. Find the user column. Windows: choose Details. Identify one process running as your account and one running as a system account.
  4. Open a second application, find its new process, then close it and confirm that it disappeared.

Expected: You can identify processes by name, see that they run under different accounts, and watch one appear and disappear.

The account shown decides the process's power. A process running as SYSTEM or root can reach far more than one running as you, which is why attackers want those accounts.

Done when:

  • You named one process run by your account and one run by the system.
  • You can explain the difference between an application and a process.

3. See it in real products

Background services are what keep running after a user closes a tab: sending notifications, generating reports, syncing files. Knowing that helps you design honest states such as "processing" and ask what happens when a background job fails.

In security operations

  • A web server runs as a low-privilege service account. If attackers break in through the website, they get only that account's limited rights unless they can escalate further.
  • Defenders treat a word processor that starts a command shell as suspicious, because a normal document has no reason to launch one.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: An analyst sees that an application called invoice.exe started a process that opened a command shell running as the user Maria. No one in accounting uses command shells. Which details matter most, and what do they suggest?

Compare your reasoning

Three facts matter: the parent program (invoice.exe), the child process (a command shell) and the account (Maria). A document or invoice program launching a shell is unusual, which suggests malicious code running with Maria's permissions. The next questions are what the shell did and whether Maria's account was misused elsewhere.

1. What is a process?

  • A program that is currently running
  • A file saved on disk
  • A list of user accounts
  • A folder that contains programs
Answer and explanation
  • Correct: A program that is currently running. A process is a running instance of a program, with its own PID and memory.
  • Incorrect: A file saved on disk. A file on disk is not running; that describes the application before it starts.
  • Incorrect: A list of user accounts. Accounts are identities and are separate from processes.
  • Incorrect: A folder that contains programs. A folder only organizes files.

2. A web server process is compromised. Why does it matter that the process runs as a low-privilege account rather than as root?

  • The attacker initially gets only that account's limited rights
  • Low-privilege accounts cannot be attacked at all
  • It makes the website faster for users
  • Root accounts cannot run web servers
Answer and explanation
  • Correct: The attacker initially gets only that account's limited rights. A process acts with its account's permissions, so a low-privilege account limits the damage.
  • Incorrect: Low-privilege accounts cannot be attacked at all. Any account can be attacked. The benefit is limiting the result.
  • Incorrect: It makes the website faster for users. Account privileges are a security control, not a performance feature.
  • Incorrect: Root accounts cannot run web servers. Root can run almost anything, which is exactly why it should not be used here.

3. Which of these are jobs of an operating system? Choose two.

  • Deciding whether a program may access a file
  • Allocating memory to programs
  • Writing the content of your documents
  • Physically supplying power to the CPU
Answer and explanation
  • Correct: Deciding whether a program may access a file. The OS enforces permissions on files.
  • Correct: Allocating memory to programs. Memory management is a core kernel job.
  • Incorrect: Writing the content of your documents. You and your applications create content, not the OS.
  • Incorrect: Physically supplying power to the CPU. The power supply is hardware, not an OS function.

4. True or false: permissions granted to a group apply to the accounts in that group.

  • True
  • False
Answer and explanation
  • Correct: True. Groups let an administrator grant permissions once rather than to each account.
  • Incorrect: False. Group membership is exactly how accounts inherit those permissions.

6. Review and references

Common mistakes

  • Assuming a familiar process name is safe. Malware often copies the name of a legitimate program.
  • Daily work as root or Administrator. Any malicious program you run then gets full control of the machine.

Summary

  • The OS manages hardware and enforces rules between programs.
  • An application is stored, a process is running and a service runs in the background.
  • Users, groups and permissions decide what each process can reach.
