Network controls: firewalls, IDS and IPS, content filters and NAC

Lesson 38 · Week 10 · Domain 4: Security Operations · Objective 4.1 · Intermediate · about 120 min

Open this lesson in Atlas →

Professional relevance for cross-functional work

1. Learn the concept

By the end, you can

  • Choose the right firewall type and write basic rules.
  • Distinguish IDS from IPS, and network from host-based sensors.
  • Explain content filtering and network access control.

Why it exists and what problem it solves

These are the everyday tools of a security team. Knowing which one fits a scenario is a major part of this domain, and PBQs often ask you to configure them.

In plain language

A firewall is a guard checking addresses and door numbers. A web application firewall reads the content of what is being carried. An intrusion detection system is a security camera with an alarm, and an intrusion prevention system is a guard who can actually step in.

2. Technical deep dive

Segmentation limits movement between areas of a network. Access controls decide who may reach what. Firewalls include rule-based filtering, which permits or denies according to a list; Layer 4 firewalls, which decide on addresses, ports and connection state; and Layer 7 firewalls, which understand applications. A web application firewall (WAF) protects web applications from attacks such as injection. Unified threat management (UTM) combines several functions in one device. Rate-limiting requests restricts how many requests are allowed in a period, which slows brute force and some denial-of-service attempts.

An intrusion detection system (IDS) monitors and alerts. An intrusion prevention system (IPS) sits inline and can block. Network-based intrusion detection system (NIDS) and network-based intrusion prevention system (NIPS) sensors watch network traffic. Host-based intrusion detection system (HIDS) and host-based intrusion prevention system (HIPS) agents watch a single host. A wireless intrusion prevention system (WIPS) detects and responds to wireless threats such as rogue access points. Detection may use signatures, which match known patterns, or anomalies, which flag departures from normal.

A content filter controls what users can reach or send. Data loss prevention (DLP) detects and blocks sensitive data leaving. Agent-based filters run on the device and work anywhere. A centralized proxy routes traffic through a central inspection point.

Network access control (NAC) decides whether a device may join a network. It uses 802.1X for port-based authentication, usually with a RADIUS server, endpoint posture and compliance checks such as patch level, and captive portals, the web pages that appear before guest Wi-Fi access. Monitoring and alerting tell you when these controls see something important.

An IDS detects and tells you. An IPS sits inline, so it can block, and so its mistakes matter more.

Walkthrough: Read a firewall rule list

  1. Rules are evaluated from top to bottom, and the first match wins.
  2. Rule 1: allow TCP 443 from any source to the web server.
  3. Rule 2: allow TCP 22 from the admin subnet to the web server.
  4. Rule 3: deny everything else, and log it.
  5. A broad allow rule placed above a specific deny rule will defeat it, so order matters.

Hands-on lab

Write and test firewall rules

About 40 min. ufw in your lab VM; the firewall PBQ in Atlas

  1. In your VM, run sudo ufw reset, then set default deny incoming and default allow outgoing.
  2. Allow TCP 443 from anywhere, and TCP 22 only from a subnet of your choice. Then run sudo ufw enable.
  3. Run sudo ufw status numbered. Explain each rule aloud.
  4. Complete the firewall exercise under Performance-based practice in Atlas.
  5. Finally, run sudo ufw disable or restore your snapshot.

Expected: Your rule list shows exactly the intended permissions.

Stating the purpose of each rule is good practice, because rules with no known reason build up over time and become risk.

Done when:

  • Your VM's rule list is correct.
  • You scored 80% or more on the firewall exercise.

3. See it in real products

Network controls appear in products as IP allow lists, rate-limit errors and web application firewall block pages. An over-eager firewall rule can stop a genuine customer, who then sees an unexplained error. A reference code on the block page lets support help them.

In security operations

  • A login page is rate-limited to five attempts a minute for each IP address, which slows guessing.
  • A laptop missing critical patches is placed by NAC into a remediation network until it is updated.

No design exercise here, on purpose. Firewalls are mostly technical knowledge, so the useful step is designing clear block states with your engineers.

  • How would a false positive be reported and resolved?

  • Which customers need IP allow lists, and who manages them?

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A web application is receiving SQL injection attempts. The network firewall already allows only port 443. Which control is most appropriate to add?

Compare your reasoning

A web application firewall, which inspects the contents of web requests. A Layer 4 firewall permits port 443 and cannot see the attack within. Secure coding should also be applied.

1. What is the key difference between an IDS and an IPS?

  • An IPS can block traffic, and an IDS only alerts
  • An IDS encrypts traffic
  • An IPS can only be used on Wi-Fi
  • An IDS replaces a firewall
Answer and explanation
  • Correct: An IPS can block traffic, and an IDS only alerts. The IPS sits inline and can act.
  • Incorrect: An IDS encrypts traffic. Neither system's purpose is encryption.
  • Incorrect: An IPS can only be used on Wi-Fi. IPS is used widely.
  • Incorrect: An IDS replaces a firewall. These have different roles.

2. Which control best stops cross-site scripting aimed at a web application?

  • WAF
  • Layer 4 firewall
  • UPS
  • Captive portal
Answer and explanation
  • Correct: WAF. It inspects application-layer web content.
  • Incorrect: Layer 4 firewall. It sees only ports, addresses and connection state.
  • Incorrect: UPS. This is a power device.
  • Incorrect: Captive portal. This controls guest network access.

3. A device is checked for patches and antivirus before it may join the network. What is this?

  • Network access control using endpoint posture
  • Rate limiting
  • A DLP proxy
  • A honeypot
Answer and explanation
  • Correct: Network access control using endpoint posture. NAC can check compliance before granting access.
  • Incorrect: Rate limiting. This limits request volume.
  • Incorrect: A DLP proxy. This focuses on data leaving.
  • Incorrect: A honeypot. This is a decoy system.

4. An ordered list reads: 1) allow any to any on TCP 443; 2) deny 203.0.113.9 to any on TCP 443. What happens to 203.0.113.9?

  • It is allowed, because rule 1 matches first
  • It is denied, because deny rules always take priority
  • It is logged and dropped automatically
  • The firewall will report a syntax error
Answer and explanation
  • Correct: It is allowed, because rule 1 matches first. First match wins, so rule 2 is never reached.
  • Incorrect: It is denied, because deny rules always take priority. Most firewalls process rules in order.
  • Incorrect: It is logged and dropped automatically. Nothing in this list would do that.
  • Incorrect: The firewall will report a syntax error. These rules are valid.

5. Match each need with a control.

Correct matches
  • Stop sensitive files leaving by email: DLP
  • Detect a rogue wireless access point: WIPS
  • Authenticate devices at a switch port: 802.1X
  • Slow repeated login attempts: Rate-limiting requests

Each tool has a specific purpose.

6. Review and references

Common mistakes

  • Thinking a firewall can stop every web attack.
  • Placing a broad allow rule above a narrow deny rule.

Summary

  • Firewalls enforce rules, and WAFs inspect web content.
  • IDS detects, and IPS can block.
  • NAC decides what devices may join.
