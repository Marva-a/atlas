Processes, services, logs and software updates

Lesson 14 · Week 4 · Foundations · Foundation (not an exam objective) · Beginner · about 120 min

Foundational technical knowledge

1. Learn the concept

By the end, you can

  • Inspect and manage processes and services.
  • Find and read basic system logs on Windows and Linux.
  • Explain why patching matters and how it is done safely.

Why it exists and what problem it solves

Logs are the story of what happened on a system, and most investigations are built from them. Patching closes the holes that attackers rely on most. These two habits sit at the centre of defensive work.

In plain language

Logs are a diary the computer keeps for itself. Each entry has a time, what happened and usually who did it. A patch is a repair sent out by a software maker, and installing it closes a known weakness, like fixing a broken lock.

2. Technical deep dive

On Linux, systemctl status shows a service, ps aux lists processes, and kill ends one. Logs are stored in /var/log, and systemd's journal is read with journalctl. On Windows, Task Manager and Get-Service show running software, and Event Viewer shows logs grouped as Application, Security and System.

Useful Windows Security event IDs include 4624 (successful logon), 4625 (failed logon) and 4688 (new process created, when that auditing is enabled). Accurate time is essential for connecting events across systems, which is why Network Time Protocol (NTP) matters.

Patch management means finding available updates, testing them, deploying them in order of risk, verifying they worked and recording it all. Automatic updates suit personal devices. Businesses often test first, because an update can break other software.

Key terms

LogA time-stamped record of an event.
Event ViewerThe Windows tool for reading system logs.
journalctlThe Linux command for reading the systemd journal.
systemctlThe Linux command that manages services.
Event IDA number identifying a type of Windows event.
NTPNetwork Time Protocol: keeps device clocks in sync.
PatchAn update that fixes a software problem.
Patch managementThe process of finding, testing, deploying and verifying updates.

Walkthrough: Investigate a failed sign-in on Linux

  1. Open a terminal in your lab VM.
  2. Run sudo grep -i "fail" /var/log/auth.log. On some distributions, the file is /var/log/secure.
  3. Read each result's timestamp, username and source.
  4. Count repeated attempts, and check whether a success follows.
  5. Note the time and compare it with any other evidence.

Hands-on lab

Read your system's diary

About 35 min. Event Viewer, or journalctl in your VM

  1. Linux VM: try su with a wrong password, then run sudo journalctl -n 30 and find the failure.
  2. Windows: open Event Viewer, then Windows Logs, then System, and open a recent entry. The Security log needs an administrator account.
  3. Check for pending updates: run sudo apt update in the VM or open Windows Update.
  4. List one thing you would verify before applying an update to a business-critical system.

Expected: You find your deliberate failed attempt with a timestamp and account name, and see any pending updates.

Causing a known event and finding it teaches you what an entry looks like before you need to find one under pressure.

Done when:

  • You located the event you caused and recorded its time and account.
  • You identified whether updates were pending.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A server shows no failed logons in its log for the past month, but the log file is unusually small and starts only yesterday. What should an analyst suspect?

Compare your reasoning

The log may have been cleared or rotated. A gap that begins recently can be a sign of tampering, so the analyst should check log forwarding to central storage and look for evidence of log clearing.

1. Which Windows tool is used to read system logs?

  • Event Viewer
  • Task Manager
  • Regedit
  • Notepad
Answer and explanation
  • Correct: Event Viewer. Event Viewer displays Application, Security and System logs.
  • Incorrect: Task Manager. Task Manager shows running processes.
  • Incorrect: Regedit. Regedit edits the registry.
  • Incorrect: Notepad. Notepad is a text editor and cannot open event logs properly.

2. Which Windows event ID records a failed logon?

  • 4625
  • 4624
  • 4688
  • 7045
Answer and explanation
  • Correct: 4625. 4625 records a failed logon attempt.
  • Incorrect: 4624. 4624 is a successful logon.
  • Incorrect: 4688. 4688 records process creation.
  • Incorrect: 7045. 7045 records a new service being installed.

3. Put the patching steps in order.

Correct order
  1. Identify available updates
  2. Test in a non-production environment
  3. Deploy, highest risk first
  4. Verify and record the result

Testing before deployment reduces the chance of an outage, and verification proves the fix took effect.

4. Why is NTP important in investigations?

  • Consistent clocks let events on different systems be placed in correct order
  • It encrypts log files
  • It stops attackers from signing in
  • It compresses old logs
Answer and explanation
  • Correct: Consistent clocks let events on different systems be placed in correct order. Investigators need reliable timestamps to reconstruct a timeline.
  • Incorrect: It encrypts log files. NTP synchronizes time and does not encrypt logs.
  • Incorrect: It stops attackers from signing in. NTP has no such role.
  • Incorrect: It compresses old logs. Compression is done by other tools.

6. Review and references

Common mistakes

  • Assuming a successful sign-in is harmless. Stolen credentials also produce successful sign-ins.
  • Keeping logs only on the machine that produced them, where an intruder can delete them.

Summary

  • Processes and services show what is running.
  • Logs record who did what and when, and depend on accurate time.
  • Patching closes known weaknesses and should be tested and verified.
