Wireless networking and basic troubleshooting

Lesson 12 · Week 3 · Foundations · Foundation (not an exam objective) · Beginner · about 120 min

Open this lesson in Atlas →

Foundational technical knowledge

1. Learn the concept

By the end, you can

  • Describe Wi-Fi basics, including SSIDs and WPA2 and WPA3.
  • Use a layered approach to troubleshoot a connection.
  • Use ping, DNS lookups and traceroute to narrow down a problem.

Why it exists and what problem it solves

Wi-Fi extends a network beyond its walls, so anyone within range can attempt to connect. Troubleshooting matters too: when an alert fires, you need to know quickly whether it is an attack or simply something broken.

In plain language

Wi-Fi replaces cables with radio. An access point broadcasts a network name, and anyone nearby can hear it, so encryption is what keeps the conversation private. Troubleshooting is like checking why a lamp will not turn on. You check the plug first, then the switch, then the bulb, in a logical order.

2. Technical deep dive

Wireless LANs follow the IEEE 802.11 standards, using frequency bands such as 2.4 GHz, 5 GHz and 6 GHz. A service set identifier (SSID) is the network's name. WPA2 and WPA3 are security standards. WEP and the original WPA are obsolete and should not be used. WPA3 improves on WPA2 with Simultaneous Authentication of Equals, which resists offline password guessing. Enterprise modes authenticate each user through 802.1X.

For troubleshooting, work up or down the layers. Check the physical link and whether the interface has an address. Use ping to test reachability to the gateway, then to an external IP address, then to a name. If an IP address works but a name does not, suspect DNS. Note that many systems block ping, so a failed ping does not prove a host is down.

An evil twin copies a trusted network's name. Devices pick the stronger signal, and the attacker sits in the middle.

Key terms

Wi-FiWireless networking based on the IEEE 802.11 standards.
SSIDService set identifier: the name of a wireless network.
WPA2Wi-Fi Protected Access 2: a security standard for Wi-Fi.
WPA3The newer Wi-Fi security standard, with stronger password protection.
WEPWired Equivalent Privacy: an obsolete and broken Wi-Fi standard.
Evil twinA fake access point that imitates a legitimate network.
pingA tool that tests whether a host replies, using ICMP.
ICMPInternet Control Message Protocol: used for error and status messages.

Walkthrough: Users cannot reach a website

  1. Check the device has a valid address. An address starting 169.254 points to DHCP.
  2. Ping the default gateway. Success shows the local network is working.
  3. Ping a known public address such as a public DNS server.
  4. Run nslookup on the site's name. If it fails while the IP ping works, the problem is DNS.
  5. If DNS works, try the site from elsewhere to see whether the service itself is down.

Hands-on lab

Diagnose by the layers

About 35 min. ping, nslookup, and your Wi-Fi settings

  1. Find your Wi-Fi security type in your device's network details. Note whether it is WPA2 or WPA3.
  2. Ping your default gateway and then ping 1.1.1.1. On Linux and macOS, stop it with Ctrl+C.
  3. Run nslookup example.com.
  4. In your lab VM, disconnect the network adapter and repeat the tests. Note which fail first.

Expected: With the adapter off, even the gateway ping fails. With it on, all succeed unless the network blocks ping.

Testing in order lets you find the first thing that breaks, which points to the layer that has the problem.

Done when:

  • You recorded your Wi-Fi security type.
  • You can explain what a failed gateway ping tells you that a failed website does not.

3. See it in real products

Wireless and troubleshooting knowledge helps you read a bug report. Whether a problem is the connection, the name lookup or the application changes who should fix it.

In security operations

  • A coffee shop's open Wi-Fi lets others nearby observe unencrypted traffic, and a nearby attacker can set up a similar network name.
  • An analyst finds that a server is unreachable by name but reachable by IP, and so saves hours by checking DNS rather than the application.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: Staff report an open network called CorpGuest appearing in the lobby alongside the real, password-protected corporate network. Nobody at the company set it up. What could this be, and why does it matter?

Compare your reasoning

It could be a rogue access point or an evil twin. Users who join could have their traffic observed or be sent to fake sign-in pages. It should be located and removed, and staff told to use only the approved network. Network and wireless monitoring help to detect this.

1. Which Wi-Fi security option should be avoided because it is broken?

  • WEP
  • WPA3
  • WPA2 with AES
  • WPA3-Enterprise
Answer and explanation
  • Correct: WEP. WEP has been broken for many years.
  • Incorrect: WPA3. WPA3 is the current standard.
  • Incorrect: WPA2 with AES. It is still widely used and acceptable when configured well.
  • Incorrect: WPA3-Enterprise. This is a strong option for organizations.

2. A user can ping 1.1.1.1 but cannot browse to any website by name. What is the most likely cause?

  • DNS resolution
  • The network cable
  • The default gateway
  • The Wi-Fi radio
Answer and explanation
  • Correct: DNS resolution. Reaching an IP address shows that routing works, so name resolution is the prime suspect.
  • Incorrect: The network cable. A faulty cable would stop the ping as well.
  • Incorrect: The default gateway. The ping left the network through the gateway successfully.
  • Incorrect: The Wi-Fi radio. The ping required working connectivity.

3. True or false: a host that does not answer ping must be powered off.

  • True
  • False
Answer and explanation
  • Incorrect: True. Many hosts and firewalls block ICMP, so no reply proves little.
  • Correct: False. Lack of a reply might only mean ICMP is being blocked.

4. Put these troubleshooting steps in a sensible order.

Correct order
  1. Confirm the device has a valid address
  2. Ping the default gateway
  3. Ping an external IP address
  4. Test name resolution

Each step depends on the one before, so the first failure points to the problem.

6. Review and references

Common mistakes

  • Assuming a network name proves a network is legitimate. Anyone can broadcast any SSID.
  • Reading a failed ping as definite proof a host is offline.

Summary

  • Wi-Fi reaches past your walls, so encryption and authentication are essential.
  • Prefer WPA3, or WPA2 with AES, and never WEP.
  • Troubleshoot in order so that the first failure identifies the layer.

References
