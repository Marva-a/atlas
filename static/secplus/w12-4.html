Evidence handling and hands-on log investigation

Lesson 50 · Week 12 · Domain 4: Security Operations · Objective 4.8 · Advanced · about 120 min

Open this lesson in Atlas →

Professional relevance for cross-functional work

1. Learn the concept

By the end, you can

  • Preserve evidence with hashes and images.
  • Use log-parsing techniques to extract a timeline.
  • Involve the right stakeholders.

Why it exists and what problem it solves

A good investigation needs both technical skill and care. Evidence that was changed can't be trusted, and a finding that isn't communicated to the right people can't be acted on.

In plain language

A forensic copy is like a photograph of a crime scene taken before anyone moves anything. Investigators work from the copy, so the original stays untouched.

2. Technical deep dive

File and log integrity is confirmed by hashing a copy and comparing later. System images include a memory dump, which captures RAM; a bit-level copy, which duplicates every bit of a drive, including deleted space; and a snapshot, which captures the state of a VM. The order of volatility means collecting the most volatile sources, such as memory, before less volatile ones, such as disks.

Stakeholders include Human Resources (HR) for employee matters, accounts (finance) for financial losses and billing fraud, and legal for evidence, privacy and notification issues. Log-parsing techniques include filtering with grep, extracting fields with cut or awk, counting with sort and uniq, and using regular expressions, as well as queries in a SIEM.

Walkthrough: Build a timeline from logs

  1. Extract only relevant lines using grep.
  2. Pull out the timestamp, user and source fields.
  3. Sort them by time.
  4. Merge lines from different systems, adjusting for time zones.
  5. Mark the first suspicious event and each later step.

Hands-on lab

Investigate a suspicious connection

About 45 min. grep, sort and uniq in your lab VM

  1. Create auth.log containing these invented lines, adding your own: Oct 2 03:01 FAILED bob 198.51.100.7; Oct 2 03:02 FAILED amy 198.51.100.7; Oct 2 03:03 FAILED raj 198.51.100.7; Oct 2 03:04 OK raj 198.51.100.7; Oct 2 08:30 OK amy 10.0.4.15.
  2. Run grep FAILED auth.log | awk '{print $NF}' | sort | uniq -c to count failures by source.
  3. Run sha256sum auth.log and save the hash. Copy the file, and verify the copy has the same hash.
  4. Write a timeline and a one-paragraph incident summary.
  5. Complete the log-analysis exercise under Performance-based practice in Atlas.

Expected: The counts show one source hitting several accounts, followed by a success for raj. The hashes of original and copy match.

One source failing against many accounts and then succeeding is the signature of a spraying attack that worked.

Done when:

  • Your hashes matched.
  • Your summary identifies the attack, the affected account and the next action.

3. See it in real products

Legal holds and chain of custody reach products through e-discovery tools and evidence exports. A hold that can quietly be removed, or an export with no record of who ran it, undermines the evidence.

In security operations

  • An investigator hashes a disk image at collection and again before analysis. Matching values show the copy is unchanged.
  • A suspected insider case needs HR and legal involved early, to keep the investigation fair and lawful.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A responder must collect evidence from a running compromised server. Should memory or disk be collected first, and why?

Compare your reasoning

Memory first, as it is the most volatile, and is lost at shutdown. Then collect a bit-level disk copy, and hash each item.

1. Which capture records the contents of RAM?

  • Memory dump
  • Bit-level copy of a disk
  • NetFlow export
  • A backup tape
Answer and explanation
  • Correct: Memory dump. It records volatile memory.
  • Incorrect: Bit-level copy of a disk. This copies storage.
  • Incorrect: NetFlow export. This records flows.
  • Incorrect: A backup tape. This is storage.

2. How can an investigator show that a forensic copy has not changed?

  • Compare cryptographic hashes taken at different times
  • Compare file names
  • Check the screen resolution
  • Ask the suspect
Answer and explanation
  • Correct: Compare cryptographic hashes taken at different times. Matching hashes indicate that the data has not changed.
  • Incorrect: Compare file names. Names can match while content differs.
  • Incorrect: Check the screen resolution. This is unrelated.
  • Incorrect: Ask the suspect. This is not evidence of integrity.

3. Which command counts repeated lines after sorting?

  • uniq -c
  • chmod 600
  • ping -c 4
  • ssh-keygen
Answer and explanation
  • Correct: uniq -c. It prefixes each unique line with its count.
  • Incorrect: chmod 600. This changes permissions.
  • Incorrect: ping -c 4. This tests reachability.
  • Incorrect: ssh-keygen. This creates keys.

4. Which conclusion fits this log best?

03:01 FAILED bob from 198.51.100.7
03:02 FAILED amy from 198.51.100.7
03:03 FAILED raj from 198.51.100.7
03:04 SUCCESS raj from 198.51.100.7
  • Password spraying from one address that succeeded against raj
  • A failed backup job
  • DNS cache poisoning
  • Certificate revocation
Answer and explanation
  • Correct: Password spraying from one address that succeeded against raj. One source failing across accounts, then succeeding, fits the pattern.
  • Incorrect: A failed backup job. Nothing points to backups.
  • Incorrect: DNS cache poisoning. This is a name resolution attack.
  • Incorrect: Certificate revocation. This is unrelated.

5. An employee is suspected of misusing payroll access. Which stakeholders should be involved? Choose two.

  • HR
  • Legal
  • The attacker's internet provider first
  • All staff through an announcement
Answer and explanation
  • Correct: HR. The matter concerns an employee.
  • Correct: Legal. Evidence and rights must be handled properly.
  • Incorrect: The attacker's internet provider first. That is not the immediate priority.
  • Incorrect: All staff through an announcement. This risks fairness and the investigation.

6. Review and references

Common mistakes

  • Analyzing the original evidence directly.
  • Forgetting time zones when merging logs.

Summary

  • Collect the most volatile evidence first.
  • Hash images to prove integrity.
  • Parse logs into a timeline.
