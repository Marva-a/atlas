DHCP, DNS, NAT and how a packet finds its way

Lesson 8 · Week 2 · Foundations · Foundation (not an exam objective) · Beginner · about 120 min

Open this lesson in Atlas →

Professional relevance for cross-functional work

1. Learn the concept

By the end, you can

  • Explain what DHCP, DNS and NAT each do.
  • Describe the steps from joining a network to loading a website.
  • Use nslookup and traceroute to observe these services.

Why it exists and what problem it solves

Attackers abuse all three. Rogue DHCP can redirect traffic, DNS can be poisoned or used to hide data, and NAT shapes what logs can tell you. Before you can recognize those attacks, you need to know what normal looks like.

In plain language

When you join a network, DHCP acts like a hotel front desk: it assigns you a room number, and tells you where the exit is and who to ask for directions. DNS is the phone book that turns a name such as example.com into a number. NAT is the company switchboard: many people inside share one outside number.

A packet is a small labelled parcel of data. Each router along the way reads the destination and passes the parcel closer to it, the way postal centres do.

2. Technical deep dive

The Dynamic Host Configuration Protocol (DHCP) gives a device its IP address, subnet mask, default gateway and DNS server. The exchange has four messages: Discover, Offer, Request and Acknowledge, often remembered as DORA. The address is leased for a limited time.

The Domain Name System (DNS) translates domain names into addresses. A resolver asks on your behalf and caches answers for a time set by the record's time to live (TTL). The resolver works from the root servers to the top-level domain servers to the domain's authoritative server. Common record types are A (IPv4), AAAA (IPv6), CNAME (an alias), MX (mail server), TXT (text, used for email security) and NS (name server).

Network Address Translation (NAT) rewrites addresses as traffic crosses a router. In the common form, many private addresses share one public address, with port numbers keeping conversations apart. Before a device can send to another on the local segment, it uses the Address Resolution Protocol (ARP) to find the matching MAC address.

The resolver does the walking: root, then .com, then the domain's own server. It caches the answer so the next lookup is instant.

Many private addresses share one public address. The router rewrites each one and uses port numbers to send replies back to the right device.

Key terms

DHCPDynamic Host Configuration Protocol: automatically assigns network settings.
DORADiscover, Offer, Request, Acknowledge: the four steps of a DHCP exchange.
DNSDomain Name System: translates names into IP addresses.
ResolverThe DNS server that looks up answers on a client's behalf.
Authoritative serverThe DNS server holding the official records for a domain.
TTLTime to live: how long a DNS answer may be cached.
A recordA DNS record mapping a name to an IPv4 address.
MX recordA DNS record that names a domain's mail servers.
NATNetwork Address Translation: rewrites addresses as traffic crosses a router.
ARPAddress Resolution Protocol: finds the MAC address for an IP address on the local network.
PacketA unit of data with addressing information.

Walkthrough: From joining Wi-Fi to loading a page

  1. Your laptop joins Wi-Fi and uses DHCP to get an address, a gateway and a DNS server.
  2. You type www.example.com. The laptop asks its DNS resolver for the address.
  3. The destination is on another network, so the laptop uses ARP to find the gateway's MAC address.
  4. The laptop sends the packet to the gateway. NAT replaces the private source address with a public one.
  5. Routers across the internet forward the packet toward its destination, and the reply returns the same way.

Hands-on lab

Watch names and paths

About 40 min. nslookup, and tracert or traceroute

  1. Run nslookup example.com. Note the server that answered and the address returned.
  2. Run nslookup -type=mx example.com to view mail records, or use your own domain if you have one.
  3. Windows: run tracert example.com. Linux or macOS: run traceroute example.com. Each line is a router on the path.
  4. Note where the addresses change from private to public on the path.

Expected: DNS returns one or more addresses, and traceroute lists a series of hops. Some hops may show asterisks because those routers do not reply.

Traceroute shows the path because each hop reports back when a packet's hop limit expires. Asterisks do not by themselves mean failure. Only trace paths to ordinary public names like this, and do not scan or probe systems without permission.

Done when:

  • You recorded the DNS answer and at least three traceroute hops.
  • You identified where the path leaves your private network.

3. See it in real products

DNS appears in products whenever a customer connects a custom domain or verifies domain ownership for single sign-on. Those setup flows ask non-experts to copy records into another system, and then wait through propagation delays that the product cannot control.

In security operations

  • A log shows many devices connecting from one public IP address. That is often NAT, so one address does not necessarily mean one computer.
  • Security teams watch DNS logs because malware has to look up where to connect, which can reveal infected hosts.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: Users report that typing their bank's correct address takes them to a fake website, while typing the bank's real IP address works normally. Which service should be investigated first?

Compare your reasoning

DNS. The name is resolving to the wrong address, and the direct IP works, so routing is fine. Likely causes include a poisoned cache or changed DNS settings. DHCP could matter too if it handed out a malicious DNS server, so check which DNS server clients are using.

1. What does DNS do?

  • Translates domain names into IP addresses
  • Assigns IP addresses to devices
  • Encrypts web traffic
  • Finds the MAC address for an IP address
Answer and explanation
  • Correct: Translates domain names into IP addresses. DNS is the internet's naming system.
  • Incorrect: Assigns IP addresses to devices. Assigning addresses is the job of DHCP.
  • Incorrect: Encrypts web traffic. TLS encrypts web traffic.
  • Incorrect: Finds the MAC address for an IP address. That is the job of ARP.

2. Put the DHCP exchange in order.

Correct order
  1. Discover
  2. Offer
  3. Request
  4. Acknowledge

The client looks for a server, the server offers an address, the client asks for it and the server confirms.

3. Why might many office computers appear as a single address in a website's log?

  • NAT translates their private addresses to one public address
  • They all have the same MAC address
  • DNS gave them all the same private address
  • The website's firewall merged them
Answer and explanation
  • Correct: NAT translates their private addresses to one public address. Many private hosts commonly share a public address through NAT.
  • Incorrect: They all have the same MAC address. Each interface has its own MAC, and MACs do not reach websites anyway.
  • Incorrect: DNS gave them all the same private address. DNS does not assign addresses to clients.
  • Incorrect: The website's firewall merged them. The translation happens at the office's router.

4. Match each protocol to its function.

Correct matches
  • DHCP: Assigns network configuration
  • DNS: Resolves names to addresses
  • NAT: Translates private to public addresses
  • ARP: Finds a MAC address on the local network

Four services run almost invisibly every time a device goes online.

6. Review and references

Common mistakes

  • Mixing up DNS and DHCP. DNS answers what address a name has, while DHCP gives a device its own settings.
  • Assuming that a public IP in a log identifies one person. NAT may be hiding many users behind it.

Summary

  • DHCP configures a device, and DNS finds addresses from names.
  • NAT lets many private devices share a public address.
  • Packets travel from router to router toward their destination.
