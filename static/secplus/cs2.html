Design brief: An AI assistant with connected tools

About 90 min

Scenario: Your company is adding an AI assistant that can read a user's documents, connect to outside tools through OAuth and take actions. It uses an external model provider.

Problem statement: The team has discussed only the assistant's helpfulness. Nothing defines what data leaves the company, whose permissions it uses or how a person stops it.

Your design task:

  • Draw the data flow, including the model provider and every connected tool.
  • Mark the points where untrusted content can influence the assistant.
  • Define permissions, confirmations and limits for its actions.
  • Design the vendor and data-use disclosure for administrators.
  • Design a rollback plan and incident path for assistant misbehaviour.

Technical security constraints:

  • The assistant can't have broader access than the user it acts for.
  • Content retrieved from documents and tools is untrusted input.
  • Provider data retention and training terms must be confirmed before you state them.

User needs:

  • Users need to know what the assistant will do before it acts.
  • Administrators need controls by group and data type.
  • Security staff need logs of prompts, tools and actions, handled with care.

Expected deliverable: A data flow diagram, an action permission table and administrator control designs.

Evaluation criteria:

  • Permission boundaries, OAuth scopes and data classification are all applied.
  • Prompt injection, data leakage and vendor risk are covered together.
  • A user can see, confirm and undo what the assistant does.
  • A go-or-no-go recommendation is given, with conditions and owners.

Senior-level considerations:

  • Be willing to recommend a smaller launch if the safeguards aren't ready.
  • AI security changes fast, so date your assumptions and plan to review them.

A design review is not a security sign-off. Have security engineers confirm technical decisions.

Design critique

1. A connected document contains hidden text telling the assistant to send files to an outside address. What limits the damage most?

  • Scoped tool permissions and confirmation before sending outside
  • A friendlier assistant personality in its written replies
  • Longer documents, so that hidden instructions are diluted
  • A filter that blocks the single word "ignore" in documents
Answer and explanation
  • Correct: Scoped tool permissions and confirmation before sending outside. The assistant's ability to act is limited even if it is manipulated.
  • Incorrect: A friendlier assistant personality in its written replies. Tone has no effect on what the assistant can do.
  • Incorrect: Longer documents, so that hidden instructions are diluted. Length offers no protection against injection.
  • Incorrect: A filter that blocks the single word "ignore" in documents. Attackers can easily rephrase the instruction.
