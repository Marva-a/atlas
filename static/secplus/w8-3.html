Secure infrastructure: zones, placement and Zero Trust architecture

Lesson 32 · Week 8 · Domain 3: Security Architecture · Objective 3.2 · Intermediate · about 120 min

Open this lesson in Atlas →

Professional relevance for cross-functional work

1. Learn the concept

By the end, you can

  • Place security devices and define security zones.
  • Explain how diversity reduces risk.
  • Describe the elements of Zero Trust architecture.

Why it exists and what problem it solves

Where you put a control matters as much as which control you buy. An IDS watching the wrong link sees nothing, and a flat network lets a single compromise spread everywhere.

In plain language

Think of an airport. There is a public hall, a secure area after screening and restricted zones for staff. Guards stand at the transitions, not randomly in the middle of the hall.

2. Technical deep dive

Device placement means putting each control where it can see or enforce the right traffic. A firewall sits at a boundary. An intrusion prevention system sits inline, while a detection sensor may watch a copy of traffic. Security zones group systems of similar trust and sensitivity, such as a screened subnet for public services, an internal zone and a restricted zone. Attack surface is reduced by removing exposure. Diversity means using different vendors, technologies or controls, so that one flaw does not defeat every layer.

In Zero Trust architecture, every request is evaluated. User authentication confirms who is asking, preferably with strong MFA. Device management checks device health, such as patch level and security software, and device inventory confirms that the device is known. Application access control grants access to specific applications, rather than to whole networks. The policy decision and enforcement functions apply these checks for each request.

Security zones. Traffic between zones must pass through a policy enforcement point.

Walkthrough: Place controls for a small company

  1. Identify the zones: internet, screened subnet, users, servers.
  2. Place a firewall at each boundary.
  3. Put public services in the screened subnet.
  4. Place an inline IPS where blocking is needed, and sensors where visibility is needed.
  5. Allow only the required flows between zones and deny the rest.

Hands-on lab

Design a segmented network

About 40 min. Drawing tool; Packet Tracer optional

  1. Draw a company with staff, guests, servers, a public website and a building-control system.
  2. Assign each group to a zone and give each a subnet from 10.0.0.0/16.
  3. Write the allowed flows between zones, with everything else denied.
  4. Mark where you would place a firewall, an IPS and a monitoring sensor.

Expected: A diagram in which guests cannot reach internal zones, and only required flows are allowed.

A short list of permitted flows is easier to protect than a long list of prohibitions.

Done when:

  • Each group is in its own zone.
  • Guest and building-control traffic is isolated from user and server zones.

3. See it in real products

Zero Trust reaches users as continuous checks: a device must be compliant, a session can be re-evaluated, and access can change partway through. Interfaces need to explain why someone who was allowed a moment ago is now being blocked.

In security operations

  • A public web server sits in a screened subnet, so if it is compromised, a second firewall still separates it from internal databases.
  • A company uses a firewall from one vendor at the edge and another internally, so one vendor's flaw does not open both.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: An organization has one flat network. Ransomware on a single laptop spreads to its servers within minutes. Which architectural change would most directly limit this?

Compare your reasoning

Segmentation into security zones with controlled traffic between them. Servers would be reachable only through the ports required, which limits lateral movement.

1. Where should a public-facing web server usually be placed?

  • A screened subnet
  • The internal user network
  • The OT network
  • On the same subnet as the database
Answer and explanation
  • Correct: A screened subnet. This separates it from internal systems.
  • Incorrect: The internal user network. A compromise would then land among users.
  • Incorrect: The OT network. This would expose control systems.
  • Incorrect: On the same subnet as the database. This removes a layer of separation.

2. A security team wants a tool to stop malicious traffic automatically. Where must it be placed?

  • Inline in the traffic path
  • On a mirrored port
  • On a separate, unconnected network
  • On a backup tape
Answer and explanation
  • Correct: Inline in the traffic path. Only an inline device can block in real time.
  • Incorrect: On a mirrored port. A mirror only receives a copy of traffic.
  • Incorrect: On a separate, unconnected network. It would see nothing.
  • Incorrect: On a backup tape. This is not a network location.

3. A managed laptop is out of date and fails a health check. What should a Zero Trust system do?

  • Deny or limit access until it is remediated
  • Grant full access because the password was correct
  • Grant access because the laptop is on the corporate network
  • Delete the user's account
Answer and explanation
  • Correct: Deny or limit access until it is remediated. Device health is part of the access decision.
  • Incorrect: Grant full access because the password was correct. Authentication alone is not sufficient.
  • Incorrect: Grant access because the laptop is on the corporate network. Location gives no trust.
  • Incorrect: Delete the user's account. This is out of proportion.

4. Why might an organization use firewalls from two vendors?

  • A vulnerability in one is less likely to affect the other
  • To eliminate the need to patch
  • To ensure identical configuration
  • Because one firewall cannot enforce any rules
Answer and explanation
  • Correct: A vulnerability in one is less likely to affect the other. Diversity avoids a single shared weakness.
  • Incorrect: To eliminate the need to patch. Both still need patches.
  • Incorrect: To ensure identical configuration. They will differ in practice.
  • Incorrect: Because one firewall cannot enforce any rules. A single firewall can enforce rules.

6. Review and references

Common mistakes

  • Placing a detection sensor where encrypted or irrelevant traffic is all it can see.
  • Equating being inside the network with being trusted.

Summary

  • Put controls where they can see or enforce traffic.
  • Zones limit how far an attacker can move.
  • Zero Trust checks user, device and application for each request.
