TCP, UDP, ports and how traffic moves

Lesson 10 · Week 3 · Foundations · Foundation (not an exam objective) · Beginner · about 120 min

Open this lesson in Atlas →

Foundational technical knowledge

1. Learn the concept

By the end, you can

  • Compare TCP and UDP and choose the right one for a use.
  • Explain what a port is and describe the TCP three-way handshake.
  • Recall the common ports and their services.

Why it exists and what problem it solves

Ports are where services listen, and each open port is a possible way in. Firewall rules and scan results are written in ports, and a port outside the expected list can be the first clue of trouble.

In plain language

An IP address gets a delivery to the right building, and the port is the apartment number. A web server waits behind one door, and an email server behind another.

TCP is like a phone call: you confirm the other person is there and each part is acknowledged. UDP is like dropping postcards in a mailbox: quick, with no confirmation they arrived.

2. Technical deep dive

The Transmission Control Protocol (TCP) is connection-oriented. It sets up a connection using a three-way handshake of SYN, SYN-ACK and ACK, numbers data, retransmits lost segments and closes the connection deliberately. The User Datagram Protocol (UDP) is connectionless and sends datagrams without those guarantees, so it has less overhead. Streaming, voice and DNS queries commonly use UDP.

Ports are 16-bit numbers, from 0 to 65535. Ports 0 to 1023 are well-known, 1024 to 49151 are registered, and 49152 to 65535 are dynamic or ephemeral. A client typically uses a temporary high port to reach a server's well-known port. A switch forwards frames by MAC address, and a router forwards packets by consulting its routing table for the best next hop.

Three messages before any data: SYN, SYN-ACK, ACK. Both sides have now confirmed they can send and receive.

Key terms

TCPTransmission Control Protocol: connection-oriented and reliable delivery.
UDPUser Datagram Protocol: connectionless delivery without guarantees.
Three-way handshakeSYN, SYN-ACK, ACK: how TCP opens a connection.
PortA number identifying a service or conversation on a device.
Ephemeral portA temporary high port used by a client.
SocketThe combination of an IP address, protocol and port.
Routing tableA list a router uses to choose the next hop for a destination.
Next hopThe next router along the path to a destination.

Walkthrough: Open a TCP connection to a website

  1. Your computer picks a temporary source port such as 51234.
  2. It sends a SYN to the server's port 443.
  3. The server replies with SYN-ACK.
  4. Your computer sends ACK, and the connection is established.
  5. TLS and the web request now travel over that connection.

Hands-on lab

See listening ports and a handshake

About 40 min. netstat or ss, and Wireshark, on your own computer

  1. Windows: run netstat -ano. Linux: run ss -tuln. macOS: run netstat -an.
  2. Note which ports your computer is listening on, and look up three of them.
  3. In Wireshark, capture while opening a website. Apply the display filter tcp.flags.syn == 1 and find a SYN and its SYN-ACK.
  4. Optional, using only your lab VM: run nmap against 127.0.0.1 and compare the result with the list above. Never scan systems you do not own without permission.

Expected: A list of listening ports and a visible handshake with matching port numbers.

The listening list shows which doors are open. Every port that does not need to be open is unnecessary exposure.

Done when:

  • You named the service for at least three listening or common ports.
  • You found the SYN and SYN-ACK of one connection.

3. See it in real products

Ports matter most when an enterprise firewall blocks a feature, which can surface as a mysterious failed connection. A good error message says a network may be blocking the service, and gives administrators what they need to allow it.

In security operations

  • A server scan finds port 3389 open to the internet. Remote desktop exposed like this is a common way attackers get in.
  • A firewall rule allows outbound 443, because users need websites, and blocks most other outbound ports.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A team wants to send live voice between offices. Occasional lost packets are acceptable, but delay is not. Should the application favour TCP or UDP?

Compare your reasoning

UDP. Retransmitting a lost piece of a live conversation arrives too late to be useful, and TCP's waiting adds delay. UDP gives low overhead and leaves occasional loss for the application to tolerate.

1. Which port is normally used by HTTPS?

  • 443
  • 80
  • 22
  • 25
Answer and explanation
  • Correct: 443. HTTPS uses TCP 443 by default.
  • Incorrect: 80. Port 80 is unencrypted HTTP.
  • Incorrect: 22. Port 22 is used by SSH.
  • Incorrect: 25. Port 25 is used by SMTP.

2. Match each port to its service.

Correct matches
  • 22: SSH
  • 53: DNS
  • 389: LDAP
  • 3389: RDP

These ports appear constantly in firewall rules, scan results and logs.

3. Put the TCP handshake in order.

Correct order
  1. SYN
  2. SYN-ACK
  3. ACK

The client asks to synchronize, the server agrees and asks in return, and the client confirms.

4. Which statement is true?

  • TCP retransmits lost data and UDP does not by itself
  • UDP uses a three-way handshake
  • TCP is connectionless
  • UDP guarantees delivery order
Answer and explanation
  • Correct: TCP retransmits lost data and UDP does not by itself. TCP includes reliability, while UDP leaves it to the application.
  • Incorrect: UDP uses a three-way handshake. The handshake belongs to TCP.
  • Incorrect: TCP is connectionless. TCP is connection-oriented.
  • Incorrect: UDP guarantees delivery order. UDP gives no ordering guarantee.

6. Review and references

Common mistakes

  • Assuming an open port means a vulnerability. It means a service is reachable, and that service is what needs assessing.
  • Assuming port numbers prove what is running. A service can be run on any port.

Summary

  • TCP is reliable and connection-based, while UDP is lightweight.
  • Ports identify services, and each open one needs justification.
  • Memorize the common ports; they recur throughout the exam.
