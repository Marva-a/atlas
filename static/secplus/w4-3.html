Hardening, endpoint protection and basic firewalls

Lesson 15 · Week 4 · Foundations · Foundation (not an exam objective) · Beginner · about 120 min

Open this lesson in Atlas →

Foundational technical knowledge

1. Learn the concept

By the end, you can

  • Explain system hardening and give concrete steps.
  • Describe what endpoint protection does.
  • Write basic host firewall rules.

Why it exists and what problem it solves

Most systems ship with more enabled than they need. Hardening removes what an attacker could otherwise use. Firewalls then limit who can reach what remains.

In plain language

Hardening a computer is like preparing a house before going on a long trip. Lock the doors you do not use, remove the spare key from under the mat and take valuables out of the window. A firewall is a guard at the door with a list of who may enter.

2. Technical deep dive

Hardening reduces attack surface. Typical steps are removing unused software and accounts, disabling unneeded services and ports, changing default passwords, applying updates, enabling logging, and requiring strong authentication. Published baselines such as the Center for Internet Security benchmarks list specific settings.

Endpoint protection covers software on devices. Antivirus looks for known malicious patterns and behaviour. Host-based firewalls control traffic on the device itself. A firewall evaluates rules in order, commonly by source, destination, port and protocol, and ends with an implicit deny that blocks anything not allowed.

A simple host firewall policy
OrderActionPortSourceReason
1AllowTCP 22Admin subnet onlyRemote management
2AllowTCP 443AnyThe public website
3DenyAnyAnyEverything else

Key terms

HardeningReducing a system's attack surface through secure configuration.
Attack surfaceAll the points where an attacker could try to get in.
BaselineAn approved, documented secure configuration.
AntivirusSoftware that detects and removes malicious code.
Host-based firewallA firewall running on the device it protects.
Implicit denyThe rule that anything not explicitly allowed is blocked.
Default credentialsUsernames and passwords set by a manufacturer.

Walkthrough: Harden a new Linux server

  1. Install updates.
  2. Create a named admin account and disable direct root login over SSH.
  3. Remove software and services the server does not need.
  4. Allow only the required ports in the firewall.
  5. Turn on logging and forward logs elsewhere.

Hands-on lab

Configure a host firewall in your VM

About 40 min. ufw in your Ubuntu lab VM

  1. Run sudo ufw status to see the current state.
  2. Run sudo ufw default deny incoming, then sudo ufw allow from 127.0.0.1 to any port 22 proto tcp.
  3. Run sudo ufw enable and then sudo ufw status numbered.
  4. Run sudo ss -tuln and compare what is listening with what the firewall allows.
  5. Restore your snapshot, or run sudo ufw disable, when finished.

Expected: The status shows default deny for incoming traffic and your single allow rule.

Default deny means that a service you forget about remains unreachable. Allow rules then state exactly what is intended.

Done when:

  • Your rule list shows default deny and the single allow rule.
  • You can explain implicit deny in a sentence.

3. See it in real products

Hardening and patching explain why products force updates and retire old browsers or app versions. The "please update" message is the visible end of a security decision.

In security operations

  • A new camera still has the manufacturer's default admin password. Attackers scan for exactly that.
  • A database server's firewall permits connections only from the application servers, so a compromised laptop cannot reach it directly.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A team installs a new web server with all default features and leaves FTP enabled, though nothing uses it. Which hardening step addresses this, and why?

Compare your reasoning

Disable or remove unneeded services. An unused FTP service adds attack surface and transmits credentials in clear text, while providing no benefit.

1. Which action is an example of hardening?

  • Disabling services that are not needed
  • Installing extra games
  • Keeping default passwords
  • Turning off logging
Answer and explanation
  • Correct: Disabling services that are not needed. Removing what is unneeded reduces attack surface.
  • Incorrect: Installing extra games. Additional software increases attack surface.
  • Incorrect: Keeping default passwords. Default credentials should always be changed.
  • Incorrect: Turning off logging. Logging is needed for detection.

2. A firewall has allow rules for ports 80 and 443 and no other rules. What happens to traffic on port 23, assuming implicit deny?

  • It is blocked
  • It is allowed
  • It is redirected to port 80
  • It is logged and then allowed
Answer and explanation
  • Correct: It is blocked. Traffic that matches no allow rule is denied.
  • Incorrect: It is allowed. Implicit deny blocks what is not allowed.
  • Incorrect: It is redirected to port 80. Firewalls do not redirect by default.
  • Incorrect: It is logged and then allowed. Implicit deny does not permit the traffic.

3. True or false: changing default passwords is part of hardening.

  • True
  • False
Answer and explanation
  • Correct: True. Default credentials are widely known and easily found.
  • Incorrect: False. Leaving them unchanged is a common and serious weakness.

4. Which actions reduce a server's attack surface? Choose two.

  • Closing unused ports
  • Removing unused software
  • Adding more administrator accounts
  • Exposing the management interface to the internet
Answer and explanation
  • Correct: Closing unused ports. Fewer open ports means fewer ways in.
  • Correct: Removing unused software. Less software means fewer possible vulnerabilities.
  • Incorrect: Adding more administrator accounts. More privileged accounts increase risk.
  • Incorrect: Exposing the management interface to the internet. This increases exposure.

6. Review and references

Common mistakes

  • Allowing all traffic so that troubleshooting is easier and forgetting to remove the rule.
  • Treating antivirus as sufficient on its own.

Summary

  • Hardening removes what is not needed.
  • Baselines define what good configuration looks like.
  • Firewalls apply rules in order and should deny by default.
