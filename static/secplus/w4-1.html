The command line, users, groups and file permissions

Lesson 13 · Week 4 · Foundations · Foundation (not an exam objective) · Beginner · about 120 min

Open this lesson in Atlas →

Professional relevance for cross-functional work

1. Learn the concept

By the end, you can

  • Move around and inspect files in Windows and Linux command lines.
  • Read Linux permission strings and describe Windows permissions at a basic level.
  • Explain why least access at the file level matters.

Why it exists and what problem it solves

Security tools, logs and incident response work often happen at a command line. A single wrong permission can expose a whole database, so you need to be able to read one quickly.

In plain language

A graphical desktop lets you point at things. A command line lets you ask for things in words, which is faster, repeatable and scriptable. Permissions are the locks on each file: they say who can open it, change it or run it.

2. Technical deep dive

On Linux, a shell such as bash reads commands. Useful commands include pwd (where am I), ls -l (list files), cd (change directory), cat (show a file), grep (search text), sudo (run as an administrator) and chmod (change permissions). On Windows, Command Prompt and PowerShell are the shells. PowerShell works with objects, using commands such as Get-Process and Get-Service.

Linux permissions appear as a string such as -rwxr-x---. After the first character, there are three groups of three, for the owner, the group and everyone else. Read is r, write is w and execute is x. In numeric form, r is 4, w is 2, x is 1, so 750 means rwxr-x---. Windows uses access control lists (ACLs) that grant permissions such as Read and Full Control to users and groups. The icacls command shows them.

Walkthrough: Read -rw-r----- for report.txt

  1. The first dash means it is a regular file. A d would mean a directory.
  2. The next three characters, rw-, mean the owner can read and write.
  3. The next three, r--, mean the group can only read.
  4. The last three, ---, mean everyone else has no access.
  5. In numbers, this is 640.

Hands-on lab

Practise commands in your VM

About 45 min. Your Ubuntu lab VM

  1. Open a terminal in your VM. Run pwd, then ls -l in your home directory.
  2. Create a file with echo hello > test.txt, then run ls -l test.txt and write down its permissions.
  3. Run chmod 600 test.txt and look at the permissions again.
  4. Run sudo adduser labuser to make a new account, switch using su - labuser, and try cat on your file using its full path. Type exit afterwards.
  5. Optional on Windows: run icacls on a file in your own Documents folder.

Expected: After chmod 600, the listing shows -rw------- and the other account gets Permission denied.

The kernel checks each access against the file's owner, group and mode. Your file stayed private even though the other user was logged in to the same machine.

Done when:

  • You changed a file's permissions and verified the result with ls -l.
  • You saw Permission denied from the second account.

3. See it in real products

File permissions are the ancestor of product sharing. Owner, group and others, along with read, write and execute, reappear as owner, team and anyone with the link. Knowing the original model helps you notice when a sharing interface is hiding an important combination.

In security operations

  • A configuration file with database passwords is set to 644, so every user on the server can read it. Setting it to 600 limits it to the owner.
  • Administrators use sudo so that each privileged command is logged against a named person.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A web application's folder has permissions 777. What does that allow, and what should an administrator consider instead?

Compare your reasoning

777 gives read, write and execute to the owner, the group and everyone else, so any account on the server, including a compromised service, can change or run those files. Give the minimum instead, for example restricting write access to the account that needs it.

1. What does the number 7 mean in a Linux permission?

  • Read, write and execute
  • Read only
  • Write only
  • No access
Answer and explanation
  • Correct: Read, write and execute. 4 plus 2 plus 1 equals 7.
  • Incorrect: Read only. Read only is 4.
  • Incorrect: Write only. Write only is 2.
  • Incorrect: No access. No access is 0.

2. What does chmod 640 give the group?

  • Read only
  • Read and write
  • Full control
  • No access
Answer and explanation
  • Correct: Read only. The middle digit is 4, which means read.
  • Incorrect: Read and write. That would be 6 in the middle digit.
  • Incorrect: Full control. That would be 7.
  • Incorrect: No access. That would be 0.

3. Match each command to its use.

Correct matches
  • pwd: Show the current directory
  • grep: Search text for a pattern
  • chmod: Change file permissions
  • sudo: Run a command with elevated rights

These commands are used constantly when investigating Linux systems.

4. True or false: Windows uses access control lists to grant permissions on files.

  • True
  • False
Answer and explanation
  • Correct: True. NTFS permissions are stored as access control lists.
  • Incorrect: False. ACLs are the standard Windows permission mechanism.

6. Review and references

Common mistakes

  • Fixing a problem with chmod 777. It may seem to work, because it removes the protection that caused the error.
  • Reading the three permission groups in the wrong order. It is always owner, group, others.

Summary

  • The command line makes work faster, repeatable and auditable.
  • Linux permissions apply to owner, group and others.
  • Grant only the access that is needed.
