Secure access, identity management and failure modes

Lesson 33 · Week 8 · Domain 3: Security Architecture · Objective 3.2 · Intermediate · about 120 min

Open this lesson in Atlas →

Direct product design relevance

1. Learn the concept

By the end, you can

  • Choose remote access and secure communication options.
  • Prevent privilege creep and use service accounts safely.
  • Decide whether a device should fail open or fail closed.

Why it exists and what problem it solves

Remote work made access paths a primary target. Accounts tend to accumulate access over time, and a device's behaviour during failure can quietly decide what happens when you need it most.

In plain language

A VPN is a private corridor. Out-of-band management is a separate service entrance used when the main entrance is blocked. Failure modes ask: when the electronic lock loses power, does the door stay locked or open?

2. Technical deep dive

Secure communication and access: a virtual private network (VPN) creates an encrypted path, and remote access lets users or admins reach systems from elsewhere. Tunneling encapsulates one protocol within another. User management controls accounts. User access should follow least privilege. End-to-end encrypted messaging means only the participants can decrypt content, not the service provider. Out-of-band management uses a separate path to manage devices, even if the main network is down. File transfer should use protected methods such as SFTP. Security Service Edge (SSE) delivers security functions from the cloud, including secure web gateway, cloud access security broker and Zero Trust network access.

Identity management: Group Managed Service Accounts (gMSAs) are a Windows feature that automatically manage long, rotating passwords for services. Least privilege access accounts have only the rights required, with separate admin accounts for admin work. Privilege creep is the build-up of permissions as people change roles without old access being removed.

Failure modes describe how a device behaves when it fails. Fail-closed blocks traffic, favouring security over availability. Fail-open allows traffic through, favouring availability. Inline security devices are chosen deliberately, based on what the organization values more. Note that life-safety systems, such as emergency exits, must allow people out.

Walkthrough: Choose a failure mode

  1. Identify what the device protects.
  2. Ask which is worse: downtime or unfiltered traffic?
  3. For a payment system firewall, fail-closed usually protects data.
  4. For a device whose failure would stop clinical care, fail-open may be chosen.
  5. Document the decision and make sure failure triggers an alert.

Hands-on lab

Review account access

About 30 min. Your lab VM

  1. Run getent passwd and identify human accounts, usually with IDs of 1000 or more.
  2. Run groups for each account you made, and check which accounts have sudo.
  3. Remove sudo from an account that does not need it using sudo deluser labuser sudo, if it is a member.
  4. Run sudo -l as that user to verify what it can do.

Expected: A list of accounts and privileges, and a confirmed reduction in access.

This is an access review in miniature. Regular reviews are what stop privilege creep.

Done when:

  • You listed each account's groups.
  • You verified that an unneeded privilege is gone.

3. See it in real products

Security controls fail, and when they do a product must either fail open and keep working unsafely, or fail closed and stop people working. That decision can appear as a login outage, a blocked payment or a safety-critical record that clinicians cannot open.

In security operations

  • An IT staff member moves through three departments and retains access to all three. An access review finds this privilege creep.
  • A hospital's inline device fails open, so clinical systems stay reachable, and the alert prompts urgent attention.

4. Apply it as a Product Designer

Design brief: Design what happens when the security system fails

About 45 min

Scenario: A hospital's scheduling and records application relies on a third-party identity and policy service. During a recent outage, nobody could sign in and staff could not view patient schedules.

Problem statement: The product has no designed behaviour for a failed identity or policy service, so it presents a generic error at the worst possible moment.

Your design task:

  • For each key function, decide whether it should fail open, fail closed or degrade, and explain why.
  • Design the degraded mode and how a user knows they are in it.
  • Design the break-glass route for emergency access, including after-the-fact review.

Technical security constraints:

  • Emergency access must be logged, time-limited and reviewed.
  • Unknown states must never appear as granted permissions.
  • Data entered in degraded mode must be reconciled once service returns.

User needs:

  • Clinicians need critical information during an outage.
  • Privacy officers need a record of any emergency access.
  • Administrators need to know what is happening and for how long.

Expected deliverable: A fail-open, fail-closed or degrade decision table, plus degraded mode and break-glass designs.

Evaluation criteria:

  • Break-glass access is limited in time, logged and reviewed.
  • The decisions consider safety and privacy consequences for each function.
  • Users can tell they are in a degraded state and what is limited.
  • The decision table identifies who must approve each fail-open choice.

Senior-level considerations:

  • Fail-open decisions involve safety and legal judgment, so they need owners beyond the design team.
  • Rehearsing outages reveals assumptions, so ask to join a recovery exercise.

A design review is not a security sign-off. Have security engineers confirm technical decisions.

Questions a Senior Product Designer should ask

Engineering:

  • What happens to signed-in sessions when the identity service is unavailable?
  • Can we tell the difference between a denial and a failed policy check?

Security:

  • Which functions should fail closed, and which may degrade?

Product:

  • What are our customers' obligations during an outage, such as patient care?

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: After a network outage, administrators cannot reach their switches to fix it, because management runs over the same failed network. What should have been in place?

Compare your reasoning

Out-of-band management, a separate path to device consoles such as a dedicated management network or cellular link.

1. A firewall that blocks all traffic when it fails is said to do what?

  • Fail closed
  • Fail open
  • Fail forward
  • Fail over
Answer and explanation
  • Correct: Fail closed. It prioritizes security over availability.
  • Incorrect: Fail open. That allows traffic through.
  • Incorrect: Fail forward. That is a change management term.
  • Incorrect: Fail over. This means switching to a standby.

2. An employee has retained access from three former roles. What is this?

  • Privilege creep
  • Key escrow
  • Evasion
  • Fail-open
Answer and explanation
  • Correct: Privilege creep. Permissions have built up over time.
  • Incorrect: Key escrow. That is storing keys for recovery.
  • Incorrect: Evasion. That is misleading an AI model.
  • Incorrect: Fail-open. That is a failure mode.

3. Which feature helps with long, automatically rotated passwords for Windows services?

  • gMSA
  • CRL
  • SNMP
  • RTO
Answer and explanation
  • Correct: gMSA. Group Managed Service Accounts automate password management.
  • Incorrect: CRL. That lists revoked certificates.
  • Incorrect: SNMP. That is a monitoring protocol.
  • Incorrect: RTO. That is a recovery metric.

4. Which best describes out-of-band management?

  • A separate path for administering devices
  • Sending management traffic over the normal user VLAN
  • Backing up data to tape
  • Encrypting a message end to end
Answer and explanation
  • Correct: A separate path for administering devices. It stays available when the production network is not.
  • Incorrect: Sending management traffic over the normal user VLAN. This is in-band.
  • Incorrect: Backing up data to tape. This is a data protection activity.
  • Incorrect: Encrypting a message end to end. This protects message content.

5. What does Security Service Edge primarily deliver?

  • Cloud-delivered security for access to web, cloud and private applications
  • Uninterruptible power for branch offices
  • A physical mantrap for a data centre
  • Certificate revocation lists
Answer and explanation
  • Correct: Cloud-delivered security for access to web, cloud and private applications. It includes functions such as ZTNA and secure web gateways.
  • Incorrect: Uninterruptible power for branch offices. This is a power function.
  • Incorrect: A physical mantrap for a data centre. This is physical security.
  • Incorrect: Certificate revocation lists. This belongs to PKI.

B. Product design assessment

Rate your work in the interactive app, where it counts toward design competency only.

1. A payment approval service is unreachable. Which behaviour is the best default for a large transfer?

  • Hold the transfer and tell the user what will happen
  • Approve it automatically and verify it later
  • Silently retry forever with no message to the user
  • Cancel it and delete all the details the user entered
Answer and explanation
  • Correct: Hold the transfer and tell the user what will happen. Failing closed protects integrity while keeping the person informed.
  • Incorrect: Approve it automatically and verify it later. Failing open on a high-value action invites irreversible loss.
  • Incorrect: Silently retry forever with no message to the user. The user is left guessing, and may submit the transfer twice.
  • Incorrect: Cancel it and delete all the details the user entered. This fails safely, but it needlessly destroys the user's work.

6. Review and references

Common mistakes

  • Assuming a VPN grants appropriate access. It should still be limited by least privilege.
  • Treating fail-open as always wrong. It is a tradeoff to be decided deliberately.

Summary

  • Protect remote paths with encryption and least privilege.
  • Review accounts to stop privilege creep.
  • Decide failure modes in advance.
