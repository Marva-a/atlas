Cryptography: encryption, hashing, salting and signatures

Lesson 20 · Week 5 · Domain 1: General Security Concepts · Objective 1.3 · Intermediate · about 120 min

Open this lesson in Atlas →

Professional relevance for cross-functional work

1. Learn the concept

By the end, you can

  • Compare symmetric and asymmetric encryption, and choose for a use case.
  • Distinguish encryption, hashing, salting and obfuscation.
  • Explain digital signatures and key exchange.

Why it exists and what problem it solves

Cryptography protects data on disks, on networks and in signatures. Most failures are not broken mathematics. They are poor choices of algorithm, weak key handling or using the wrong tool, such as encrypting passwords when they should be hashed.

In plain language

Encryption is a lockbox: with the key you can get the original back. Hashing is a blender: you can make a smoothie from fruit, but cannot turn it back. If two people blend the same fruit, they get the same smoothie, which is how you can check that something has not changed.

In symmetric encryption, both people share the same key, like a shared house key. In asymmetric encryption, there is a pair: a public key that anyone can use to lock a box, and a private key that only you can use to open it.

2. Technical deep dive

Symmetric algorithms use one shared key and are fast, so they are used for bulk data. The Advanced Encryption Standard (AES) is the main example, with key lengths of 128, 192 or 256 bits. Asymmetric algorithms use a public and private key pair, and are slower, so they are used for key exchange and signatures. RSA and elliptic curve cryptography (ECC) are examples. ECC gets comparable strength from much shorter keys. For the same algorithm, a longer key length generally makes brute force harder.

Key exchange solves the problem of agreeing on a shared key over an open network. Diffie-Hellman, including its elliptic curve form, lets two parties derive a shared secret without ever sending it. TLS uses asymmetric methods to agree on a key, and symmetric encryption for the session. That is the transport/communication use of encryption. Forward secrecy uses temporary keys, so stealing a long-term key later cannot unlock past sessions.

A hashing algorithm produces a fixed-length digest from any input. It is one-way, and any small change in the input yields a very different digest. SHA-256 is a current choice, whereas MD5 and SHA-1 are considered broken for collision resistance. A salt is a random value added to each password before hashing, so identical passwords produce different hashes and pre-computed rainbow tables are defeated. Passwords should be stored with slow, purpose-built functions such as bcrypt, scrypt or Argon2.

A digital signature is made by hashing a message and signing that hash with the sender's private key. Anyone can verify it with the sender's public key, which gives integrity, authentication of origin and non-repudiation. Obfuscation makes something hard to understand without protecting it mathematically. Steganography, hiding data within other data, and code minification are examples. Obfuscation is not encryption.

Encryption can be applied at different levels: full disk (the entire drive), partition, volume (a logical storage unit), file, database, or an individual record. The narrower the level, the more precisely you can control access, and the more there is to manage. Protocols such as TLS, IPsec and SSH apply encryption in transit.

Cryptographic tools include the Trusted Platform Module (TPM), a chip in a computer that stores keys and supports full disk encryption; the hardware security module (HSM), a dedicated device that protects keys at scale; key management systems, which handle generating, storing and rotating keys; and the secure enclave, an isolated processor area that protects sensitive operations.

Symmetric uses one shared key. Asymmetric uses a matched pair.

A salt is a random value stored beside each password's hash. It is not secret; it only has to be different for every account.

Signing uses the private key; checking uses the public key. A match gives integrity, proof of origin and non-repudiation.

Diffie-Hellman in paint: two people agree on a shared secret over an open channel without ever sending the secret itself.

Walkthrough: Choose the right tool

  1. Need to keep a large file secret and get it back? Use symmetric encryption, such as AES.
  2. Need to share a key with someone you have never met? Use asymmetric key exchange.
  3. Need to store passwords? Use a salted, slow hash such as Argon2, not encryption.
  4. Need to detect whether a download changed? Compare a SHA-256 hash.
  5. Need to prove who approved something? Use a digital signature.

Hands-on lab

Hash, salt and encrypt

About 40 min. OpenSSL and sha256sum in your lab VM

  1. Run echo -n hello | sha256sum, then echo -n Hello | sha256sum, and compare the results.
  2. Run openssl passwd -6 -salt abc mysecret and again with -salt xyz, and compare the two results.
  3. Create a file and run openssl enc -aes-256-cbc -pbkdf2 -in file.txt -out file.enc, then decrypt it using -d.
  4. Run openssl genrsa -out priv.pem 2048 and openssl rsa -in priv.pem -pubout -out pub.pem. Sign a file with openssl dgst -sha256 -sign priv.pem -out sig file.txt and verify it using -verify pub.pem -signature sig.
  5. Change the file and verify again.

Expected: A one-letter change alters the whole hash. Different salts give different results. Decryption returns the original. Verification succeeds until the file changes.

You have just seen one-way hashing, the salt's effect, reversible encryption and a signature that detects tampering. Only use practice keys here.

Done when:

  • You observed different hashes from a single changed letter.
  • Verification failed after you changed the signed file.

3. See it in real products

Cryptography sets what a product can promise. If passwords are hashed, nobody can show a user their old password, so reset is the only path. If content is end-to-end encrypted, losing the key can mean losing the data, and the recovery experience has to be honest about that.

In security operations

  • BitLocker can use a laptop's TPM, so the drive decrypts only on the original hardware in its expected state.
  • When a password database leaks, salted bcrypt hashes make cracking far slower than unsalted MD5.

5. Test your understanding

A. Security+ technical assessment

Exam-style scenario: A developer proposes encrypting user passwords with AES and storing the key on the same server, so that passwords can be recovered for users. What should be recommended?

Compare your reasoning

Do not store passwords in a reversible form. Use a salted, slow password hashing function such as Argon2 or bcrypt, and provide password reset instead of recovery. If an attacker obtains the server, the key would decrypt every password.

1. Which statement is true about symmetric encryption?

  • The same key encrypts and decrypts
  • It uses a public and private key pair
  • It cannot be used for large files
  • It is one-way and cannot be reversed
Answer and explanation
  • Correct: The same key encrypts and decrypts. That is the defining feature.
  • Incorrect: It uses a public and private key pair. That describes asymmetric encryption.
  • Incorrect: It cannot be used for large files. Symmetric encryption is well suited to bulk data.
  • Incorrect: It is one-way and cannot be reversed. That describes hashing.

2. An organization needs to verify that a downloaded file has not changed. What should it use?

  • A SHA-256 hash comparison
  • AES encryption
  • Obfuscation
  • A longer password
Answer and explanation
  • Correct: A SHA-256 hash comparison. A matching digest shows the file is unchanged.
  • Incorrect: AES encryption. Encryption provides confidentiality, not a simple integrity check.
  • Incorrect: Obfuscation. Obfuscation does not verify anything.
  • Incorrect: A longer password. A password has no bearing on file integrity.

3. What is the main benefit of salting password hashes?

  • Identical passwords produce different hashes
  • Hashes can be reversed more easily
  • Passwords no longer need to be long
  • The salt must be kept as secret as a private key
Answer and explanation
  • Correct: Identical passwords produce different hashes. Unique salts defeat pre-computed tables.
  • Incorrect: Hashes can be reversed more easily. Salting does not make hashes reversible.
  • Incorrect: Passwords no longer need to be long. Weak passwords remain weak.
  • Incorrect: The salt must be kept as secret as a private key. Salts are normally stored with the hash and need not be secret.

4. Which key does a sender use to create a digital signature?

  • The sender's private key
  • The sender's public key
  • The recipient's public key
  • A shared symmetric key
Answer and explanation
  • Correct: The sender's private key. Only the signer holds it, so the signature proves origin.
  • Incorrect: The sender's public key. Public keys verify signatures.
  • Incorrect: The recipient's public key. This would be used to encrypt data for the recipient.
  • Incorrect: A shared symmetric key. A shared key cannot prove which party acted.

5. Match each need to the most suitable level of encryption.

Correct matches
  • A stolen laptop must be unreadable: Full disk
  • One sensitive document must be protected: File
  • A credit card column in a table must be protected: Record
  • Web traffic must be protected: Transport/communication

Match the scope of the threat to the scope of the protection.

6. Which device is designed to protect and manage cryptographic keys for many servers?

  • HSM
  • TPM
  • NIC
  • SIEM
Answer and explanation
  • Correct: HSM. A hardware security module is dedicated to protecting keys at scale.
  • Incorrect: TPM. A TPM is a chip that serves one device.
  • Incorrect: NIC. A NIC connects a device to a network.
  • Incorrect: SIEM. A SIEM collects and analyzes events.

6. Review and references

Common mistakes

  • Saying passwords should be encrypted. They should be salted and hashed with a slow function.
  • Treating obfuscation as if it were encryption.
  • Thinking the public key encrypts a digital signature. The private key signs, and the public key verifies.

Summary

  • Symmetric is fast and uses one key, and asymmetric uses a key pair.
  • Hashing is one-way, and salting makes password hashes unique.
  • Signatures give integrity, proof of origin and non-repudiation.
